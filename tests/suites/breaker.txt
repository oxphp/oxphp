# And the same client hanging up, reached the other way. ignore_user_abort()
# makes the interrupt handler record the disconnect and return instead of
# unwinding, and in worker mode the write that follows declines too, so these
# requests reach the end of their own handlers with nobody reading what they
# write. It is the same event as the abort above and has to read the same way:
# three of them must leave the worker serving.
#
# The timing is what keeps all three running. Each handler sleeps two seconds
# before its first write, and each client gives up after one and a half: it is
# gone at least half a second before that write, and the next line, queued
# behind the request before it, is reached by the worker at least half a second
# before its own client goes. A client that leaves while its request is still
# queued has that request dropped without being run — the last block of this
# suite — so a shorter wait here would leave these blocks counting two requests,
# not three.

# Requests whose clients leave while they are still waiting in the queue. Nobody
# is left to read what they would produce, so the worker that reaches them
# answers each as closed and takes the next one: it neither runs them nor counts
# them as served. Each of the two ways a worker takes a request from the queue
# has a test here. The first stages three such requests and returns, leaving the
# worker to reach them on its blocking branch; the probe after it reads what the
# worker did with them. The second stages three more and parks, so the event
# loop's tick reaches them while it sleeps. The staging confirms from /metrics
# that all three were queued and that the server saw all three clients leave
# before any worker took them.
