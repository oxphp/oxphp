# Runs deep into the suite on purpose: by now every worker has served a request,
# so this one probably lands on a RECYCLED request fiber. Kept ahead of the tests
# that retire a worker (scheduleExit) so it cannot be handed a freshly spawned
# one. Under the default multi-worker pool none of that is a guarantee, which is
# why strict=1 is NOT passed here — drawing a fresh fiber reports "no reuse
# coverage" in the response instead of failing the run. The hooks profile lists
# this test too, with strict=1, and there PHP_WORKERS=1 makes reuse certain.
worker/test_request_state_after_reuse >> ?probe=42

# Two requests, different probe: $_REQUEST must follow the request being served,
# not the one that first loaded the script on that worker. The check is live only
# on the second sighting by the same worker — the first compiles the file, and
# compiling materialises the lazy auto-global correctly on any build — so under
# this profile's multi-worker pool the pair is a likelihood rather than a
# guarantee, and each response names the worker that answered. The hooks profile
# lists the same pair with PHP_WORKERS=1, where it is certain.
worker/test_request_autoglobal_refresh >> ?probe=alpha
worker/test_request_autoglobal_refresh >> ?probe=beta

# Explicit http_response_code() is honored on the worker send path: the status a
# script sets via http_response_code() lives only in SG(sapi_headers) and must be
# collected into the response. (The uncaught-throw variant — where the status must
# also survive the fatal fallback — is asserted in the default/traditional profile
# via headers/test_status_explicit_then_throw, free of the worker async
# output-buffer interaction that makes a throwing worker request flaky here.)
