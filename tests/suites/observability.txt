# profile: default
# description: Per-worker observability — supervisor heartbeats, age gauge

# The age gauge is populated by the supervisor (1 s period). The test
# script sleeps 2 s and then scrapes /metrics from inside the same
# request — its own slot's request_start_us is still non-zero, so the
# supervisor wrote a non-zero age into oxphp_worker_request_age_seconds.
observability/test_request_age_metric

# The queue gauges are read off the live admission gate by a probe the
# executor installs. Unit tests install their own probe, so only a real
# scrape proves the wiring exists; the test also pins the healthy
# reading — a serving pool has admission slots free.
observability/test_queue_gauges

# Cancellation counters are wired through the abort guard the dispatch
# side puts around every request (see `Metrics::observe_cancelled`), which
# reads the reason out of the per-request cancellation state.
# An end-to-end test would assert
# `oxphp_request_cancelled_total{reason="timeout"}` increments after a
# `set_time_limit(1) + sleep(3)` request. That assertion is intentionally
# omitted here: in ZTS PHP the SIGPROF/SIGALRM-driven timeout path skips
# `zend_interrupt_function` and goes straight to `zend_timeout()`'s
# default error, so the unified bailout never observes the reason. When
# that path lands the counter wiring will start incrementing without
# code changes.

# The negative half of the runtime-hooks reporting: this profile sets no
# RUNTIME_HOOKS, which is also what a misspelled variable name leaves behind.
# An absent key would read identically on a server with the hooks on, so the
# key has to be there and empty. hooks/test_runtime_hooks_published is the
# other half.
observability/test_runtime_hooks_empty
