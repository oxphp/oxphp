# A request ended inside an internal function leaves what that function held
# behind, and nothing frees it. The worker is retired for it when the heap grew
# by more than a threshold between two moments with no request in flight, and not
# otherwise: a worker that kept a lot on purpose in plain code is left alone, and
# so is one that then has a few hundred rows left behind by a sort — the growth
# that came before it is not counted against it, which is why the pairs are in
# this order. The time limit ends them, which no failure counter sees.

# A stream's flush waiting for room in its queue: the stream reaches a client
# on the same worker thread whole, another request is served while it waits, the
# wait ends at its client leaving and at its time limit, and what is left of a
# stream ended that way neither waits nor is lost. What a stream flushes once its
# client has gone is dropped, and a stream that runs out of memory_limit ends at
# that error instead of waiting to flush it. What an output handler throws in a
# flush that finds the queue full reaches the script's catch. A flush that waits
# by holding the thread wedges this profile's only worker, which fails every test
