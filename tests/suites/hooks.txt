# profile: hooks
# description: Runtime hooks in worker mode — request/task fiber multiplexing of native sleep

# These two lines belong together and must stay at the top of this profile, in
# this order. PHP_WORKERS=1 here, so every request lands on the same worker:
# the first one gives its request fiber a completed request WITHOUT suspending,
# and the second then runs on that recycled fiber with a never-written state
# snapshot — the case where all of the second test's checks are live. Any
# suspending request first (every hooks/* test awaits or sleeps) leaves a
# half-benign snapshot behind instead: its header list and status come back
# valid, and only the $_REQUEST check would still fail on a broken build.
# A replacement opener must therefore never suspend. strict=1 turns "served on a
# fresh fiber" into a failure, which here is a real invariant, not a coin flip.
worker/test_worker_class_get_id
worker/test_request_state_after_reuse >> ?probe=42&strict=1

# Same invariant on the other dispatch site: this one suspends and has its inner
# self-requests served from the event-loop tick.
hooks/test_tick_path_fiber_reuse

# Two requests, different probe, one worker (PHP_WORKERS=1): $_REQUEST must
# follow the request being served. The first request compiles the file and so
# materialises the lazy auto-global correctly whatever the build; the second gets
# it from OPcache with no compile, which is where a worker that does not rebuild
# $_REQUEST per request hands out the first one's parameters. Both lines are
# needed — the second alone proves nothing without the first to leave a different
# value behind.
worker/test_request_autoglobal_refresh >> ?probe=alpha
worker/test_request_autoglobal_refresh >> ?probe=beta

# The other half of the same decision: $_ENV must NOT be rebuilt per request,
# because its callback repopulates from the process environment and would erase
# what a .env loader wrote straight into the array at worker boot. Seed a key,
# then compile a mention of $_ENV — the trigger that fires the callback, since
# every reset re-arms the lazy auto-globals — then require the key to still be
# there. All three must stay adjacent and in this order. Listed here only: they
# need one worker, which PHP_WORKERS=1 guarantees and a pool does not.
worker/test_env_superglobal_persists >> ?mode=seed
worker/test_env_superglobal_persists >> ?mode=touch
worker/test_env_superglobal_persists >> ?mode=expect

# What ext/filter reads for INPUT_ENV is not $_ENV but the engine's own slot, and
# with the callback disarmed above nothing rebuilds that slot — so it has to
# survive the request boundary by itself. Read it on a later request, then prove a
# suspended request does not take it away: the third line's inner self-request
# reads the slot inside the parked window and the outer reads it again after
# resuming. Adjacent, in this order, and here only — one worker, which
# PHP_WORKERS=1 guarantees and a pool does not.
#
# The first line makes the block stand on its own. Until $_ENV exists the callback
# is still armed and rebuilds the slot on demand, which would make the second line
# pass on any build — as this profile runs today the seed above has materialised it
# long since, so the line's eval() fires nothing and what it is really carrying is
# the check that $_ENV holds the process environment (against a key the
# environment has, since the seed above already makes the array non-empty
# whatever variables_order says) plus the $_ENV write the two reading lines assert
# is NOT visible through INPUT_ENV.
hooks/test_env_filter_input >> ?mode=warm
hooks/test_env_filter_input >> ?mode=expect
hooks/test_env_filter_input >> ?mode=suspend

# The other three INPUT_* constants, whose storage is not a slot of the engine's
# but three arrays inside ext/filter — one set per worker thread, filled from
# every request and given back by a function the engine calls where worker mode
# no longer goes. The first line sends a query value, a cookie and a body and
# demands they are readable; the second sends none of the three and demands the
# first line's are not. Both are needed and in this order: the second alone
# passes on any build that reads no input at all, and one worker is what makes
# the pair mean anything, which PHP_WORKERS=1 guarantees and a pool does not.
#
# The third line is the same claim across a suspension, in both directions — a
# request that parks must not come back reading what ran in its window, and the
# request served in that window must not read the parked one's input — plus the
# half that has nothing to do with leaking: a suspension nobody else ran in must
# leave a request its own input. It carries its own query and cookie, so it does
# not depend on the two lines above; it does read the seed's body key, which the
# second line has already required gone.
hooks/test_filter_input_not_shared >> ?mode=seed&oxfilter_token=seed-query-value | POST | -H "Cookie: oxfilter_sid=seed-session-id" -H "Content-Type: application/x-www-form-urlencoded" --data "oxfilter_pw=seed-body-secret&oxfilter_user=alice" | |
hooks/test_filter_input_not_shared >> ?mode=expect
hooks/test_filter_input_not_shared >> ?mode=suspend&oxfilter_token=suspend-query-value | GET | -H "Cookie: oxfilter_sid=suspend-session-id" | |

# And the case where giving the storage back would pull it out from under a call
# that is still reading it: filter_input_array() with a definition array re-reads
# the storage for every key, and a FILTER_CALLBACK between two of them runs
# userland that can park. This line parks there on purpose, with an inner
# self-request waiting to be served in exactly that window, and demands both keys
# come back as this request's own. Stands on its own — its own query, its own
# inner request — so it needs no neighbour and no fixed position in the block.
hooks/test_filter_input_not_shared >> ?mode=callback&oxfilter_token=callback-query-value&oxfilter_second=callback-second-value

# The same split for ini directives: what a request changes must end with that

# What a fatal costs the worker it happened on. A pair, in order: the first line

# Last in this profile, and it has to stay last. The first of the two lines
# turns OPcache off, and a worker cannot turn it back on — only OPcache's own
# per-request startup does that, and a worker runs it once. So from here on this
# worker compiles every file from source, and anything appended below that
# depends on OPcache being live (worker/test_request_autoglobal_refresh above is
# one) would silently stop testing what it was written for. PHP_WORKERS=1 makes
# both lines land on the worker the first one changed, which is also what makes
# the second line's reading meaningful.
worker/test_opcache_enable_stays_off >> ?phase=off
worker/test_opcache_enable_stays_off >> ?phase=check
