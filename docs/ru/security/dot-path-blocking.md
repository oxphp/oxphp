# Блокировка dot-путей

OxPHP блокирует доступ к любому URL-пути, содержащему сегмент, начинающийся с `.` — возвращая 404 Not Found. Это предотвращает утечку чувствительных файлов, таких как `.env`, `.git/`, `.htaccess`, `.svn/` и `.DS_Store`, которые часто становятся целью автоматических сканеров.

Эта защита всегда включена и не может быть отключена. Она действует во всех режимах маршрутизации (традиционный, фреймворк, SPA и воркеры).

## Что блокируется

Любой запрос, в котором сегмент пути начинается с `.`, возвращает 404:

| Запрос | Результат |
|--------|-----------|
| `/.env` | 404 |
| `/.git/config` | 404 |
| `/.htaccess` | 404 |
| `/.DS_Store` | 404 |
| `/.docker/config.json` | 404 |
| `/path/.hidden/file.txt` | 404 |
| `/path/to/.env` | 404 |

Одноуровневые попытки обхода через процентное кодирование перехватываются — `/%2egit/HEAD` декодируется один раз в `/.git/HEAD` и отклоняется. Двойное кодирование (`/%252egit/HEAD`) декодируется только один раз и остаётся `/%2egit/HEAD`, что этот слой не распознаёт как сегмент-точку. Стандартные HTTP-клиенты и браузеры не делают двойного кодирования, так что на практике это редко имеет значение; если ваш вышестоящий прокси нормализует URI перед пересылкой, одного прохода декодирования достаточно.

## Исключение: `.well-known`

[RFC 8615](https://www.rfc-editor.org/rfc/rfc8615) определяет `/.well-known/` как стандартное расположение для метаданных сайта. OxPHP разрешает доступ к подпутям внутри `.well-known` с ограничениями:

| Запрос | Результат |
|--------|-----------|
| `/.well-known/security.txt` | Отдаётся как статический файл |
| `/.well-known/acme-challenge/token` | Отдаётся как статический файл (Let's Encrypt) |
| `/.well-known/openid-configuration` | Отдаётся если файл существует, иначе ENTRY_FILE или 404 |
| `/.well-known` | 404 (голый путь) |
| `/.well-known/` | 404 (листинг директории) |
| `/.well-known/test.php` | 404 (выполнение PHP заблокировано) |

PHP-файлы внутри `.well-known` никогда не выполняются — они всегда возвращают 404. Эта директория обслуживает только статический контент.

MIME-типы определяются по расширению файла. Файлы без расширения (например, `openid-configuration`) отдаются как `application/octet-stream`.
