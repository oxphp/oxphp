# Разрешённые цели симлинков

По умолчанию OxPHP отвергает любой запрос, который при разрешении пути уходит за пределы канонического `DOCUMENT_ROOT`. Симлинк внутри `DOCUMENT_ROOT`, указывающий на внешнюю директорию, возвращает 404, а в логе появляется `Blocked request: resolved path escapes document root`.

Это разумное умолчание — оно блокирует directory traversal, symlink-swap TOCTOU-атаки и случайные утечки конфигов / секретов, лежащих уровнем выше. Но оно же ломает легитимные паттерны, которые фреймворки используют годами: Laravel `php artisan storage:link`, Symfony asset bundles, общие upload-тома, смонтированные в несколько контейнеров.

`SYMLINK_ALLOW_PATHS` — явный opt-in: вы перечисляете пути файловой системы, на которые симлинки внутри `DOCUMENT_ROOT` могут указывать. Всё, что не в списке, по-прежнему получает строгий 404.

## Настройка

```bash
# Абсолютные пути через запятую
SYMLINK_ALLOW_PATHS=/var/www/storage,/opt/shared/assets

# Относительные пути резолвятся от DOCUMENT_ROOT
SYMLINK_ALLOW_PATHS=../storage,../shared/uploads

# Смесь допустима
SYMLINK_ALLOW_PATHS=/opt/shared/cdn,../storage/app/public
```

Если переменная не задана (умолчание), ни один симлинк не может выйти за пределы `DOCUMENT_ROOT`.

## Пример Laravel

```bash
DOCUMENT_ROOT=/app/public
SYMLINK_ALLOW_PATHS=../storage/app/public
```

Команда `php artisan storage:link` создаёт `public/storage -> ../storage/app/public` внутри проекта. URL вида `/storage/<file>` через симлинк резолвится в `/app/storage/app/public/<file>` — путь, авторизованный allow-list'ом. Изменений в коде приложения не требуется.

## Как это работает

На старте каждая запись разрешается:

- **Абсолютные записи** — сначала проверяются против blacklist (см. ниже), затем пропускаются через `realpath(3)` (`std::fs::canonicalize`). Если `realpath` падает (цель не существует), сервер не стартует.
- **Относительные записи** — джойнятся с каноническим `DOCUMENT_ROOT`, затем `realpath`'ятся.

Полученные канонические пути сохраняются как allow-list. Дубликаты молча отсекаются.

В рантайме на каждом запросе слой роутинга канонизирует разрешённый путь файла и проверяет, что он удовлетворяет одному из условий:

1. лежит внутри `DOCUMENT_ROOT`, либо
2. ровно совпадает с одной из записей allow-list'а (цели-файлы), либо
3. начинается с одной из записей, за которой следует `/` (цели-директории).

Та же проверка выполняется повторно как TOCTOU-защита внутри пути отдачи статики — после route-кэша, до любого read-syscall.

## Blacklist

Небольшой набор путей никогда не может появиться в `SYMLINK_ALLOW_PATHS` — опечатки и недоразумения иначе слишком сильно расширили бы attack surface. Сервер не стартует, если хоть одна запись резолвится в blacklist.

**Запрещены как полное совпадение:**

```
/   /etc   /proc   /sys   /dev   /var   /home   /tmp   /root   /usr   /srv
```

**Запрещены как префикс** (запись лежит под одной из этих директорий):

```
/etc   /proc   /sys   /dev   /tmp   /root   /usr
```

Обратите внимание: `/var`, `/home` и `/srv` блокируются только как точное совпадение — голый `/srv` отвергается, но `/srv/myapp/storage` разрешён, как и `/var/www/storage` или `/home/<любой>/...`. Записи проверяются дважды: один раз против сырого пути, который указал админ (чтобы macOS-style `/etc -> /private/etc` не пропустил blacklisted-путь через `realpath`), один раз против канонической формы (defense-in-depth от symlink-target escape).

Сам blacklist захардкожен — env-vars для расширения нет. Дефолт это консервативный минимум, отсекающий очевидные ошибки уровня "опечатался". Админам, которым нужны более строгие политики, стоит навешивать их слоями снаружи (права на файловой системе, ограничения mount'ов в контейнере, AppArmor/SELinux профили).

## Сценарии падения старта

| Ошибка конфигурации | Результат |
|---|---|
| Цель записи не существует на диске | Сервер не стартует, ошибка называет запись и `canonicalize` |
| Запись попадает в blacklist (сырой или канонический путь) | Сервер не стартует, ошибка называет запись и правило blacklist |
| Пустая / whitespace-only переменная | Трактуется как unset — строгое умолчание |
| Дублирующиеся записи | Молча отсекаются после канонизации |
| Симлинка ещё нет на момент старта | Allow-list зарегистрирован, но бездействует, пока симлинк не появится; на старте наличие симлинка не проверяется |

## Замечания о безопасности

- Allow-list — opt-in: безопасное умолчание "никаких побегов" сохраняется, пока переменная не задана
- Записи канонизируются на старте, так что `..` и промежуточные симлинки в пути записи коллапсируют до сохранения
- Канонизация в рантайме закрывает symlink-swap TOCTOU-окно — проверенный путь и есть тот, который читается с диска
- Цели-файлы матчатся точно; цели-директории матчатся по префиксу. Указание файла `/etc/passwd` всё равно отрежет blacklist; но в общем случае: запись на единственный файл `/opt/shared/license.key` не открывает доступ к соседним файлам
- Результаты валидации пути кэшируются per-URL (один `realpath` на уникальный URL до eviction'а), так что рантайм-оверхед амортизируется
