OxPHP -- это асинхронный сервер PHP-приложений, написанный на Rust. Он заменяет связку nginx + PHP-FPM единым бинарным файлом, который обеспечивает обработку HTTP-запросов, выполнение PHP и встроенную наблюдаемость в одном процессе.

## Зачем OxPHP

Традиционное развёртывание PHP требует веб-сервера (nginx или Apache), менеджера процессов (PHP-FPM) и отдельных инструментов для метрик, ограничения частоты запросов и терминации TLS. OxPHP объединяет весь этот стек в единый бинарный файл без внешних зависимостей во время выполнения, кроме библиотеки PHP.

Сервер использует настраиваемую асинхронную среду выполнения Tokio (по умолчанию CPU / 2 потоков, мин. 1; явно задаётся через `TOKIO_WORKERS`) для всех операций ввода-вывода и пул выделенных потоков ОС для выполнения PHP через Zend Thread Safety (ZTS). Такая архитектура освобождает асинхронный цикл событий от блокирующих вызовов PHP, при этом масштабируя выполнение PHP на все доступные ядра. Аллокатор mimalloc обеспечивает низкую задержку аллокаций при конкурентном доступе.

## Возможности

- **Раздача статических файлов** с кешированием в памяти и автоматическим определением MIME-типов
- **Три режима маршрутизации**: Traditional (прямое сопоставление файлов), Framework (фронт-контроллер) и SPA (перенаправление для одностраничных приложений)
- **Выполнение PHP** через собственный SAPI (`oxphp`) с полной поддержкой суперглобальных переменных (`$_GET`, `$_POST`, `$_SERVER`, `$_COOKIE`, `$_FILES`)
- **Динамическое масштабирование воркеров** -- автоматическое масштабирование потоков PHP-воркеров между настраиваемыми минимальным и максимальным значениями в зависимости от нагрузки
- **Ограниченная очередь запросов** с обратным давлением -- возвращает 503 при переполнении очереди вместо принятия неограниченного объёма работы
- **Система плагинов** с хуками жизненного цикла, регистрацией PHP-функций и топологической сортировкой зависимостей
- **Система событий** с типизированными событиями и обработчиками с приоритетным порядком на каждом этапе жизненного цикла запроса
- **Сжатие Brotli** для сжимаемых типов ответов
- **TLS** через rustls (без зависимости от OpenSSL на границе)
- **Ограничение частоты запросов по IP** с настраиваемыми лимитами и временными окнами
- **Метрики, совместимые с Prometheus**, доступные на выделенном внутреннем порту
- **Проверка состояния** по адресу `/health` на внутреннем сервере
- **Идентификаторы запросов**, генерируемые для каждого запроса и доступные в PHP через `oxphp_request_id()`
- **Структурированное JSON-логирование** доступа через фреймворк tracing
- **Пользовательские страницы ошибок**, загружаемые из каталога на диске
- **Плавная остановка** с настраиваемым тайм-аутом завершения
- **OPcache + JIT** -- поддержка из коробки
- **Мониторинг здоровья воркеров** с автоматическим пересозданием упавших воркеров
- **Потоковая передача SSE** -- Server-Sent Events в реальном времени через автоопределение `Content-Type: text/event-stream` или `oxphp_stream_flush()`
- **Ранний ответ** через `oxphp_finish_request()` -- немедленная отправка HTTP-ответа с продолжением фоновой обработки
- **Режим воркера** -- персистентные PHP-процессы с мягким сбросом между запросами, автоматическим рециклированием и метриками отдельных воркеров
- **Изоляция паник** через `catch_unwind` -- аварийный сбой PHP не роняет весь сервер
