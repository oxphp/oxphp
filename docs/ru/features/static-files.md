OxPHP обслуживает статические файлы напрямую из корня документов с автоматическим определением MIME-типов, трёхуровневым LRU-кешем и потоковой отдачей больших файлов.

## Определение MIME-типов

MIME-типы определяются по расширению файла с помощью крейта `mime_guess`. Если тип не удаётся определить, сервер использует `application/octet-stream` в качестве резервного значения. Основные соответствия:

| Расширение | Content-Type |
|-----------|-------------|
| `.html` | `text/html` |
| `.css` | `text/css` |
| `.js` | `application/javascript` |
| `.json` | `application/json` |
| `.png` | `image/png` |
| `.svg` | `image/svg+xml` |
| `.woff2` | `font/woff2` |

## Файловый кеш

Файловый кеш снижает количество системных вызовов к файловой системе при маршрутизации и отдаче файлов. Он использует `Mutex<HashMap>` с LRU-вытеснением на основе счётчика и работает на трёх уровнях:

### Кеш метаданных

Хранит информацию о том, является ли путь файлом, директорией или не существует. Маршрутизатор проверяет этот кеш при каждом запросе, чтобы решить — отдать файл, выполнить скрипт или вернуть 404 — без обращения к файловой системе.

- Ёмкость: 200 записей (настраивается на этапе компиляции)
- Вытеснение: LRU по счётчику обращений
- При промахе кеша выполняется асинхронный вызов `tokio::fs::metadata()`

### Кеш содержимого

Хранит полное содержимое небольших файлов, чтобы повторные запросы обслуживались из памяти без дискового ввода-вывода.

- Максимум на файл: 1 МБ
- Общий бюджет кеша: 64 МБ
- Вытеснение: LRU при превышении общего объёма
- Данные хранятся как `Bytes` (с подсчётом ссылок, клонирование без копирования)
- MIME-тип хранится рядом с содержимым как `Arc<str>`

Файлы размером более 1 МБ никогда не кешируются и всегда отдаются потоково с диска.

### Кеш канонических путей

Хранит результаты вызовов `canonicalize()`, используемых для защиты от выхода через символические ссылки. Это позволяет избежать повторных системных вызовов `realpath(3)` для одних и тех же путей.

- Разделяет ту же ёмкость в 200 записей с кешем метаданных
- Хранит `Option<PathBuf>` -- `None` означает, что файл не существовал на момент кеширования
- Вытеснение: LRU по счётчику обращений

## Поведение при отдаче файлов

При поступлении запроса на статический файл:

1. **Проверка кеша содержимого** -- если файл закеширован, он возвращается немедленно с сохранённым MIME-типом
2. **Определение MIME-типа** -- вычисление типа содержимого по расширению файла
3. **Повторная проверка TOCTOU** -- если защита через символические ссылки включена, путь канонизируется повторно перед чтением
4. **Проверка размера** -- чтение метаданных файла для определения стратегии отдачи

### Малые файлы (до 1 МБ)

Весь файл считывается в память с помощью `tokio::fs::read()`, помещается в кеш содержимого и возвращается как буферизованное тело ответа. Заголовок `Content-Length` устанавливается равным точному количеству байт.

### Большие файлы (более 1 МБ)

Файл открывается с помощью `tokio::fs::File::open()` и отдаётся клиенту потоково через `ReaderStream`. Заголовок `Content-Length` устанавливается из метаданных файла, чтобы клиент знал общий размер.

## Заголовки ответа

Каждый ответ со статическим файлом включает:

| Заголовок | Значение |
|-----------|----------|
| `Content-Type` | Определённый MIME-тип |
| `Content-Length` | Размер файла в байтах |

## Обработка ошибок

- **Файл не найден**: возвращается 404 с текстовым телом ответа
- **Ошибки доступа**: передаются как ошибка 500
- **Сбой чтения после проверки метаданных**: возвращается 404 (файл мог быть удалён между проверкой и чтением)
