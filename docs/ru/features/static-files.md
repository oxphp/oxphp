OxPHP обслуживает статические файлы напрямую из корня документов с автоматическим определением MIME-типов, трёхуровневым LRU-кешем, HTTP-кешированием (ETag / Last-Modified / 304) и потоковой отдачей больших файлов.

## Определение MIME-типов

MIME-типы определяются по расширению файла с помощью крейта `mime_guess`. Если тип не удаётся определить, сервер использует `application/octet-stream` в качестве резервного значения. Основные соответствия:

| Расширение | Content-Type |
|-----------|-------------|
| `.html` | `text/html` |
| `.css` | `text/css` |
| `.js` | `application/javascript` |
| `.json` | `application/json` |
| `.png` | `image/png` |
| `.svg` | `image/svg+xml` |
| `.woff2` | `font/woff2` |

## Файловый кеш

Файловый кеш снижает количество системных вызовов к файловой системе при маршрутизации и отдаче файлов. Он использует `RwLock<FileCacheInner>`, оборачивающий три отдельных HashMap (кеши метаданных, содержимого и канонических путей), с LRU-вытеснением на основе счётчика и работает на трёх уровнях:

### Кеш метаданных

Хранит информацию о том, является ли путь файлом, директорией или не существует. Маршрутизатор проверяет этот кеш при каждом запросе, чтобы решить — отдать файл, выполнить скрипт или вернуть 404 — без обращения к файловой системе.

- Ёмкость: 200 записей (настраивается на этапе компиляции)
- Вытеснение: LRU по счётчику обращений
- При промахе кеша выполняется асинхронный вызов `tokio::fs::metadata()`

### Кеш содержимого

Хранит полное содержимое небольших файлов, чтобы повторные запросы обслуживались из памяти без дискового ввода-вывода.

- Максимум на файл: 1 МБ
- Общий бюджет кеша: 64 МБ
- Вытеснение: LRU при превышении общего объёма
- Данные хранятся как `Bytes` (с подсчётом ссылок, клонирование без копирования)
- MIME-тип хранится рядом с содержимым как `Arc<str>`

Файлы размером более 1 МБ никогда не кешируются и всегда отдаются потоково с диска.

### Кеш канонических путей

Хранит результаты вызовов `canonicalize()`, используемых для защиты от выхода через символические ссылки. Это позволяет избежать повторных системных вызовов `realpath(3)` для одних и тех же путей.

- Разделяет ту же ёмкость в 200 записей с кешем метаданных
- Хранит `Option<PathBuf>` -- `None` означает, что файл не существовал на момент кеширования
- Вытеснение: LRU по счётчику обращений

## HTTP-кеширование

OxPHP поддерживает HTTP-кеширование статических файлов с валидацией ETag и условными запросами, управляемое переменной окружения `STATIC_CACHE_TTL`.

### Конфигурация

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `STATIC_CACHE_TTL` | `30d` | TTL кеширования статических файлов. Поддерживает гибкие форматы длительности или `off` для отключения |

Поддерживаемые форматы длительности:

| Формат | Пример | Секунды |
|--------|--------|---------|
| Секунды | `30s` | 30 |
| Минуты | `5m` | 300 |
| Часы | `2h` | 7,200 |
| Дни | `30d` | 2,592,000 |
| Недели | `1w` | 604,800 |
| Годы | `1y` | 31,536,000 |
| Число без суффикса | `3600` | 3,600 |
| Отключено | `off` | *(без заголовков кеширования)* |

### Заголовки ответа

При включённом кешировании каждый ответ со статическим файлом включает:

| Заголовок | Значение | Пример |
|-----------|----------|--------|
| `Cache-Control` | `public, max-age={ttl}` | `public, max-age=2592000` |
| `ETag` | Weak ETag из размера файла и mtime | `W/"1024-65a1b2c3"` |
| `Last-Modified` | HTTP-дата по RFC 7231 | `Tue, 14 Nov 2023 18:13:20 GMT` |

### Условные запросы (304 Not Modified)

Когда клиент отправляет заголовки `If-None-Match` или `If-Modified-Since`, OxPHP валидирует их по текущим метаданным файла:

1. **If-None-Match** имеет приоритет (согласно RFC 7232 §3.3). ETag сравнивается со списком тегов, разделённых запятыми. Значение `*` всегда совпадает.
2. **If-Modified-Since** проверяется как резервный вариант. Время модификации файла (усечённое до секундной точности) сравнивается со значением заголовка.

Если файл не изменился, OxPHP возвращает ответ `304 Not Modified` с заголовками `ETag`, `Last-Modified` и `Cache-Control`, но без тела. Эта проверка выполняется **до** любого файлового ввода-вывода:

- Для **закешированных файлов**: условная проверка выполняется под read lock без клонирования данных
- Для **незакешированных файлов**: условная проверка выполняется после `fs::metadata()`, но до `fs::read()`, избегая чтения с диска для неизменённых файлов

### Формат ETag

ETag использует формат weak `W/"<size>-<mtime_hex>"`, где:

- `<size>` — размер файла в байтах (десятичный)
- `<mtime_hex>` — Unix-временная метка последней модификации (шестнадцатеричный, в нижнем регистре)

Weak ETag обозначают семантическую эквивалентность — ответ может отличаться на уровне байтов (например, после сжатия Brotli), но представляет тот же контент.

### Отключение кеширования

Установите `STATIC_CACHE_TTL=off` для отключения всех заголовков кеширования. Заголовки `Cache-Control`, `ETag` и `Last-Modified` не будут отправляться, и условные запросы не будут обрабатываться.

## Поведение при отдаче файлов

При поступлении запроса на статический файл:

1. **Условная проверка (кеш)** -- если файл находится в кеше содержимого и имеет совпадающие условные заголовки, немедленно возвращается 304
2. **Проверка кеша содержимого** -- если файл закеширован, он возвращается с сохранённым MIME-типом и заголовками кеширования
3. **Определение MIME-типа** -- вычисление типа содержимого по расширению файла
4. **Повторная проверка TOCTOU** -- если защита через символические ссылки включена, путь канонизируется повторно перед чтением
5. **Метаданные + условная проверка (без кеша)** -- чтение метаданных файла; при совпадении условных заголовков возвращается 304 до чтения файла
6. **Проверка размера** -- определение стратегии отдачи в зависимости от размера файла

### Малые файлы (до 1 МБ)

Весь файл считывается в память с помощью `tokio::fs::read()`, помещается в кеш содержимого и возвращается как буферизованное тело ответа. Заголовок `Content-Length` устанавливается равным точному количеству байт.

### Большие файлы (более 1 МБ)

Файл открывается с помощью `tokio::fs::File::open()` и отдаётся клиенту потоково через `ReaderStream`. Заголовок `Content-Length` устанавливается из метаданных файла, чтобы клиент знал общий размер.

## Заголовки ответа

Каждый ответ со статическим файлом включает:

| Заголовок | Значение |
|-----------|----------|
| `Content-Type` | Определённый MIME-тип |
| `Content-Length` | Размер файла в байтах |
| `Cache-Control` | `public, max-age={ttl}` *(при включённом кешировании)* |
| `ETag` | `W/"<size>-<mtime_hex>"` *(при включённом кешировании)* |
| `Last-Modified` | HTTP-дата по RFC 7231 *(при включённом кешировании)* |

## Метрики кеша

Файловый кеш предоставляет два счётчика Prometheus для мониторинга эффективности кеша:

| Метрика | Описание |
|---------|----------|
| `oxphp_static_cache_hits_total` | Запросы, обслуженные из кеша содержимого (без дискового ввода-вывода) |
| `oxphp_static_cache_misses_total` | Запросы, потребовавшие чтения с диска |

Коэффициент попаданий в кеш вычисляется как `hits / (hits + misses)`. Низкий коэффициент может указывать на то, что бюджет кеша содержимого (64 МБ) слишком мал для рабочего набора, или что большинство запрашиваемых файлов превышают лимит кеширования в 1 МБ на файл.

## Обработка ошибок

- **Файл не найден**: возвращается 404 с текстовым телом ответа
- **Ошибки доступа**: передаются как ошибка 500
- **Сбой чтения после проверки метаданных**: возвращается 404 (файл мог быть удалён между проверкой и чтением)
