# Статические файлы

OxPHP обслуживает статические файлы напрямую из корневого каталога документов без вызова PHP. Файлы отдаются с автоматическим определением MIME-типа, кэшем в памяти для быстрого повторного доступа и полной поддержкой HTTP-кэширования, включая ETags, условные запросы и Range-запросы для частичной загрузки.

## Как это работает

Когда запрос соответствует статическому файлу:

1. **Файл найден** — слой маршрутизации разрешает URL-путь в файл на диске
2. **Определение MIME** — тип содержимого определяется по расширению файла
3. **Проверка кэша** — проверяется кэш файлов до обращения к файловой системе
4. **Условная проверка** — если запрос содержит `If-None-Match` или `If-Modified-Since`, OxPHP оценивает условие и может вернуть `304 Not Modified` без отправки тела
5. **Проверка Range** — если GET- или HEAD-запрос содержит заголовок `Range`, OxPHP отвечает `206 Partial Content`: GET получает только запрошенный диапазон байтов, HEAD — те же заголовки диапазона без тела
6. **Ответ** — файлы размером до 1 МиБ отдаются из кэша в памяти; более крупные файлы передаются потоком непосредственно с диска

## Конфигурация

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `STATIC_MAX_AGE` | `30d` | Значение `Cache-Control: max-age` для статических файлов. Принимает `30s`, `5m`, `2h`, `30d`, `1w`, `1y`, число секунд (например, `3600`) или `off` для полного отключения заголовков кэширования. Заменяет устаревшую `STATIC_CACHE_TTL`. |
| `STATIC_REVALIDATE` | `off` | `on` — включает проверку mtime для кэша контента в памяти (файл перепроверяется не чаще одного раза в 3 секунды; изменения становятся видны в пределах этого окна). Заменяет устаревшую `STATIC_CACHE` (где значение `off` имело обратный смысл). |

## Определение MIME-типов

MIME-типы определяются автоматически по расширению файла. Если тип не удаётся определить, сервер возвращает `application/octet-stream`. Распространённые соответствия:

| Расширение | Content-Type |
|------------|-------------|
| `.html` | `text/html` |
| `.css` | `text/css` |
| `.js` | `text/javascript` |
| `.json` | `application/json` |
| `.png` | `image/png` |
| `.svg` | `image/svg+xml` |
| `.woff2` | `font/woff2` |

## Кэширование файлов

OxPHP использует кэш в памяти для уменьшения дискового ввода-вывода при частых запросах к файлам:

- Файлы **до 1 МиБ** (1 048 576 байт) считываются в память и кэшируются. Общий объём кэша составляет 64 МиБ (67 108 864 байт). При превышении этого объёма наименее недавно использованные записи вытесняются для освобождения места.
- Файлы **размером более 1 МиБ** всегда передаются потоком непосредственно с диска. Заголовок `Content-Length` устанавливается из метаданных файла, чтобы клиент знал общий размер заранее.

Кэш файлов заполняется при первом запросе к каждому файлу и сохраняется для последующих запросов. По умолчанию записи кэша остаются до вытеснения по политике LRU.

### Ревалидация контента

Установите `STATIC_REVALIDATE=on` для включения проверки mtime. В этом режиме сервер перепроверяет время модификации закэшированного файла системным вызовом `stat()` **не чаще одного раза в 3 секунды на файл**, а не при каждом запросе. Если файл изменился на диске, устаревшая запись удаляется и файл перечитывается автоматически. В пределах 3-секундного окна запись отдаётся прямо из памяти без системного вызова — стоимость амортизируется, а не платится на каждый запрос. Изменения на диске становятся видны в течение 3 секунд. **Включайте этот режим при разработке** — изменения файлов видны без перезапуска сервера. В продакшене оставляйте выключенным.

В продакшене оставьте `STATIC_REVALIDATE` без значения (по умолчанию `off`) для максимальной производительности без дополнительных системных вызовов.

## HTTP-кэширование

### Cache-Control

Когда `STATIC_MAX_AGE` задан (по умолчанию `30d`), каждый ответ со статическим файлом содержит заголовок `Cache-Control`:

```http
Cache-Control: public, max-age=2592000
```

Значение `max-age` — это TTL, преобразованный в секунды. Установите `STATIC_MAX_AGE=off`, чтобы полностью убрать этот заголовок.

### ETag и Last-Modified

Каждый ответ со статическим файлом включает:

- **ETag** — строгий (strong) ETag в формате `"<size>-<mtime_hex>"`, основанный на размере файла и времени последнего изменения. Строгий валидатор также удовлетворяет `If-Range`, поэтому прерванные загрузки безопасно докачиваются. Если ответ отдаётся сжатым brotli, метка ослабляется до `W/"…"` — сжатые байты являются другим представлением; слабая метка по-прежнему проходит ревалидацию (304), но не позволяет смешивать сжатые и несжатые фрагменты при докачке.
- **Last-Modified** — HTTP-дата по RFC 7231, основанная на времени изменения файла

Эти заголовки позволяют браузерам и CDN проверять кэшированные копии без повторной загрузки файла.

### Условные запросы (304)

OxPHP оценивает заголовки условных запросов, чтобы избежать отправки неизменившегося содержимого файла:

- **If-None-Match** — клиент отправляет кэшированный ETag. Если он совпадает с текущим файлом, OxPHP возвращает `304 Not Modified` без тела.
- **If-Modified-Since** — клиент отправляет временную метку. Если файл не изменялся с этого момента, OxPHP возвращает 304.

`If-None-Match` имеет приоритет над `If-Modified-Since` согласно RFC 7232. Для файлов, уже находящихся в кэше памяти, условная проверка выполняется без какого-либо дискового ввода-вывода.

### Range-запросы (206)

Ответы со статическими файлами объявляют `Accept-Ranges: bytes`, а GET-запросы с одиночным диапазоном в заголовке `Range` получают только запрошенные байты:

```http
GET /videos/intro.mp4 HTTP/1.1
Range: bytes=1048576-

HTTP/1.1 206 Partial Content
Content-Range: bytes 1048576-52428799/52428800
Content-Length: 51380224
```

Это обеспечивает перемотку `<video>`/`<audio>` в браузерах, докачку загрузок (`wget -c`, менеджеры закачек) и частичную подгрузку PDF. Поддерживаются все три формы диапазона из RFC 9110: `bytes=N-M`, `bytes=N-` (от смещения до конца) и `bytes=-N` (последние N байтов).

- Невыполнимый диапазон (начало за концом файла) возвращает `416 Range Not Satisfiable` с `Content-Range: bytes */<size>`.
- **If-Range** учитывается: если клиент присылает ETag (или дату `Last-Modified`) своей частичной копии, а файл с тех пор изменился, OxPHP возвращает полный ответ `200` вместо несовместимого фрагмента. Форма с датой принимается только после того, как секунда модификации файла полностью истекла — только что записанный файл может измениться ещё раз в пределах той же секунды без изменения даты, поэтому такая дата ещё не является строгим валидатором (RFC 9110).
- Запросы с **несколькими диапазонами** (`bytes=0-1,4-5`) получают весь файл как `200 OK` — ответы `multipart/byteranges` не генерируются.
- **HEAD**-запросы с заголовком `Range` получают те же заголовки `206`/`Content-Range`, что и GET, но без тела — как nginx и Apache.
- **Диапазоны и сжатие взаимоисключающие.** Для клиентов, принимающих brotli, обработка диапазонов отключается у представлений, которые были бы отданы сжатыми, а сжатые ответы не объявляют `Accept-Ranges` — иначе докачка могла бы приклеить несжатые байты к сжатому префиксу. Сжимаются только файлы, отдаваемые из кэша в памяти (до 1 МиБ), поэтому диапазоны всегда работают для контента, которому они реально нужны: видео, архивы, изображения и все файлы, передаваемые потоком с диска. Ответы для файлов, подпадающих под сжатие, всегда несут `Vary: Accept-Encoding` — даже когда отдаются несжатыми, — чтобы общие кэши хранили варианты раздельно.
- Ответы `206` никогда не сжимаются, а обработка Range не применяется к PHP-ответам — только к статическим файлам.

Пример: докачка прерванной загрузки с помощью curl:

```bash
curl -C - -O https://example.com/dist/app-installer.dmg
```

### Отключение кэширования

Существуют два независимых слоя кэширования с отдельной переменной для каждого:

| Переменная | Управляет | Эффект `off` |
|-----------|-----------|--------------|
| `STATIC_MAX_AGE=off` | **Кэш браузера** (HTTP-заголовки) | Заголовки `Cache-Control`, `ETag`, `Last-Modified` не отправляются |
| `STATIC_REVALIDATE=on` | **Кэш сервера в памяти** | mtime файла перепроверяется не чаще одного раза в 3 секунды на файл; устаревшие записи удаляются автоматически |

Для разработки установите `STATIC_REVALIDATE=on`, чтобы сервер всегда отдавал актуальный контент. Дополнительно можно установить `STATIC_MAX_AGE=off` для полного отключения кэширования в браузере.

## Устранение неполадок

### Сервер отдаёт устаревшие файлы

По умолчанию кэш контента в памяти не проверяет, изменились ли файлы на диске. Установите `STATIC_REVALIDATE=on` при разработке — сервер будет автоматически обнаруживать изменения файлов (в течение 3 секунд).

### Браузер продолжает отдавать устаревшие файлы

Если сервер возвращает актуальный контент, но браузер показывает старую версию — виноват кэш самого браузера. Установите `STATIC_MAX_AGE=off` чтобы не отправлять заголовки кэширования, или используйте принудительную перезагрузку в браузере (Shift+F5 или Cmd+Shift+R).

### Файлы отдаются с типом `application/octet-stream`

OxPHP использует расширение файла для определения MIME-типа. Если расширение отсутствует или не распознано, используется `application/octet-stream`. Добавьте правильное расширение к файлу или убедитесь, что ваш фреймворк явно устанавливает заголовок `Content-Type` в PHP-ответах.

### Большие файлы загружаются медленно

Файлы размером более 1 МиБ передаются потоком с диска при каждом запросе и не кэшируются в памяти. Для очень больших файлов разместите CDN перед OxPHP для их кэширования на краю сети. В качестве альтернативы реструктурируйте ресурсы так, чтобы часто запрашиваемые файлы оставались в пределах 1 МиБ.

### Возвращаются ответы 304, тогда как ожидается 200

Ответ 304 означает, что у клиента уже есть актуальная версия. Это корректное поведение. Если вам нужно принудительно получить свежий ответ в процессе разработки, установите `STATIC_MAX_AGE=off`, чтобы заголовки `ETag` и `Last-Modified` не отправлялись.

## Пример Docker

```yaml
services:
  app:
    image: ghcr.io/oxphp/oxphp:0.10.0
    ports:
      - "8080:80"
    volumes:
      - ./src:/var/www/html
    environment:
      - DOCUMENT_ROOT=/var/www/html/public
      - ENTRY_FILE=index.php
      - STATIC_MAX_AGE=1y
```

## Лучшие практики

- **Используйте долгие TTL вместе с именами файлов, содержащими хэш сборки** в продакшене (например, `app.a1b2c3.js`). Установите `STATIC_MAX_AGE=1y` для максимального кэширования браузером и CDN.
- **Устанавливайте `STATIC_REVALIDATE=on` при разработке**, чтобы сервер автоматически обнаруживал изменения файлов. Дополнительно можно установить `STATIC_MAX_AGE=off` для отключения кэширования в браузере.
- **Размещайте CDN перед OxPHP** для сайтов с высокой нагрузкой. Заголовки `ETag`, `Last-Modified` и `Cache-Control` работают со всеми основными CDN-провайдерами.
- **Поручите хэширование ресурсов инструменту сборки.** Фреймворки Vite и Laravel Mix автоматически генерируют хэшированные имена файлов, делая долгие TTL безопасными.
