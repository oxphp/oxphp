# Ранний ответ

`oxphp_finish_request()` немедленно отправляет клиенту полный HTTP-ответ и позволяет PHP-скрипту продолжать работу для выполнения фоновых задач. Это эквивалент `fastcgi_finish_request()` из PHP-FPM для OxPHP.

## Как это работает

1. Скрипт устанавливает заголовки, код статуса и выводит тело ответа как обычно.
2. Вызовите `oxphp_finish_request()` — OxPHP очищает все буферы вывода, помечает запрос как завершённый и доставляет полный HTTP-ответ клиенту.
3. Скрипт продолжает выполняться для фоновой работы: отправки писем, записи кэша или отправки вебхуков.
4. Весь вывод после вызова (`echo`, `print`, `var_dump`) молча отбрасывается.
5. `oxphp_finish_request()` возвращает `true` при первом вызове и `false` при любом последующем вызове в рамках того же запроса.

## Случаи использования

Ранний ответ полезен всякий раз, когда нужно немедленно подтвердить запрос, откладывая некритичную работу:

- **Отправка писем** — немедленно вернуть "принято", отправить письмо в фоне
- **Прогрев кэша** — ответить кэшированными данными, затем обновить запись кэша
- **Аналитика и логирование** — подтвердить запрос, затем записать детальную аналитику
- **Отправка вебхуков** — подтвердить получение отправителю, затем разослать вебхуки
- **Обработка изображений** — немедленно вернуть URL, затем обработать полноразмерное изображение

## Примеры PHP

### Базовое использование

```php
<?php
header('Content-Type: application/json');
echo json_encode(['status' => 'accepted', 'id' => uniqid()]);

// Отправить ответ сейчас — клиент получает полный ответ в этот момент
oxphp_finish_request();

// Фоновая работа выполняется здесь; клиент больше не ожидает
file_put_contents('/tmp/audit.log', date('c') . " request processed\n", FILE_APPEND);
send_notification_email($user);
```

### Защита от повторного вызова

`oxphp_finish_request()` возвращает `false` при втором и последующих вызовах. Проверяйте возвращаемое значение в приложениях с большим количеством слоёв middleware, где несколько слоёв могут вызвать функцию:

```php
<?php
function finish_and_cleanup(): void
{
    if (!oxphp_finish_request()) {
        // Уже завершён — фоновая работа уже была запланирована
        return;
    }

    // Первый вызов — безопасно выполнять очистку
    flush_metrics_buffer();
    close_external_connections();
}
```

### Условная фоновая работа

```php
<?php
header('Content-Type: application/json');
$payload = json_decode(file_get_contents('php://input'), true);

$result = handle_request($payload);
echo json_encode($result);

if ($result['needs_sync']) {
    oxphp_finish_request();
    sync_to_external_service($result);
}
// Ранний выход не нужен, если синхронизация не требуется — скрипт завершается нормально
```

### Worker mode

В worker mode PHP-воркер остаётся занятым до завершения всего скрипта (включая всю фоновую работу). Воркер не принимает новый запрос до возврата из callback-функции.

```php
<?php
oxphp_worker(function () {
    $order = json_decode(file_get_contents('php://input'), true);

    $result = process_order($order);
    header('Content-Type: application/json');
    echo json_encode(['order_id' => $result['id'], 'status' => 'accepted']);
    oxphp_finish_request();

    // Воркер всё ещё занят во время этой фоновой работы
    send_confirmation_email($result);
    update_inventory($result);
    notify_warehouse($result);
    // Воркер становится доступным после этого момента
});
```

> **Примечание:** Учитывайте время фоновой обработки при выборе размера пула воркеров. Воркер, тратящий 3 секунды на пост-ответную работу после каждого запроса, эффективно обрабатывает меньше одновременных запросов.

## Устранение неполадок

### Фоновая работа не завершается

`max_execution_time` PHP продолжает действовать после вызова `oxphp_finish_request()`. Если общее время выполнения скрипта — включая фоновую работу — превышает лимит, запрос отменяется фатальной ошибкой `Request cancelled (timeout)`.

**Исправление:** Увеличьте `max_execution_time` (в `php.ini` или через `set_time_limit()` из скрипта) или перенесите длительные фоновые задачи в очередь сообщений:

```php
set_time_limit(300);
oxphp_finish_request();
// ... длительная работа ...
```

Для работы, регулярно занимающей более нескольких секунд, опубликуйте сообщение в Redis, RabbitMQ или аналогичную очередь и пусть выделенный потребитель обрабатывает её асинхронно.

### Изменения сессии теряются

Данные сессии должны быть записаны до вызова `oxphp_finish_request()`. Изменения, сделанные после вызова, отбрасываются.

**Исправление:** Вызовите `session_write_close()` до `oxphp_finish_request()`:

```php
<?php
$_SESSION['last_seen'] = time();
session_write_close();      // Сохранить сессию перед завершением
oxphp_finish_request();     // Отправить ответ
```

### Тело ответа пустое после вызова `oxphp_finish_request()`

Если вызвать `oxphp_finish_request()` до любого вывода через `echo`, клиент получит пустое тело. Сначала сформируйте и выведите ответ, затем вызывайте функцию.

## Примечания

- `oxphp_finish_request()` возвращает `true` при первом вызове и `false` при последующих вызовах в рамках того же запроса.
- Весь вывод (`echo`, `print`, `var_dump`) после первого вызова молча отбрасывается.
- В worker mode воркер остаётся занятым до полного завершения callback-функции, включая весь пост-ответный код.
- Тайм-аут запроса продолжает применяться к фоновому коду, выполняемому после `oxphp_finish_request()`.
- `oxphp_finish_request()` и `oxphp_stream_flush()` взаимно исключают друг друга: вызов `oxphp_finish_request()` до начала стриминга делает стриминг невозможным, а вызов после `oxphp_stream_flush()` закрывает поток.
