# Сжатие

OxPHP сжимает HTTP-ответы с использованием кодирования Brotli по умолчанию. Сжатие автоматически применяется к текстовым типам содержимого, когда клиент его поддерживает, уменьшая объём передаваемых данных без каких-либо изменений в коде приложения.

## Как это работает

1. **Проверка Accept-Encoding** — заголовок `Accept-Encoding` клиента анализируется на наличие поддержки `br` (Brotli). Запросы без `br` в этом заголовке никогда не сжимаются.
2. **Проверка типа содержимого** — MIME-тип ответа проверяется по списку сжимаемых типов.
3. **Проверка существующего кодирования** — ответы с уже существующим заголовком `Content-Encoding` пропускаются во избежание двойного сжатия.
4. **Проверка диапазона размера** — сжимаются только ответы размером от 256 байт до 3 МБ. Для меньших ответов выгода незначительна; для более крупных применяется потоковая передача без буферизации.
5. **Сжатие** — применяется кодирование Brotli. Если сжатый результат не меньше исходного, вместо него отправляется несжатый ответ.

Сжатие происходит после выполнения PHP и после обслуживания статических файлов. Всё сжатое тело кратковременно удерживается в памяти — именно поэтому ответы размером более 3 МБ исключаются.

## Конфигурация

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `COMPRESSION_LEVEL` | `4` | Уровень качества Brotli (0–11). Более высокие значения дают меньший размер вывода ценой большего времени процессора. Установите `0`, чтобы полностью отключить сжатие |

Уровень по умолчанию `4` обеспечивает хороший баланс между степенью сжатия и нагрузкой на процессор при веб-обслуживании. Уровни 9–11 лучше подходят для офлайн-сжатия или сжатия во время сборки.

## Сжимаемые типы содержимого

Сжатие применяется к следующим MIME-типам:

**Текстовые типы:**
- `text/html`
- `text/css`
- `text/plain`
- `text/xml`
- `text/javascript`

**Типы application:**
- `application/javascript`
- `application/json`
- `application/xml`
- `application/xhtml+xml`
- `application/rss+xml`
- `application/atom+xml`
- `application/manifest+json`
- `application/ld+json`
- `application/wasm`

**Другие типы:**
- `image/svg+xml`
- `font/ttf`
- `font/otf`
- `application/x-font-ttf`
- `application/x-font-opentype`
- `application/vnd.ms-fontobject`

## Не сжимается

Ответы отправляются без сжатия при выполнении любого из следующих условий:

- Клиент не объявляет `br` в заголовке `Accept-Encoding`
- Ответ уже содержит заголовок `Content-Encoding` (например, предварительно сжатое содержимое)
- Тело ответа меньше 256 байт или больше 3 МБ
- Тип содержимого отсутствует в списке сжимаемых типов (например, `image/png`, `image/jpeg`, `font/woff2`, `application/zip` — эти форматы уже используют внутреннее сжатие)

## Заголовки ответа

При применении сжатия OxPHP устанавливает следующие заголовки:

| Заголовок | Значение |
|-----------|----------|
| `Content-Encoding` | `br` |
| `Content-Length` | Обновляется до размера сжатого тела |
| `Vary` | К нему добавляется `Accept-Encoding`, гарантируя, что HTTP-кэши хранят отдельные версии для клиентов с поддержкой Brotli и без неё |

## Устранение неполадок

### Ответы не сжимаются

Убедитесь, что клиент отправляет `Accept-Encoding: br`. Большинство современных браузеров делают это, но некоторые инструменты тестирования HTTP не включают его по умолчанию.

**Проверка** с помощью curl:

```bash
curl -H "Accept-Encoding: br" -I http://localhost/
```

Ищите `Content-Encoding: br` в заголовках ответа. Если он отсутствует, проверьте следующее:

1. `COMPRESSION_LEVEL` не установлен в `0`
2. Тело ответа составляет не менее 256 байт
3. `Content-Type` ответа входит в приведённый выше список сжимаемых типов

### Сжатие увеличивает размер ответов

Для очень маленьких ответов (в несколько сотен байт) накладные расходы Brotli иногда дают результат, превышающий размер оригинала. OxPHP обнаруживает это и автоматически отправляет несжатый ответ — изменения конфигурации не требуются.

### Высокое потребление процессора из-за сжатия

Более высокие уровни качества (8–11) обеспечивают значительно лучшее сжатие, но потребляют намного больше процессорного времени. Если вы наблюдаете высокое потребление процессора из-за сжатия:

**Решение:** Снизьте `COMPRESSION_LEVEL` до `4` или `5`. Эти уровни обеспечивают 80–90% уменьшения размера по сравнению с максимальным качеством при значительно меньших затратах процессора.

### Предварительно сжатые ресурсы сжимаются повторно

Если ваш конвейер сборки генерирует файлы `.br` и устанавливает заголовок `Content-Encoding: br` для этих файлов, OxPHP автоматически пропускает повторное сжатие. Если ваше предварительно сжатое содержимое сжимается снова, убедитесь, что заголовок `Content-Encoding` присутствует в исходном ответе до выполнения сжатия.

## Пример Docker

```yaml
services:
  app:
    image: ghcr.io/oxphp/oxphp:0.3.0
    ports:
      - "8080:80"
    volumes:
      - ./src:/var/www/html
    environment:
      - DOCUMENT_ROOT=/var/www/html/public
      - ENTRY_FILE=index.php
      - COMPRESSION_LEVEL=6
```
