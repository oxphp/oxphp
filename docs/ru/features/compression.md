title: Сжатие
description: Brotli-сжатие для сжимаемых типов ответов

OxPHP сжимает HTTP-ответы с помощью Brotli, когда клиент поддерживает это кодирование и тип ответа допускает сжатие. Сжатие включено по умолчанию и может быть переключено переменной окружения.

## Конфигурация

| Переменная | Описание | По умолчанию |
|------------|----------|-------------|
| `COMPRESSION` | Включить Brotli-сжатие | `true` |

Для отключения сжатия:

```bash
COMPRESSION=false
```

Значения `false`, `0` и `off` отключают сжатие. Любое другое значение (или отсутствие переменной) включает его.

## Как это работает

Конвейер сжатия выполняется после формирования ответа и до его отправки клиенту. Он вызывается только когда запрос содержит заголовок `Accept-Encoding` -- запросы без этого заголовка полностью пропускают функцию сжатия, избегая асинхронных накладных расходов.

### Логика принятия решения

1. **Проверка Accept-Encoding** -- разбор заголовка, разделение по `,`, извлечение имени кодирования до параметра качества `;` и поиск `br`
2. **Проверка Content-Type** -- проверка того, что MIME-тип ответа входит в список сжимаемых типов
3. **Проверка наличия кодирования** -- пропуск, если ответ уже содержит заголовок `Content-Encoding`
4. **Проверка Content-Length** -- пропуск, если заголовок `Content-Length` присутствует и его значение выходит за пределы диапазона от 256 байт до 3 МБ
5. **Проверка подсказки о размере тела** -- пропуск, если подсказка о размере тела (когда `Content-Length` отсутствует) выходит за пределы диапазона от 256 байт до 3 МБ
6. **Сбор тела** -- материализация тела ответа в память
7. **Проверка размера во время выполнения** -- проверка того, что собранное тело находится в допустимом диапазоне (для ответов без заранее известного размера)
8. **Сжатие** -- применение Brotli и отброс результата, если сжатый вариант не меньше оригинала

### Параметры Brotli

| Параметр | Значение | Примечания |
|----------|----------|-----------|
| Качество | 4 | Баланс между скоростью и степенью сжатия для веб-сервера |
| Размер окна | 20 | Окно 1 МБ, подходит для типичных веб-ответов |

Уровень качества 4 выбран как компромисс: он обеспечивает достаточное сжатие для текстового веб-контента без затрат процессора на более высокие уровни качества (9-11), которые лучше подходят для офлайн-сжатия.

## Сжимаемые типы

Сжатие применяется к следующим 19 MIME-типам (сопоставление точное, не по префиксу):

**Текстовые типы:**
- `text/html`
- `text/css`
- `text/plain`
- `text/xml`
- `text/javascript`

**Типы application:**
- `application/javascript`
- `application/json`
- `application/xml`
- `application/xhtml+xml`
- `application/rss+xml`
- `application/atom+xml`
- `application/manifest+json`
- `application/ld+json`
- `application/wasm`

**Прочие:**
- `image/svg+xml`
- `font/ttf`
- `font/otf`
- `application/x-font-ttf`
- `application/x-font-opentype`
- `application/vnd.ms-fontobject`

Типы вроде `image/png`, `image/jpeg`, `font/woff2` и `application/zip` не сжимаются, так как уже используют внутреннее сжатие.

## Ограничения по размеру

| Ограничение | Значение | Причина |
|-------------|----------|---------|
| Минимум | 256 байт | Малые ответы вряд ли выиграют от сжатия |
| Максимум | 3 МБ | Более крупные ответы следует отдавать потоково с диска без загрузки в память |

Ответы вне этого диапазона отправляются без сжатия.

## Заголовки ответа

При применении сжатия устанавливаются следующие заголовки:

| Заголовок | Значение |
|-----------|----------|
| `Content-Encoding` | `br` |
| `Content-Length` | Обновляется до размера сжатых данных |
| `Vary` | `Accept-Encoding` (добавляется) |

Заголовок `Vary` гарантирует, что HTTP-кеши хранят отдельные версии для клиентов, поддерживающих Brotli, и тех, которые его не поддерживают.
