# TLS

OxPHP обрабатывает завершение TLS нативно — без обратного прокси или внешней SSL-библиотеки. При наличии конфигурации сервер принимает HTTPS-соединения и автоматически согласовывает наилучший доступный протокол.

## Как это работает

Для включения TLS укажите в `TLS_CERT` и `TLS_KEY` пути к PEM-кодированным файлам сертификата и закрытого ключа. Как только оба параметра установлены, сервер начинает принимать HTTPS-соединения по адресу, заданному в `LISTEN_ADDR`.

Рукопожатие TLS происходит до любой HTTP-обработки:

1. TCP-соединение поступает на `LISTEN_ADDR`.
2. Сервер выполняет рукопожатие TLS с использованием настроенного сертификата и ключа.
3. Согласование протокола (ALPN) выбирает HTTP/2 (`h2`) или HTTP/1.1 в зависимости от поддержки клиентом.
4. Зашифрованное соединение передаётся в HTTP-слой для обычной обработки запросов.

> **Примечание:** При включённом TLS тайм-ауты заголовков и запросов применяются к каждому запросу после завершения рукопожатия TLS.

## Конфигурация

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `TLS_CERT` | *(не задана)* | Путь к PEM-кодированному файлу сертификата. Для включения TLS должны быть заданы оба параметра — `TLS_CERT` и `TLS_KEY` |
| `TLS_KEY` | *(не задана)* | Путь к PEM-кодированному файлу закрытого ключа |
| `LISTEN_ADDR` | `0.0.0.0:80` | Адрес и порт для прослушивания. Измените на `0.0.0.0:443` при использовании TLS |

Если задан только один из параметров — `TLS_CERT` или `TLS_KEY` — TLS не включается и сервер запускается в режиме обычного HTTP.

## Поддерживаемые протоколы

| Возможность | Подробности |
|-------------|-------------|
| Версии TLS | TLS 1.2 и TLS 1.3 |
| Протоколы ALPN | `h2` (HTTP/2) и `http/1.1`, согласовываются в указанном порядке |
| Клиентские сертификаты | Не поддерживаются (взаимный TLS отсутствует) |

## HTTP/2

OxPHP отдаёт HTTP/2 и HTTP/1.1 на одном порту. Протокол выбирается для каждого соединения — отдельной настройки, чтобы включить или выключить HTTP/2, нет:

- **Поверх TLS** протокол согласуется во время рукопожатия через ALPN. OxPHP анонсирует `h2`, затем `http/1.1`, поэтому клиенты с поддержкой HTTP/2 получают HTTP/2, а остальные прозрачно откатываются на HTTP/1.1.
- **Без TLS (h2c)** OxPHP распознаёт преамбулу HTTP/2-соединения и отдаёт незашифрованный HTTP/2 клиентам, которые подключаются с prior knowledge (например, `curl --http2-prior-knowledge`). Клиенты, не поддерживающие HTTP/2, продолжают работать по HTTP/1.1 на том же порту. (Рукопожатие `Upgrade: h2c` не используется — HTTP/2 поверх незашифрованного соединения требует prior knowledge.)

Окна управления потоком HTTP/2 подняты выше значений по умолчанию — 8 МБ на соединение и 4 МБ на поток против дефолтных 64 КБ — чтобы избежать стопоров на типичных PHP-ответах, которые обычно больше одного окна по умолчанию.

PHP видит согласованный протокол в `$_SERVER['SERVER_PROTOCOL']` (`"HTTP/2"` или `"HTTP/1.1"`).

### Как проверить

```bash
# HTTP/2 поверх TLS (согласование через ALPN)
curl -k --http2 -I https://localhost/

# Незашифрованный HTTP/2 (h2c, prior knowledge)
curl --http2-prior-knowledge -I http://localhost/
```

Ищите `HTTP/2 200` в строке ответа.

## Поддерживаемые типы ключей

Файл закрытого ключа должен содержать один PEM-кодированный ключ в одном из следующих форматов:

- **RSA**
- **ECDSA** (например, prime256v1, secp384r1)
- **Ed25519**

Файл сертификата может содержать один или несколько PEM-кодированных сертификатов. Для использования в продакшене включайте полную цепочку: ваш серверный сертификат, за которым следуют промежуточные сертификаты.

## Самоподписанный сертификат для разработки

Создайте самоподписанный ECDSA-сертификат для локальной разработки:

```bash
openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:prime256v1 \
  -keyout key.pem -out cert.pem -days 365 -nodes \
  -subj "/CN=localhost"
```

Затем настройте OxPHP для использования созданных файлов:

```bash
TLS_CERT=./cert.pem
TLS_KEY=./key.pem
LISTEN_ADDR=0.0.0.0:443
```

## Устранение неполадок

### Сервер запускается, но TLS не активен

OxPHP требует, чтобы были заданы **оба** параметра — `TLS_CERT` и `TLS_KEY`. Если один из них отсутствует, сервер запускается в режиме обычного HTTP без каких-либо предупреждений. Убедитесь, что оба параметра установлены:

```bash
docker exec <container> env | grep TLS
```

### Ошибка `no private key found in PEM file` при запуске

Файл ключа пустой, повреждённый или содержит только сертификат. Убедитесь, что файл ключа содержит блок `-----BEGIN ... PRIVATE KEY-----`:

```bash
grep "PRIVATE KEY" key.pem
```

Если ключ отсутствует, создайте пару сертификат/ключ заново.

### Ошибка `no certificates found in PEM file` при запуске

Файл сертификата пустой или повреждённый. Убедитесь, что файл сертификата содержит хотя бы один блок `-----BEGIN CERTIFICATE-----`:

```bash
grep "BEGIN CERTIFICATE" cert.pem
```

### Клиенты видят ошибку цепочки сертификатов

Сервер отправляет только конечный сертификат без промежуточных. Объедините полную цепочку в один PEM-файл:

```bash
cat cert.pem intermediate.pem > fullchain.pem
```

Затем установите `TLS_CERT=./fullchain.pem`.

### Сертификат истёк

OxPHP читает файлы сертификатов при запуске и хранит их в памяти. Обновление сертификата на диске не имеет эффекта до перезапуска сервера.

**Решение:** Перезапустите OxPHP после обновления сертификата. Автоматизируйте это с помощью инструмента обновления сертификатов (например, параметра `--deploy-hook` в certbot).

### Невозможно одновременно обслуживать HTTP и HTTPS на одном порту

OxPHP прослушивает один порт. Для одновременной поддержки обоих протоколов используйте обратный прокси (Caddy, Traefik, nginx), который обрабатывает перенаправление HTTP на HTTPS, или запустите второй экземпляр OxPHP на порту 80, предназначенный исключительно для перенаправления трафика.

## Пример Docker

```yaml
services:
  app:
    image: ghcr.io/oxphp/oxphp:0.5.0
    ports:
      - "443:443"
    environment:
      LISTEN_ADDR: "0.0.0.0:443"
      TLS_CERT: "/etc/ssl/oxphp/cert.pem"
      TLS_KEY: "/etc/ssl/oxphp/key.pem"
    volumes:
      - ./app:/var/www/html:ro
      - ./certs:/etc/ssl/oxphp:ro
```

## Лучшие практики

- **Включайте промежуточные сертификаты** в PEM-цепочку. Сначала укажите серверный сертификат, затем промежуточные по порядку, чтобы клиенты могли проверить полный путь доверия.
- **Автоматизируйте обновление сертификатов.** Используйте certbot или acme.sh для обновления сертификатов до истечения срока, затем перезапускайте OxPHP для загрузки новых файлов.
- **Используйте обратный прокси для перенаправления HTTP на HTTPS.** OxPHP не обслуживает одновременно HTTP и HTTPS на одном порту.

## Примечания

- OxPHP не зависит от OpenSSL. TLS обрабатывается встроенной реализацией, что устраняет распространённый источник CVE внешних библиотек.
- Файлы сертификата и ключа читаются только при запуске. Обновление сертификатов на диске требует перезапуска сервера.
