OxPHP терминирует TLS напрямую с помощью rustls, без зависимости от OpenSSL. При настроенном TLS сервер принимает HTTPS-соединения и согласовывает HTTP/2 или HTTP/1.1 через ALPN.

## Конфигурация

| Переменная | Описание | По умолчанию |
|------------|----------|-------------|
| `TLS_CERT` | Путь к файлу сертификата в формате PEM | *(не задано)* |
| `TLS_KEY` | Путь к файлу закрытого ключа в формате PEM | *(не задано)* |

Обе переменные должны быть заданы для включения TLS. Если указана только одна, TLS не включается.

```bash
TLS_CERT=/etc/oxphp/cert.pem
TLS_KEY=/etc/oxphp/key.pem
LISTEN_ADDR=0.0.0.0:443
```

## Как это работает

При запуске OxPHP считывает файлы сертификата и ключа, разбирает их как PEM и создаёт `TlsAcceptor` из конфигурации rustls.

Конфигурация TLS включает:

- **Криптографический провайдер**: ring (через `rustls::crypto::ring::default_provider()`)
- **Версии протокола**: безопасные значения по умолчанию, выбранные rustls (TLS 1.2 и 1.3)
- **Аутентификация клиента**: отключена (проверка клиентского сертификата не выполняется)
- **Протоколы ALPN**: `h2` и `http/1.1`, в указанном порядке

При поступлении TCP-соединения сервер вызывает `acceptor.accept(stream)` для выполнения TLS-рукопожатия, после чего передаёт зашифрованный поток в hyper для обработки HTTP.

## Форматы сертификатов

Файл сертификата должен содержать один или несколько сертификатов в формате PEM (сертификат сервера, за которым следуют промежуточные сертификаты, если применимо). Файл ключа должен содержать один закрытый ключ в формате PEM (RSA, ECDSA или Ed25519).

### Самоподписанный сертификат для разработки

Генерация самоподписанного сертификата для локальной разработки:

```bash
openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:prime256v1 \
  -keyout key.pem -out cert.pem -days 365 -nodes \
  -subj "/CN=localhost"
```

Затем настройте OxPHP:

```bash
TLS_CERT=./cert.pem
TLS_KEY=./key.pem
```

### Пример с Docker

Монтирование сертификатов в контейнер:

```yaml
services:
  oxphp:
    image: oxphp:latest
    ports:
      - "443:443"
    environment:
      LISTEN_ADDR: "0.0.0.0:443"
      TLS_CERT: /certs/cert.pem
      TLS_KEY: /certs/key.pem
    volumes:
      - ./certs:/certs:ro
```

## Работа в смешанном режиме

OxPHP не обслуживает HTTP и HTTPS на одном и том же слушателе. Для поддержки обоих протоколов запустите два экземпляра или используйте обратный прокси для перенаправления HTTP на HTTPS.

## Отсутствие зависимости от OpenSSL

Использование rustls означает, что бинарный файл сервера вообще не линкуется с OpenSSL. Это устраняет распространённый источник CVE в производственных развёртываниях и упрощает образ контейнера (не требуются пакеты `libssl`).
