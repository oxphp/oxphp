# Тайм-ауты

OxPHP применяет два независимых тайм-аута, защищающих от медленных клиентов и зависших запросов. Тайм-аут заголовков охраняет фазу подключения, а тайм-аут запроса ограничивает общее время обработки, включая выполнение PHP.

## Как это работает

Каждый запрос проходит через две последовательные фазы тайм-аута:

1. **Соединение принято** — запускается тайм-аут заголовков. OxPHP ожидает, пока клиент отправит полный набор HTTP-заголовков.
2. **Заголовки получены** — тайм-аут заголовков заканчивается. Запускается тайм-аут запроса, охватывающий маршрутизацию, выполнение PHP и формирование ответа.
3. **PHP обрабатывает запрос** — код приложения выполняется в пределах тайм-аута запроса.
4. **Ответ отправлен** — оба тайм-аута истекли. На keep-alive-соединениях цикл повторяется с шага 1.

```text
TCP connect (+ TLS handshake если включён)
  |
  +-- [HEADER_TIMEOUT_SECONDS] --> заголовки получены
                                   |
                                   +-- [REQUEST_TIMEOUT_SECONDS] --> ответ отправлен
                                                                    |
                                                                    +-- следующий запрос (keep-alive)
```

На keep-alive-соединениях оба тайм-аута применяются независимо к каждому запросу в соединении.

> **Примечание:** При включённом TLS тайм-аут заголовков запускается после завершения TLS-рукопожатия, а не в момент принятия TCP-соединения.

Тайм-аут заголовков защищает от атак типа slowloris, при которых клиент отправляет заголовки по одному байту, удерживая соединения открытыми неограниченно долго. Тайм-аут запроса гарантирует освобождение ресурсов сервера, даже если PHP не соблюдает собственную настройку `max_execution_time`.

При срабатывании тайм-аута запроса OxPHP возвращает ответ `504 Gateway Timeout` и записывает предупреждение с идентификатором запроса и настроенным значением тайм-аута.

## Конфигурация

| Переменная | По умолчанию | Описание |
|------------|-------------|----------|
| `HEADER_TIMEOUT_SECONDS` | `5` | Максимальное количество секунд для получения заголовков запроса после принятия соединения. Защищает от атак slowloris. Установите `0` для отключения |
| `REQUEST_TIMEOUT_SECONDS` | `120` | Максимальное количество секунд для полной обработки запроса, включая выполнение PHP. При превышении возвращает `504`. Установите `0` для отключения |

## Рекомендуемые значения

| Сценарий | Тайм-аут заголовков | Тайм-аут запроса |
|----------|---------------------|------------------|
| API-сервер | 5с | 30с |
| Обычный веб-сервер | 5с | 60с |
| Загрузка файлов | 10с | 300с |
| SSE / long-polling | 5с | 0 (отключён) |

Корректируйте эти значения исходя из характеристик вашего приложения. Если PHP-скрипты выполняют длительные операции — например, генерацию отчётов или импорт данных — увеличьте тайм-аут запроса соответствующим образом. Для SSE-эндпоинтов отключите тайм-аут запроса, чтобы долгосрочные соединения не завершались преждевременно.

## Устранение неполадок

### Клиенты неожиданно получают 504 Gateway Timeout

Тайм-аут запроса срабатывает до того, как PHP завершает выполнение.

**Проверьте:** Запросите эндпоинт `/config`, чтобы подтвердить активное значение тайм-аута:

```bash
curl http://localhost:9090/config | grep request_timeout
```

**Исправление:** Увеличьте тайм-аут или выясните, какая операция PHP работает медленно. Для заведомо длительных операций увеличьте лимит:

```bash
REQUEST_TIMEOUT_SECONDS=300
```

Для SSE- или стриминговых эндпоинтов, где соединения должны оставаться открытыми неограниченно долго, отключите тайм-аут:

```bash
REQUEST_TIMEOUT_SECONDS=0
```

### Соединения разрываются до получения заголовков

Тайм-аут заголовков слишком короткий для клиентов с высокой задержкой или за медленными балансировщиками нагрузки.

**Исправление:** Увеличьте тайм-аут заголовков:

```bash
HEADER_TIMEOUT_SECONDS=15
```

### OPcache вызывает тайм-аут первого запроса после изменения скрипта

Перекомпиляция OPcache увеличивает задержку при первом запросе после изменения файла. Это чаще встречается в среде разработки с большим количеством файлов. Увеличьте тайм-аут или отключите его в процессе разработки.

## Пример Docker

```yaml
services:
  app:
    image: ghcr.io/oxphp/oxphp:0.5.0
    ports:
      - "8080:8080"
    environment:
      HEADER_TIMEOUT_SECONDS: "5"
      REQUEST_TIMEOUT_SECONDS: "30"
    volumes:
      - ./app:/var/www/html:ro
```

## Лучшие практики

- **Никогда не отключайте тайм-аут запроса в продакшене**, если у вас нет SSE- или long-polling-эндпоинтов, требующих бессрочных соединений. Отсутствие тайм-аута позволяет зависшим PHP-скриптам бесконечно занимать воркеры.
- **Используйте короткие тайм-ауты для API-серверов.** API имеют предсказуемое время отклика. Тайм-аут запроса в 30 секунд быстро обнаруживает зависшие запросы, не влияя на обычный трафик.
- **Сочетайте с ограничением частоты запросов.** Тайм-ауты защищают отдельные запросы; ограничение частоты защищает от высокого объёма запросов. Вместе они обеспечивают комплексную защиту от медленных и быстрых атак.
