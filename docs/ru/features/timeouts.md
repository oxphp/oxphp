---
title: Тайм-ауты
description: Настраиваемые тайм-ауты соединений и запросов
---

OxPHP применяет настраиваемые тайм-ауты для защиты от медленных клиентов и зависших запросов. Каждый тайм-аут настраивается через переменную окружения.

## Настройка

| Переменная | Описание | По умолчанию |
|------------|----------|--------------|
| `HEADER_TIMEOUT_SECONDS` | Максимальное время ожидания HTTP-заголовков после TCP-подключения | `5` |
| `IDLE_TIMEOUT_SECONDS` | Максимальное время простоя между запросами на keep-alive соединении | `60` |
| `REQUEST_TIMEOUT_SECONDS` | Максимальное общее время обработки запроса (включая выполнение PHP) | `120` |

```bash
HEADER_TIMEOUT_SECONDS=5
IDLE_TIMEOUT_SECONDS=60
REQUEST_TIMEOUT_SECONDS=120
```

При установке `HEADER_TIMEOUT_SECONDS=0` тайм-аут чтения заголовков не регистрируется в hyper. При установке `REQUEST_TIMEOUT_SECONDS=0` тайм-аут запроса полностью отключается.

## Типы тайм-аутов

### Тайм-аут чтения заголовков

Определяет, как долго сервер ожидает от клиента отправки полного набора HTTP-заголовков после установки TCP-соединения (или после завершения TLS-рукопожатия).

Это защищает от атак типа slowloris, при которых клиент отправляет заголовки по одному байту, удерживая соединение открытым на неопределённое время.

**Примечание к реализации**: hyper-util требует регистрации таймера через `builder.http1().timer(TokioTimer::new())` перед установкой `header_read_timeout`. OxPHP всегда регистрирует этот таймер. Если тайм-аут установлен в ноль, вызов `header_read_timeout` пропускается.

### Тайм-аут простоя

Зарезервирован для контроля времени простоя keep-alive соединения между запросами. Переменная `IDLE_TIMEOUT_SECONDS` считывается из окружения и включена в внутренний эндпоинт `/config`, но HTTP/1.1 builder hyper-util не предоставляет настройку `keep_alive_timeout`. В настоящее время этот тайм-аут не применяется на уровне соединения.

### Тайм-аут запроса

Определяет максимальное общее время обработки одного запроса — от определения маршрута через выполнение PHP, формирование ответа и сжатие. Реализован как обёртка `tokio::time::timeout` вокруг конвейера диспетчеризации. Применяется как к обычному выполнению скриптов, так и к запросам в режиме обработчика.

При срабатывании тайм-аута сервер возвращает ответ `504 Gateway Timeout` с записью в журнал на уровне warn, включающей идентификатор запроса и путь.

Для PHP-запросов тайм-аут запроса является внешней границей. Собственный `max_execution_time` PHP может сработать раньше, но тайм-аут запроса гарантирует освобождение серверных ресурсов, даже если PHP не соблюдает собственное ограничение по времени.

## Взаимодействие тайм-аутов

Тайм-аут чтения заголовков и тайм-аут запроса охватывают разные фазы запроса:

```
TCP-подключение (+ TLS-рукопожатие, если включено)
  |
  +-- [HEADER_TIMEOUT_SECONDS] --> заголовки получены
  |                               |
  |                               +-- [REQUEST_TIMEOUT_SECONDS] --> ответ отправлен
  |                                                                |
  |                                                                +-- следующий запрос или закрытие
  |                                                                     |
  |                                                                     +-- [HEADER_TIMEOUT_SECONDS] --> ...
```

На keep-alive соединении тайм-аут заголовков и тайм-аут запроса применяются к каждому запросу индивидуально.

## Рекомендуемые значения

| Сценарий | Заголовки | Запрос |
|----------|-----------|--------|
| Общий веб-сервер | 5 сек | 120 сек |
| API-сервер | 3 сек | 30 сек |
| Долгие PHP-задачи | 5 сек | 300 сек |
| Высокая безопасность / защита от slowloris | 2 сек | 30 сек |

Подберите значения исходя из характеристик вашего приложения. Если ваши PHP-скрипты выполняют длительные операции (генерация отчётов, импорт данных), увеличьте тайм-аут запроса соответственно.
