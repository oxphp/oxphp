# Server-Sent Events (SSE)

OxPHP передаёт данные в реальном времени клиентам по протоколу Server-Sent Events со встроенной поддержкой противодавления. Установите `Content-Type: text/event-stream` в своём PHP-скрипте и вызовите `oxphp_stream_flush()` — OxPHP возьмёт на себя всё остальное.

## Как это работает

1. PHP-скрипт устанавливает `Content-Type: text/event-stream` через `header()` и записывает строки в формате SSE с помощью `echo`.
2. Первый вызов `oxphp_stream_flush()` отправляет HTTP-заголовки клиенту и переходит в режим стриминга. Клиентское соединение остаётся открытым.
3. Каждый последующий вызов `oxphp_stream_flush()` отправляет буферизированный вывод в виде нового чанка, немедленно доставляя его клиенту.
4. OxPHP поддерживает внутренний буфер до 64 чанков между PHP-воркером и клиентом. Когда буфер заполнен — потому что медленный клиент не успел обработать предыдущие чанки — `oxphp_stream_flush()` блокируется до появления свободного места. Это предотвращает неограниченный рост потребления памяти.
5. Когда PHP-скрипт завершается, OxPHP корректно закрывает соединение. Если клиент отключается в процессе стриминга, последующие вызовы flush завершаются без ошибки, но чанки отбрасываются.

> **Примечание:** Держите полезную нагрузку событий небольшой для поддержания плавной пропускной способности. Большие полезные нагрузки быстро заполняют буфер из 64 чанков, заставляя PHP блокироваться при каждом flush.

## Примеры PHP

### Базовый SSE-поток

```php
<?php
header('Content-Type: text/event-stream');
header('Cache-Control: no-cache');
header('Connection: keep-alive');

for ($i = 0; $i < 100; $i++) {
    $data = json_encode(['counter' => $i, 'time' => microtime(true)]);
    echo "id: {$i}\n";
    echo "event: tick\n";
    echo "data: {$data}\n\n";
    oxphp_stream_flush();

    sleep(1);

    // Отправляем heartbeat-комментарий каждые 15 секунд, чтобы прокси не закрывали простаивающие соединения
    if ($i % 15 === 0) {
        echo ": heartbeat\n\n";
        oxphp_stream_flush();
    }
}
```

### Проверка состояния стриминга

Используйте `oxphp_is_streaming()` для проверки того, находится ли текущий запрос уже в режиме стриминга. Это полезно в middleware или общих обработчиках запросов:

```php
<?php
if (!oxphp_is_streaming()) {
    header('Content-Type: text/event-stream');
    header('Cache-Control: no-cache');
}

echo "data: {\"status\": \"connected\"}\n\n";
oxphp_stream_flush();
```

### Использование нативного flush()

Нативная функция PHP `flush()` также работает для стриминга, но требует предварительной очистки всех уровней буфера вывода. Предпочитайте `oxphp_stream_flush()` — она автоматически управляет буферами вывода и интегрируется с системой противодавления OxPHP.

```php
<?php
header('Content-Type: text/event-stream');
header('Cache-Control: no-cache');

while (ob_get_level()) {
    ob_end_clean();
}

for ($i = 0; $i < 100; $i++) {
    echo "data: " . json_encode(['counter' => $i]) . "\n\n";
    flush();
    sleep(1);
}
```

### SSE с Worker Mode

SSE работает как в стандартном режиме, так и в worker mode. В worker mode стриминговое соединение занимает воркер на всю продолжительность потока. Воркер обрабатывает следующий запрос только после завершения скрипта.

```php
<?php
require __DIR__ . '/../vendor/autoload.php';

$redis = new Redis();
$redis->pconnect('redis', 6379);

oxphp_worker(function () use ($redis) {
    if (($_SERVER['HTTP_ACCEPT'] ?? '') !== 'text/event-stream') {
        http_response_code(400);
        echo json_encode(['error' => 'SSE only']);
        return;
    }

    header('Content-Type: text/event-stream');
    header('Cache-Control: no-cache');

    while (true) {
        $message = $redis->brPop('events', 25);
        if ($message) {
            echo "data: {$message[1]}\n\n";
        } else {
            // Нет сообщений в течение таймаута — отправляем heartbeat для поддержания соединения
            echo ": heartbeat\n\n";
        }
        oxphp_stream_flush();
    }
});
```

## Устранение неполадок

### Клиент не получает данные до завершения скрипта

PHP-буфер вывода захватывает вывод вместо его стриминга. Это происходит, когда активны OB-уровни и `oxphp_stream_flush()` не вызывается.

**Исправление:** Вызывайте `oxphp_stream_flush()` после каждого события. Эта функция очищает все уровни буфера вывода PHP и отправляет накопленный вывод в виде чанка.

### SSE-соединения закрываются через несколько минут

Тайм-аут запроса завершает соединение. SSE-потоки должны работать дольше, чем `REQUEST_TIMEOUT_SECONDS`.

**Исправление:** Отключите тайм-аут запроса для SSE-эндпоинтов:

```bash
REQUEST_TIMEOUT_SECONDS=0
```

Если у вас смесь SSE- и обычных эндпоинтов, установите тайм-аут достаточно высоким для вашего самого длинного потока или запустите SSE на отдельном экземпляре OxPHP с отключённым тайм-аутом.

### Промежуточные прокси закрывают простаивающие SSE-соединения

Балансировщики нагрузки и прокси часто закрывают соединения, не передающие данные в течение 30–60 секунд.

**Исправление:** Отправляйте heartbeat-комментарий с регулярными интервалами для поддержания соединения:

```php
echo ": heartbeat\n\n";
oxphp_stream_flush();
```

### `oxphp_stream_flush()` возвращает `false`

Ранее в том же запросе был вызван `oxphp_finish_request()`. После завершения ответа стриминг невозможен. Проверьте код на случайные вызовы `oxphp_finish_request()` до начала стриминга.

## Пример Docker

SSE-эндпоинты требуют отключения тайм-аута запроса или его высокого значения. Каждое активное SSE-соединение занимает один PHP-воркер на всю продолжительность потока, поэтому настройте пул воркеров под ожидаемое количество одновременных потоков.

```yaml
services:
  app:
    image: ghcr.io/oxphp/oxphp:0.5.0
    ports:
      - "8080:8080"
    volumes:
      - ./src:/var/www/html
    environment:
      DOCUMENT_ROOT: "/var/www/html/public"
      ENTRY_FILE: "index.php"
      REQUEST_TIMEOUT_SECONDS: "0"
      PHP_WORKERS: "32"
```

> **Примечание:** `REQUEST_TIMEOUT_SECONDS=0` отключает тайм-аут для всех запросов на этом экземпляре, включая не-SSE эндпоинты. Если это нежелательно, выделите отдельный экземпляр OxPHP для SSE.

## Лучшие практики

- **Используйте `oxphp_stream_flush()` вместо нативного `flush()`** для автоматического управления буферами вывода и интеграции с системой противодавления.
- **Отправляйте периодические heartbeat-комментарии** (`: heartbeat\n\n`) каждые 20–30 секунд, чтобы промежуточные прокси не закрывали простаивающие соединения и для раннего обнаружения отключений клиентов.
- **Держите полезную нагрузку событий небольшой.** Большие полезные нагрузки быстрее заполняют буфер из 64 чанков, вызывая остановку PHP при каждом flush. Для больших данных отправляйте идентификатор события и пусть клиент получает полную полезную нагрузку через отдельный запрос.
- **Отключайте тайм-аут запроса** (`REQUEST_TIMEOUT_SECONDS=0`) для долгоживущих SSE-эндпоинтов или устанавливайте его достаточно высоким для покрытия ожидаемой максимальной продолжительности потока.
- **Настраивайте пул воркеров под пиковое количество одновременных потоков.** Каждое активное SSE-соединение удерживает один PHP-воркер на всю свою продолжительность. Планируйте как минимум один воркер на ожидаемый одновременный клиент плюс дополнительные воркеры для обычных не-SSE запросов.

## Примечания

- Brotli-компрессия автоматически пропускается для стриминговых ответов. Компрессия применяется только к полностью буферизированным ответам.
- `oxphp_stream_flush()` возвращает `false`, если в том же запросе уже был вызван `oxphp_finish_request()`.
- В worker mode воркер остаётся занятым на всю продолжительность потока и обрабатывает следующий запрос только после выхода PHP-скрипта.
