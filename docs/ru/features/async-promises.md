# Асинхронные промисы

OxPHP предоставляет систему асинхронного выполнения, запускающую PHP-замыкания на выделенном пуле потоков, отдельном от пула HTTP-воркеров. Это предотвращает блокировку обработки запросов длительными фоновыми задачами.

## Как это работает

1. **Отправка** — вызовите `oxphp_async()` с замыканием и необязательными аргументами. OxPHP сериализует `use`-переменные и аргументы замыкания, отправляет их в асинхронный пул и немедленно возвращает идентификатор промиса
2. **Выполнение** — выделенный поток асинхронного воркера десериализует данные, выполняет замыкание и сериализует результат
3. **Ожидание** — вызовите `oxphp_async_await()` с идентификатором промиса. В worker mode с fiber текущий fiber приостанавливается, и другие запросы продолжают выполняться в том же потоке. В традиционном режиме поток воркера блокируется до получения результата
4. **Очистка** — все промисы, которые явно не были ожидаемы, автоматически отменяются и очищаются в конце запроса

## Конфигурация

| Переменная | По умолчанию | Описание |
|------------|-------------|----------|
| `ASYNC_WORKERS` | `0` (отключено) | Количество выделенных потоков асинхронных воркеров. Установите `0` для полного отключения асинхронного пула |
| `ASYNC_QUEUE_CAPACITY` | `0` (авто) | Максимальное количество ожидающих асинхронных задач. При `0` по умолчанию равно `ASYNC_WORKERS × 64` |

> **Примечание:** Асинхронный пул отключён по умолчанию (`ASYNC_WORKERS=0`). При отключённом пуле все четыре async-функции зарегистрированы, но при вызове выбрасывают `OxPHP\Async\Exception`. Установите `ASYNC_WORKERS` в значение больше `0` для включения фонового выполнения.

## Отправка задач

Передайте замыкание и необязательные аргументы в `oxphp_async()`. Функция немедленно возвращает идентификатор промиса (целое число):

```php
<?php
$promise = oxphp_async(function (string $url) {
    return file_get_contents($url);
}, 'https://api.example.com/data');

// Замыкание выполняется в фоне.
// Здесь можно делать другую работу...

$result = oxphp_async_await($promise);
echo $result;
```

### Передача данных в замыкания

Используйте `use`-переменные или аргументы функции для передачи данных. Поддерживаются только скалярные типы и массивы:

```php
<?php
$apiKey = 'sk-abc123';
$ids = [1, 2, 3];

$promise = oxphp_async(function () use ($apiKey, $ids) {
    // $apiKey и $ids доступны здесь
    return count($ids);
});
```

## Ожидание результатов

### Один промис

```php
<?php
$result = oxphp_async_await($promise);           // Ждать бесконечно
$result = oxphp_async_await($promise, 5.0);      // Ждать до 5 секунд
```

Тайм-аут `0.0` (значение по умолчанию) ждёт бесконечно. При тайм-ауте выбрасывается исключение `OxPHP\Async\TimeoutException`.

### Все промисы

`oxphp_async_await_all()` ожидает каждый промис и возвращает ассоциативный массив с ключами по идентификаторам промисов:

```php
<?php
$p1 = oxphp_async(fn() => file_get_contents('https://api.example.com/users'));
$p2 = oxphp_async(fn() => file_get_contents('https://api.example.com/orders'));

$results = oxphp_async_await_all([$p1, $p2], 10.0);

$users  = $results[$p1];
$orders = $results[$p2];
```

> **Примечание:** `oxphp_async_await_all()` ожидает промисы последовательно в порядке массива. Все замыкания выполняются параллельно в асинхронном пуле, но вызывающий поток собирает результаты по одному.

### Первый промис (гонка)

`oxphp_async_await_any()` возвращает результат, как только один из промисов завершается:

```php
<?php
$p1 = oxphp_async(fn() => fetch_from_primary_db());
$p2 = oxphp_async(fn() => fetch_from_replica_db());

$winner = oxphp_async_await_any([$p1, $p2], 5.0);
// $winner = ['id' => int, 'value' => mixed]

echo "Promise {$winner['id']} won: {$winner['value']}";
```

Проигравшие промисы остаются доступными для индивидуального ожидания после возврата `oxphp_async_await_any()`.

## Обработка ошибок

Исключения, выброшенные внутри асинхронного замыкания, перехватываются и повторно выбрасываются при ожидании как `OxPHP\Async\Exception`:

```php
<?php
$promise = oxphp_async(function () {
    throw new \RuntimeException('Something failed');
});

try {
    $result = oxphp_async_await($promise);
} catch (\OxPHP\Async\Exception $e) {
    // "Async task failed: [RuntimeException] Something failed"
    echo $e->getMessage();
}
```

Вызовы `exit()` и `die()` внутри асинхронного замыкания также перехватываются и преобразуются в `OxPHP\Async\Exception`. Асинхронный воркер продолжает работу и обрабатывает новые задачи.

### Иерархия исключений

```text
\Exception
  └── OxPHP\Async\Exception              # Все асинхронные ошибки
        └── OxPHP\Async\TimeoutException  # Специфично для тайм-аутов
```

## Интеграция с Fiber

В worker mode `oxphp_async_await()` взаимодействует с планировщиком fiber OxPHP. Вместо блокировки потока воркера текущий fiber приостанавливается в ожидании результата. Планировщик возобновляет его, когда результат готов, позволяя обрабатывать другие запросы в том же потоке.

В традиционном режиме (без файла воркера) `oxphp_async_await()` синхронно блокирует поток воркера. Это означает, что воркер не может обрабатывать другие запросы во время ожидания.

Для наилучшей производительности сочетайте асинхронные промисы с worker mode:

```php
<?php
// worker.php
require __DIR__ . '/../vendor/autoload.php';

oxphp_worker(function () {
    // Эти два API-вызова выполняются параллельно в асинхронном пуле,
    // пока fiber приостановлен — поток воркера свободен для других запросов
    $p1 = oxphp_async(fn() => file_get_contents('https://api.example.com/users'));
    $p2 = oxphp_async(fn() => file_get_contents('https://api.example.com/orders'));

    $results = oxphp_async_await_all([$p1, $p2]);
    echo json_encode($results);
});
```

## Ограничения

Асинхронные замыкания выполняются в отдельных потоках. Это накладывает ограничения на данные, которые могут пересекать границу потока:

| Разрешено | Не разрешено |
|-----------|--------------|
| `null`, `bool`, `int`, `float`, `string` | Объекты (любые экземпляры классов) |
| Массивы скалярных типов | Ресурсы (файловые дескрипторы, DB-соединения, потоки) |
| Вложенные скалярные массивы | Замыкания, ссылающиеся на объекты в `use` |

Дополнительные ограничения:

- **Нет вложенных async** — вызов `oxphp_async()` внутри асинхронного замыкания выбрасывает `OxPHP\Async\Exception`
- **Только пользовательские функции** — замыкание должно быть определено пользователем, а не быть обёрткой над встроенной функцией
- **Накладные расходы на сериализацию** — аргументы и возвращаемые значения сериализуются через границу потока. Большие массивы или строки увеличивают задержку
- **Нет общего состояния** — каждый асинхронный воркер имеет собственную PHP-среду. Общих переменных между отправляющим потоком и асинхронным потоком нет

```yaml
services:
  app:
    image: ghcr.io/oxphp/oxphp:0.2.0
    ports:
      - "80:80"
    environment:
      - DOCUMENT_ROOT=/var/www/html/public
      - WORKER_FILE=worker.php
      - ASYNC_WORKERS=4
      - ASYNC_QUEUE_CAPACITY=256
```

## Устранение неполадок

### "Async pool is disabled. Set ASYNC_WORKERS > 0 to enable."

Асинхронный пул отключён (`ASYNC_WORKERS=0`). Функции `oxphp_async()` и связанные с ней функции зарегистрированы, но немедленно выбрасывают `OxPHP\Async\Exception`.

**Исправление:** Установите `ASYNC_WORKERS` в нужное количество фоновых потоков:

```bash
ASYNC_WORKERS=4
```

### "Failed to dispatch async task (pool full)"

Асинхронный пул настроен, но очередь задач заполнена.

**Проверьте:** Убедитесь, что `ASYNC_WORKERS` установлен в значение больше `0`:

```bash
curl -s http://localhost:9090/config | jq '.async_workers'
```

**Исправление:** Увеличьте `ASYNC_QUEUE_CAPACITY` или добавьте больше воркеров:

```bash
ASYNC_WORKERS=8
ASYNC_QUEUE_CAPACITY=512
```

### "Cannot pass object values in use-vars to async closure"

Объекты не могут быть сериализованы через границы потоков.

**Исправление:** Извлеките необходимые скалярные данные перед отправкой:

```php
<?php
// Неверно: передача объекта
$promise = oxphp_async(function () use ($user) { ... });

// Верно: передача скалярных данных, извлечённых из объекта
$userId = $user->getId();
$userName = $user->getName();
$promise = oxphp_async(function () use ($userId, $userName) { ... });
```

### Await зависает в традиционном режиме

В традиционном режиме (без `WORKER_FILE`) `oxphp_async_await()` блокирует поток воркера. Если все PHP-воркеры заблокированы в ожидании асинхронных результатов, сервер перестаёт обрабатывать запросы.

**Исправление:** Используйте worker mode (`WORKER_FILE`), чтобы `oxphp_async_await()` приостанавливал fiber вместо блокировки потока.

### Тайм-аут async не завершает выполняемую задачу

`OxPHP\Async\TimeoutException` выбрасывается на стороне ожидания — замыкание продолжает выполняться в асинхронном пуле до своего завершения или до окончания запроса. Задачи отменяются в конце запроса во время очистки.

## Лучшие практики

- **Всегда устанавливайте тайм-ауты** для вызовов `oxphp_async_await()` в продакшене, чтобы избежать бесконечного ожидания
- **Используйте worker mode** для получения неблокирующего ожидания на основе fiber вместо блокировки потока воркера
- **Держите замыкания небольшими** — отправляйте сфокусированные единицы работы, а не целые обработчики запросов
- **Извлекайте скаляры перед отправкой** — вытаскивайте идентификаторы, строки и значения конфигурации из объектов перед передачей в замыкание
- **Следите за асинхронным пулом** — проверяйте метрику `oxphp_async_tasks_rejected_total` в Prometheus. Если количество отказов растёт, увеличьте `ASYNC_WORKERS` или `ASYNC_QUEUE_CAPACITY`
