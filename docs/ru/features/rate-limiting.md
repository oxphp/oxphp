---
title: Ограничение частоты запросов
description: Ограничение частоты запросов по IP с настраиваемыми лимитами и временными окнами
---

OxPHP включает встроенный ограничитель частоты запросов по IP, который отклоняет избыточные запросы ответом 429. Ограничение частоты запросов отключено по умолчанию и активируется при установке переменной `RATE_LIMIT` в ненулевое значение.

## Конфигурация

| Переменная | Описание | По умолчанию |
|------------|----------|-------------|
| `RATE_LIMIT` | Максимальное количество запросов на IP за окно | `0` (отключено) |
| `RATE_WINDOW_SECONDS` | Длительность окна в секундах | `60` |

```bash
# Разрешить 100 запросов на IP за 60-секундное окно
RATE_LIMIT=100
RATE_WINDOW_SECONDS=60
```

Установка `RATE_LIMIT=0` полностью отключает ограничение частоты запросов. При отключении обработчик ограничения частоты не регистрируется в диспетчере событий и не создаёт никаких накладных расходов.

## Как это работает

Ограничитель частоты запросов использует `DashMap` (шардированную конкурентную хеш-таблицу), ключом которой является IP-адрес клиента. Каждая запись хранит счётчик запросов и метку времени начала текущего окна.

### Обработка запроса

1. Поиск IP-адреса клиента в таблице (или вставка новой записи)
2. Если окно истекло, сброс счётчика в ноль и начало нового окна
3. Инкремент счётчика
4. Если счётчик превышает `RATE_LIMIT`, возврат ответа 429

### Ответ 429

Когда запрос отклоняется ограничителем частоты, сервер возвращает:

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 45
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 45
X-Request-ID: 67890abc00000042

429 Too Many Requests
```

| Заголовок | Описание |
|-----------|----------|
| `Retry-After` | Секунды до сброса текущего окна |
| `X-RateLimit-Limit` | Максимальное количество запросов, разрешённых за окно |
| `X-RateLimit-Remaining` | Оставшиеся запросы в текущем окне (всегда `0` при срабатывании ограничения) |
| `X-RateLimit-Reset` | Секунды до сброса текущего окна |
| `X-Request-ID` | Идентификатор данного запроса |

## Интеграция с обработчиком событий

Ограничение частоты запросов реализовано как обработчик событий, который слушает события `RequestReceived` с приоритетом **-50**. Это означает, что он выполняется после генератора идентификаторов запросов (приоритет -100), но до обработчиков метрик и других.

Когда ограничитель отклоняет запрос, он устанавливает поле `early_response` в событии. Обработчик соединения проверяет это поле и немедленно возвращает ответ 429, пропуская маршрутизацию и выполнение PHP.

Обработчик всегда возвращает `Propagation::Continue`, чтобы обработчики метрик и логирования доступа по-прежнему обрабатывали запрос. Это означает, что отклонённые запросы отображаются в логах доступа и метриках.

Каждый отклонённый запрос увеличивает счётчик Prometheus `oxphp_rate_limited_total`.

## Очистка

Фоновая задача Tokio выполняется каждые 60 секунд и удаляет записи, чьё окно истекло более чем `2 * RATE_WINDOW_SECONDS` секунд назад. Это предотвращает неограниченный рост `DashMap`, когда клиенты отправляют всплеск запросов и затем исчезают.

## Ограничения

- **Алгоритм фиксированного окна** -- ограничитель использует простой счётчик с фиксированным окном, а не скользящее окно. Клиент может отправить до `2 * RATE_LIMIT` запросов всплеском на границе двух окон.
- **Только по IP** -- ограничение частоты запросов привязано к IP-адресу источника. Клиенты за общим NAT или прокси разделяют один счётчик.
- **Только в памяти** -- состояние ограничителя не разделяется между несколькими экземплярами OxPHP. Каждый экземпляр ведёт собственные счётчики.
