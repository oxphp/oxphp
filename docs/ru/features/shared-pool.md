# Shared\Pool

`OxPHP\Shared\Pool` — это ограниченный пул потокозависимых ресурсов. Это примитив для управления объектами, которые дорого создавать, нельзя дёшево пересоздавать и которые не должны существовать в неограниченных количествах — обычно соединения с БД, кэши prepared-statement'ов, переиспользуемые JSON-декодеры или сессии HTTP-клиентов.

Pool даёт каждому потоку PHP-воркера свою полосу готовых к использованию ресурсов, обеспечивает строгий максимум по всему пулу и автоматически перерабатывает простаивающие слоты, так что вы не платите за ёмкость, которую не используете.

## Обзор

- **Строгий бюджет.** `maxSize` — это жёсткий cap на весь пул. Захваты сверх cap'а блокируются, пока слот не освободится или не истечёт таймаут.
- **Per-thread аффинность.** У каждого потока воркера своя idle-очередь. Захват тянет сначала из локальной очереди и никогда не передаёт слот, отчеканенный на потоке A, на поток B (v1).
- **Фабрика выполняется на захватывающем воркере.** Ресурсы чеканятся лениво при первом запросе на потоке, а не при конструировании пула.
- **Callback destroy при вытеснении.** Опциональное замыкание `destroy($resource)` выполняется, когда пул сбрасывает слот (idle timeout, вытеснение пула, остановка сервера).
- **Вытеснение по idle-timeout.** Слоты, простаивающие дольше `idleTimeout`, уничтожаются фоновой задачей, тикающей каждые 500 мс.
- **Shareable.** Пулы переживают границы запросов и разделяются по хэндлу (`use ($pool)` в замыканиях).

## Справочник API

```php
namespace OxPHP\Shared;

final class Pool implements Shareable
{
    public function __construct(
        callable  $factory,
        ?callable $destroy = null,
        int       $maxSize = 32,
        float     $idleTimeout = 300.0,
        ?float    $defaultAcquireTimeout = 5.0,
    );

    public function acquire(float $timeout = 0.0): Pool\Handle;
    public function release(Pool\Handle $handle): void;
    public function with(callable $body, float $timeout = 0.0): mixed;

    public function size(): int;
    public function inUse(): int;
    public function idle(): int;
    public function waiting(): int;
    public function maxSize(): int;

    public function evict(): int;
    public function id(): int;
}

namespace OxPHP\Shared\Pool;

final class Handle
{
    public function get(): mixed;     // нижележащий ресурс
}
```

| Метод          | Возвращает | Применение                                                      |
|----------------|----------|-------------------------------------------------------------------|
| `acquire`      | `Handle` | Взять ресурс; блокирует до `$timeout`. `0.0` использует default. |
| `release`      | void     | Вернуть хэндл в пул. Идемпотентно в пределах жизни хэндла; двойной release отклоняется. |
| `with`         | mixed    | Захват + release в скоупе вокруг замыкания. Возвращаемое значение замыкания пробрасывается. Предпочтительнее ручного `acquire`/`release`. |
| `size`         | int      | Текущее число слотов (in-use + idle) по всем потокам.            |
| `inUse`        | int      | Слоты, выданные сейчас.                                           |
| `idle`         | int      | Слоты, лежащие в per-thread очередях.                             |
| `waiting`      | int      | Захваты, припаркованные в ожидании свободного слота.              |
| `maxSize`      | int      | Настроенный жёсткий cap.                                          |
| `evict`        | int      | Принудительно запустить sweeper вытеснения сейчас; возвращает число сброшенных. |
| `id`           | int      | Идентификатор реестра; полезен для логов / наблюдаемости.         |

## Примеры

### Пул соединений с БД

```php
<?php
$db = new OxPHP\Shared\Pool(
    factory: function () {
        return new PDO(
            getenv('DB_DSN'),
            getenv('DB_USER'),
            getenv('DB_PASS'),
            [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION],
        );
    },
    destroy: function (PDO $conn) {
        // Делать нечего — PDO закрывается на destruct. Callback существует
        // для ресурсов, которым нужен явный teardown (сокеты, хэндлы).
    },
    maxSize: 16,
    idleTimeout: 60.0,        // освобождать idle-соединения через 1 мин
);

// В обработчике запроса
$users = $db->with(function (PDO $conn) use ($userId) {
    $stmt = $conn->prepare('SELECT * FROM users WHERE id = ?');
    $stmt->execute([$userId]);
    return $stmt->fetch();
});
```

`with()` — паттерн с самой короткой жизнью: захват происходит на входе, release — на выходе *или* на исключении — вы не можете утечь хэндл.

### Ручной acquire / release

```php
<?php
$h = $pool->acquire(timeout: 2.0);

try {
    $conn = $h->get();
    $conn->beginTransaction();
    doWork($conn);
    $conn->commit();
} finally {
    $pool->release($h);
}
```

Берите ручной acquire только когда скоуп пересекает границу, которую `with()` не может выразить (например, ресурс должен пережить несколько вызовов в последовательности обработчиков).

### Пул переиспользуемых парсеров

```php
<?php
$parsers = new OxPHP\Shared\Pool(
    factory: fn () => new JsonMachine\Parser(),
    maxSize: 8,
);

$doc = $parsers->with(fn ($p) => $p->parse($body));
```

### Короткий acquire-таймаут + fallback

```php
<?php
try {
    $h = $pool->acquire(timeout: 0.1);    // 100 мс
} catch (OxPHP\Shared\TimeoutException $e) {
    // Пул насыщен — деградируем красиво
    http_response_code(503);
    header('Retry-After: 1');
    return;
}

try {
    // ...
} finally {
    $pool->release($h);
}
```

## Семантика factory и destroy

Фабрика выполняется **лениво** на захватывающем потоке воркера. Пул с `maxSize: 32` не предвыделяет 32 ресурса; он чеканит их по мере поступления спроса, в пределах `maxSize` по всем потокам вместе.

- От фабрики ожидается возврат не-null значения. Возврат `null` или throw всплывает как исключение из `acquire()`, и слот не учитывается в бюджете.
- Callback destroy (если задан) выполняется, когда пул сбрасывает слот: истечение idle-timeout, явный `evict()`, shutdown сервера или вытеснение пула. Он выполняется на потоке воркера (а не на потоке Tokio, ведущем sweeper вытеснения), так что PHP безопасно вызывать.
- Callback destroy, который бросает, логируется, но не отравляет пул — слот уже уничтожается, так что откатывать нечего.

## Per-thread аффинность

Пулы v1 строго per-thread: слот, отчеканенный на потоке воркера A, не может быть захвачен на потоке воркера B. Практически это означает, что `idle()` может быть ненулевым на воркере A, пока воркер B блокирован в `acquire()`. Это держит слоты горячими в потоке, который их использует (соединения с БД, объекты, прогретые OPcache), и избегает перетасовки ресурсов между ядрами.

Межпоточный work stealing — кандидат на v1.x. До тех пор размеряйте `maxSize` против числа потоков воркеров × ожидаемая per-thread конкурентность, а не просто против совокупного спроса.

## Вытеснение по idle-timeout

Idle-слоты вытесняются фоновым планировщиком, тикающим каждые 500 мс. Когда слот простаивал дольше `idleTimeout`, планировщик помечает его; владелец-воркер уничтожает его при следующем входе в `execute_request` (с живым PHP-движком, так что `$destroy` выполняется в нормальном request-контексте). Бюджет освобождается в той же точке.

Настраивайте `idleTimeout` под стоимость пересоздания:

- **Дёшево пересоздать** (JSON-декодер, string pool): ставьте 10–60 с; быстро освобождает память при спаде трафика.
- **Дорого пересоздать** (соединение с БД, TLS-сессия): ставьте 300 с (по умолчанию) — 900 с; реже платите за пересоздание.
- **Никогда не вытеснять**: передайте очень большое число. Не рекомендуется; одинокий горячий слот, который потом неопределённо долго не используется, — это память, которую вы никогда не вернёте.

`$pool->evict()` принудительно запускает sweep сейчас и возвращает, сколько слотов было сброшено. Полезно в тестах и в админских эндпоинтах, сбрасывающих нагрузку по требованию.

## Бюджет и acquire-таймаут

`acquire(timeout)` ведёт себя так:

| Состояние на момент вызова                  | Результат                                     |
|---------------------------------------------|----------------------------------------------|
| Idle-слот в локальной очереди потока        | Переиспользован сразу, фабрика не вызвана.   |
| Нет idle-слотов, но `size() < maxSize`      | Фабрика выполняется, чеканится новый слот.   |
| `size() == maxSize` и все слоты `inUse`     | Блокирует до `timeout`, затем `TimeoutException`. |

Передача `0.0` в `timeout` использует `$defaultAcquireTimeout` (по умолчанию 5 с). Чтобы ждать бесконечно, передайте очень большое число — намеренно нет «infinite»-сентинела, поскольку пул, дедлокающийся в вечном ожидании, диагностировать сложнее, чем тот, который таймаутится и бросает.

## Исключения

| Исключение               | Бросается                                                            |
|--------------------------|----------------------------------------------------------------------|
| `TimeoutException`       | `acquire` превысил `$timeout` без свободного слота.                  |
| `CapacityException`      | Создание нарушило бы `maxSize`, несмотря на согласование бюджета (редко). |
| `TypeException`          | Неположительный `maxSize`, возврат фабрики не PHP-объект и т. д.     |
| `StaleHandleException`   | Вызов метода на хэндле, чья запись реестра была вытеснена, или на `Pool\Handle`, который уже отпущен. |
| `UninitializedException` | `id()` на обёртке пула, которая не завершила `__construct`.           |

Исключения, брошенные внутри фабрики, распространяются вызывающему `acquire()` без изменений и не потребляют бюджет. Исключения внутри тела `with()` распространяются вызывающему после release хэндла.

## Наблюдаемость

Полную экскурсию см. в [Shared Observability](../operations/shared-observability.md). Краткие отсылки:

- `GET /__ox_shared/entry?id=N` показывает `{ type: "Pool", size, in_use, idle, waiting, max_size, idle_timeout_ms }`.
- `GET /__ox_shared/summary` считает экземпляры Pool и агрегированные `waiting_total`, `evicted_total`.
- Prometheus-метрики per pool:
  - `oxphp_shared_pool_size{pool_id="…"}`            — gauge, всего слотов.
  - `oxphp_shared_pool_in_use{pool_id="…"}`          — gauge.
  - `oxphp_shared_pool_idle{pool_id="…"}`            — gauge.
  - `oxphp_shared_pool_waiting{pool_id="…"}`         — gauge, захваты в очереди.
  - `oxphp_shared_pool_acquires_total{pool_id="…"}`  — counter.
  - `oxphp_shared_pool_evicted_total{pool_id="…",reason="idle_timeout|manual|shutdown"}` — counter.
  - `oxphp_shared_pool_factory_errors_total{pool_id="…"}` — counter исключений фабрики.
  - `oxphp_shared_pool_acquire_timeouts_total{pool_id="…"}` — counter таймаутов acquire.

Сочетания, заслуживающие алерта: рост `waiting` при плоском `size` означает, что пул насыщен и должен быть пересмотрен; рост `acquire_timeouts_total` при нормальном `in_use` означает, что фабрика медленная (или блокирует).

## Когда не использовать

- **Дешёвые или иммутабельные ресурсы.** Накладные расходы пула больше, чем пересоздание простого объекта. Используйте его для ресурсов, где создание стоит миллисекунды или килобайты.
- **Объекты, которые нельзя безопасно переиспользовать.** Если ресурс накапливает per-request состояние (открытые транзакции, ожидающие чтения) и вы не можете надёжно его сбросить, пуллинг утекает состояние между запросами. Возвращайте слоты в известное состояние в коде завершения запроса или не пуллите.
- **Межхостовые ресурсы.** Pool — внутри процесса. Для межхостового пуллинга соединений предпочитайте connection-bucket сервис или sidecar (pgbouncer, proxy-sql).
- **Неограниченный fan-out.** Если вам нужно одно соединение на каждый in-flight HTTP-вызов, это не пул — это N-на-запрос проблема. Используйте `Shared\Channel` для сериализации работы за ограниченным пулом.
- **Ресурсы со своей собственной семантикой пуллинга.** Многие клиентские библиотеки уже пуллят внутри (например, connection pool у Guzzle). Класть `Shared\Pool` поверх — двойная бухгалтерия; предпочитайте собственный пуллинг библиотеки.
