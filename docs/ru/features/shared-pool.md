# Shared\Pool

`OxPHP\Shared\Pool` — это ограниченный пул потокозависимых ресурсов. Это примитив для управления объектами, которые дорого создавать, нельзя дёшево пересоздавать и которые не должны существовать в неограниченных количествах — обычно соединения с БД, кэши prepared-statement'ов, переиспользуемые JSON-декодеры или сессии HTTP-клиентов.

Pool даёт каждому потоку PHP-воркера свою полосу готовых к использованию ресурсов, обеспечивает строгий максимум по всему пулу и автоматически перерабатывает простаивающие слоты, так что вы не платите за ёмкость, которую не используете.

## Обзор

- **Строгий бюджет.** `maxSize` — это жёсткий cap на весь пул. Когда пул насыщен, захват либо ждёт, либо возвращает `null`, либо бросает исключение — в зависимости от того, какой метод захвата вы вызвали.
- **Per-thread аффинность.** У каждого потока воркера своя idle-очередь. Захват тянет сначала из локальной очереди и никогда не передаёт слот, отчеканенный на потоке A, на поток B (v1).
- **Фабрика выполняется на захватывающем воркере.** Ресурсы чеканятся лениво при первом запросе на потоке, а не при конструировании пула.
- **Callback destroy при вытеснении.** Опциональное замыкание `destroy($resource)` выполняется, когда пул сбрасывает слот (idle timeout, ручное вытеснение, остановка сервера).
- **Вытеснение по idle-timeout.** Слоты, простаивающие дольше `idleTimeoutMs`, уничтожаются фоновой задачей. Установите `idleTimeoutMs: 0`, чтобы полностью отключить вытеснение по простою.
- **RAII-хэндлы.** `acquire()` возвращает `Handle`; слот возвращается в пул автоматически, когда хэндл выходит из области видимости (в том числе при исключении), или раньше через `$handle->release()`.
- **Shareable.** Пулы переживают границы запросов и разделяются по хэндлу (`use ($pool)` в замыканиях).

## Справочник API

```php
namespace OxPHP\Shared;

final class Pool implements Shareable
{
    public function __construct(
        callable  $factory,                  // fn(): object — создать ресурс
        ?callable $destroy       = null,     // fn(object): void — разобрать ресурс
        int       $maxSize       = 32,       // жёсткий cap на живые слоты; > 0
        int       $idleTimeoutMs = 300_000,  // мс простоя до вытеснения; 0 отключает
    );

    // семейство acquire — трихотомия таймаутов в миллисекундах
    public function acquire(): Pool\Handle;                 // ждать вечно
    public function tryAcquire(): ?Pool\Handle;             // неблокирующий; null при насыщении
    public function acquireTimeout(int $ms): Pool\Handle;   // ограниченный; $ms > 0

    // семейство with — scope-guard вокруг сырого ресурса
    public function with(callable $body): mixed;                 // ждать вечно
    public function withTimeout(callable $body, int $ms): mixed; // ограниченный; $ms > 0

    public function stats(): Pool\Stats;   // снимок счётчиков на момент вызова
    public function evict(): int;          // принудительно вытеснить все idle-слоты сейчас; возвращает число
    public function id(): int;
}

namespace OxPHP\Shared\Pool;

final class Handle
{
    public function get(): mixed;     // нижележащий ресурс (бросает после release)
    public function release(): void;  // вернуть слот сейчас; идемпотентно; также выполняется на destruct
}

final class Stats
{
    public function inUse(): int;    // слоты, выданные сейчас
    public function idle(): int;     // свободные слоты, готовые к выдаче
    public function waiting(): int;  // вызывающие, заблокированные в acquire
    public function size(): int;     // inUse() + idle() (живые слоты)
    public function maxSize(): int;  // настроенный cap

    public function utilization(): float;  // inUse() / maxSize(), 0.0 если maxSize() == 0
}
```

| Метод             | Возвращает    | Применение                                                             |
|-------------------|---------------|------------------------------------------------------------------------|
| `acquire`         | `Handle`      | Взять ресурс, ожидая свободного слота вечно.                            |
| `tryAcquire`      | `?Handle`     | Неблокирующее взятие. Сразу возвращает `null`, если пул насыщен.        |
| `acquireTimeout`  | `Handle`      | Взять в пределах ограниченного бюджета `$ms` (`> 0`); по истечении бросает `OperationTimeoutException`. |
| `with`            | mixed         | Scope-guard: захват (вечно), выполнение `$body($resource)` с сырым ресурсом, release даже при исключении. Возвращаемое значение замыкания пробрасывается. |
| `withTimeout`     | mixed         | Как `with`, но захват ограничен `$ms`.                                  |
| `stats`           | `Pool\Stats`  | Снимок счётчиков пула на момент вызова.                                 |
| `evict`           | int           | Принудительно вытеснить все idle-слоты сейчас (независимо от `idleTimeoutMs`); возвращает число сброшенных. |
| `id`              | int           | Идентификатор реестра; полезен для логов / наблюдаемости.               |
| `Handle::get`     | mixed         | Нижележащий ресурс. Бросает `StaleHandleException` после release.       |
| `Handle::release` | void          | Вернуть слот в пул сейчас. Идемпотентно; также выполняется автоматически на destruct (RAII). |

Таймауты следуют той же трихотомии, что и `Shared\Mutex` и `Shared\Channel`: голый метод ждёт вечно, метод `try*` неблокирующий, а метод `*Timeout(int $ms)` ждёт ограниченное число миллисекунд. Таймаута в дробных секундах не существует.

## Примеры

### Пул соединений с БД

```php
<?php
$db = new OxPHP\Shared\Pool(
    factory: function () {
        return new PDO(
            getenv('DB_DSN'),
            getenv('DB_USER'),
            getenv('DB_PASS'),
            [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION],
        );
    },
    destroy: function (PDO $conn) {
        // Делать нечего — PDO закрывается на destruct. Callback существует
        // для ресурсов, которым нужен явный teardown (сокеты, хэндлы).
    },
    maxSize: 16,
    idleTimeoutMs: 60_000,     // освобождать idle-соединения через 1 мин
);

// В обработчике запроса
$users = $db->with(function (PDO $conn) use ($userId) {
    $stmt = $conn->prepare('SELECT * FROM users WHERE id = ?');
    $stmt->execute([$userId]);
    return $stmt->fetch();
});
```

`with()` — паттерн с самой короткой жизнью: захват происходит на входе, release — на выходе *или* при исключении — вы не можете утечь хэндл. Он также передаёт вашему замыканию **сырой ресурс** напрямую, так что вы пропускаете шаг `Handle::get()`.

### Ручной acquire / release

```php
<?php
$h = $pool->acquire();        // ждёт свободного слота вечно

$conn = $h->get();
$conn->beginTransaction();
doWork($conn);
$conn->commit();

$h->release();                // или просто дайте $h выйти из области видимости (RAII)
```

Хэндл возвращает свой слот автоматически при уничтожении — в том числе если исключение раскручивает стек — так что явный `release()` опционален. Берите ручной хэндл (вместо `with()`) только когда ресурс должен пережить несколько вызовов в последовательности обработчиков.

### Пул переиспользуемых парсеров

```php
<?php
$parsers = new OxPHP\Shared\Pool(
    factory: fn () => new JsonMachine\Parser(),
    maxSize: 8,
);

$doc = $parsers->with(fn ($p) => $p->parse($body));
```

### Неблокирующий acquire с fallback

```php
<?php
$h = $pool->tryAcquire();
if ($h === null) {
    // Пул насыщен — деградируем красиво, не ожидая.
    http_response_code(503);
    header('Retry-After: 1');
    return;
}
// ... используйте $h->get(); слот возвращается на выходе из области видимости.
```

### Ограниченный acquire с таймаутом

```php
<?php
try {
    $h = $pool->acquireTimeout(100);   // ждать до 100 мс
} catch (OxPHP\Shared\OperationTimeoutException $e) {
    http_response_code(503);
    header('Retry-After: 1');
    return;
}
// ... используйте $h->get();
```

## Семантика factory и destroy

Фабрика выполняется **лениво** на захватывающем потоке воркера. Пул с `maxSize: 32` не предвыделяет 32 ресурса; он чеканит их по мере поступления спроса, в пределах `maxSize` по всем потокам вместе.

- Фабрика должна вернуть PHP-объект. Возврат не-объекта всплывает как `TypeException` из вызова acquire, и слот не учитывается в бюджете.
- Фабрика, которая бросает, распространяет своё собственное исключение вызывающему acquire без изменений, и слот не учитывается в бюджете.
- Callback destroy (если задан) выполняется, когда пул сбрасывает слот: истечение idle-timeout, явный `evict()` или shutdown сервера. Он выполняется на потоке воркера (а не на потоке Tokio, ведущем планировщик вытеснения), так что PHP безопасно вызывать.
- Callback destroy, который бросает, логируется, но не отравляет пул — слот уже уничтожается, так что откатывать нечего полезного.

## Per-thread аффинность

Пулы v1 строго per-thread: слот, отчеканенный на потоке воркера A, не может быть захвачен на потоке воркера B. Практически это означает, что `stats()->idle()` может быть ненулевым на воркере A, пока воркер B блокирован в `acquire()`. Это держит слоты горячими в потоке, который их использует (соединения с БД, объекты, прогретые OPcache), и избегает перетасовки ресурсов между ядрами.

Межпоточный work stealing — кандидат на v1.x. До тех пор размеряйте `maxSize` против числа потоков воркеров × ожидаемая per-thread конкурентность, а не просто против совокупного спроса.

## Вытеснение по idle-timeout

Idle-слоты вытесняются фоновым планировщиком. Когда слот простаивал дольше `idleTimeoutMs`, планировщик помечает его; владелец-воркер уничтожает его при следующем запросе (с живым PHP-движком, так что `$destroy` выполняется в нормальном request-контексте). Бюджет освобождается в той же точке.

Настраивайте `idleTimeoutMs` под стоимость пересоздания:

- **Дёшево пересоздать** (JSON-декодер, string pool): ставьте 10_000–60_000 мс; быстро освобождает память при спаде трафика.
- **Дорого пересоздать** (соединение с БД, TLS-сессия): ставьте 300_000 мс (по умолчанию) — 900_000 мс; реже платите за пересоздание.
- **Никогда не вытеснять**: передайте `0`. Idle-слоты тогда живут, пока пул не будет сброшен.

`$pool->evict()` принудительно вытесняет **все** idle-слоты, достижимые из вызывающего воркера прямо сейчас — независимо от `idleTimeoutMs` — и возвращает, сколько было сброшено. Это операционный аварийный выход «сбросить idle сейчас» (например, нижележащий сервис перезапустился, и вы хотите, чтобы следующий acquire отчеканил свежие ресурсы). Слоты в использовании не трогаются.

## Бюджет и семантика acquire

Каждый вариант acquire сначала пытается удовлетворить запрос немедленно — переиспользовать idle-слот или (если пул ниже `maxSize`) отчеканить новый через фабрику. Только когда пул **насыщен** — нет idle-слота **и** достигнут `maxSize` — поведение различается:

| Состояние на момент вызова                  | `acquire()`           | `tryAcquire()`     | `acquireTimeout($ms)`                     |
|---------------------------------------------|-----------------------|--------------------|-------------------------------------------|
| Idle-слот в очереди локального потока        | переиспользован сразу | переиспользован сразу | переиспользован сразу                  |
| Нет idle-слотов, но ниже `maxSize`           | фабрика чеканит слот  | фабрика чеканит слот | фабрика чеканит слот                    |
| Насыщен (на `maxSize`, все в использовании)  | ждёт **вечно**        | возвращает `null`  | ждёт до `$ms`, затем `OperationTimeoutException` |

`$ms` должен быть `> 0`; `0` или отрицательное бросает `TypeException`. Намеренно нет формы в дробных секундах и нет «бесконечного» аргумента-сентинела — используйте голый `acquire()` для неограниченного ожидания.

## Исключения

| Исключение                | Бросается                                                            |
|---------------------------|----------------------------------------------------------------------|
| `OperationTimeoutException` | `acquireTimeout` / `withTimeout` превысил `$ms` без свободного слота. **Наследник `Async\AsyncException`, а не `SharedException`.** |
| `TypeException`           | Неположительный `maxSize`, отрицательный `idleTimeoutMs`, `$ms <= 0` или фабрика, вернувшая не-объект. |
| `StaleHandleException`    | `Handle::get()` после того, как хэндл был отпущен.                    |
| `UninitializedException`  | Вызов метода на обёртке пула, которая не завершила `__construct`.     |

`tryAcquire()` **не** бросает при насыщении — он возвращает `null`. Поскольку `OperationTimeoutException` наследует `OxPHP\Async\AsyncException` (а не `SharedException`), `catch (SharedException)` **не** поймает таймаут acquire; используйте `catch (OxPHP\Async\AsyncException)` или ловите `OperationTimeoutException` напрямую.

**Почему это отличается от `Mutex::tryWithLock()`.** Оба — неблокирующие вызовы `try*`, но `Pool` при конкуренции возвращает `null`, а `Mutex` бросает `ContentionException`. Различие структурное, а не стилевое. `Pool` — **handle-first**: каждый захват отдаёт `Handle`, поэтому у исхода «насыщен» есть естественный носитель — `?Handle`, где `null` означает «нет слота» и никогда не сталкивается с настоящим значением (`Handle` сам по себе никогда не бывает пользовательским значением). `Mutex` по дизайну **closure-only** — он намеренно не отдаёт guard блокировки наружу в PHP, чтобы удерживаемый лок нельзя было «утечь» за пределы замыкания. Из-за этого у `tryWithLock` нет объекта, который можно вернуть как nullable, а результат `mixed` его тела может легитимно быть `null` — поэтому `null` не может одновременно означать «не захвачено». Без handle и без свободного sentinel единственный однозначный сигнал конкуренции — исключение. Ловите соответственно: `tryAcquire` → проверка на `null`; `tryWithLock` → `catch (ContentionException)`.

Исключения, брошенные внутри фабрики, распространяются вызывающему acquire без изменений и не потребляют бюджет. Исключения внутри тела `with()` / `withTimeout()` распространяются вызывающему после release слота.

## Наблюдаемость

Полную экскурсию см. в [Shared Observability](../operations/shared-observability.md). Краткие отсылки:

- `GET /__ox_shared/entry?id=N` показывает `{ type: "Pool", size, in_use, idle, waiting, max_size, idle_by_thread, rebalance_strategy }`.
- `GET /__ox_shared/summary` считает экземпляры Pool и агрегированные `waiting_total`, `evicted_total`.
- Prometheus-метрики per pool:
  - `oxphp_shared_pool_size{pool_id="…"}`            — gauge, всего слотов (in-use + idle).
  - `oxphp_shared_pool_in_use{pool_id="…"}`          — gauge.
  - `oxphp_shared_pool_idle{pool_id="…"}`            — gauge.
  - `oxphp_shared_pool_waiting{pool_id="…"}`         — gauge, захваты в очереди.
  - `oxphp_shared_pool_acquire_total{pool_id="…",result="ok|timeout|closed|saturated"}` — counter. `saturated` считает неблокирующие вызовы `tryAcquire`, заставшие пул полным (в отличие от `timeout`, который означает истёкшее ожидание).
  - `oxphp_shared_pool_evicted_total{pool_id="…",reason="idle_timeout|evict|shutdown"}` — counter.
  - `oxphp_shared_pool_wait_seconds_*{pool_id="…"}`  — гистограмма ожидания acquire (bucket / sum / count).

Сочетания, заслуживающие алерта: рост `waiting` при плоском `size` означает, что пул насыщен и должен быть пересмотрен; рост `acquire_total{result="timeout"}` при нормальном `in_use` означает, что фабрика медленная (или блокирует); рост `acquire_total{result="saturated"}` означает, что вызывающие постоянно попадают в `tryAcquire` на полном пуле (срабатывает backpressure).

## Когда не использовать

- **Дешёвые или иммутабельные ресурсы.** Накладные расходы пула больше, чем пересоздание простого объекта. Используйте его для ресурсов, где создание стоит миллисекунды или килобайты.
- **Объекты, которые нельзя безопасно переиспользовать.** Если ресурс накапливает per-request состояние (открытые транзакции, ожидающие чтения) и вы не можете надёжно его сбросить, пуллинг утекает состояние между запросами. Возвращайте слоты в известное состояние в коде завершения запроса или не пуллите.
- **Межхостовые ресурсы.** Pool — внутри процесса. Для межхостового пуллинга соединений предпочитайте connection-bucket сервис или sidecar (pgbouncer, proxy-sql).
- **Неограниченный fan-out.** Если вам нужно одно соединение на каждый in-flight HTTP-вызов, это не пул — это N-на-запрос проблема. Используйте `Shared\Channel` для сериализации работы за ограниченным пулом.
- **Ресурсы со своей собственной семантикой пуллинга.** Многие клиентские библиотеки уже пуллят внутри (например, connection pool у Guzzle). Класть `Shared\Pool` поверх — двойная бухгалтерия; предпочитайте собственный пуллинг библиотеки.
