# Мультиплексирование файберов

OxPHP использует PHP Fibers для одновременной обработки нескольких HTTP-запросов на одном потоке воркера. Когда запрос вызывает `oxphp_sleep()` или `oxphp_async_await()` (при включённом асинхронном пуле), он приостанавливается, и поток воркера немедленно берёт следующий запрос. Это позволяет одному воркеру обрабатывать сотни запросов одновременно без дополнительных потоков.

## Как это работает

1. Поступает запрос, и планировщик назначает его файберу — легковесному контексту выполнения со своим стеком и PHP-состоянием
2. Файбер выполняет обработчик `oxphp_worker()`. Если обработчик завершается без приостановки, ответ отправляется и файбер переиспользуется — никаких накладных расходов по сравнению с обычным воркером
3. Если обработчик вызывает приостанавливающую функцию (`oxphp_sleep()`, `oxphp_usleep()`, `oxphp_async_await()`), файбер возвращает управление планировщику
4. Планировщик принимает новые входящие запросы (создавая новые файберы) и возобновляет приостановленные файберы, когда их условия ожидания выполнены (таймер истёк, результат async готов)
5. PHP-состояние каждого файбера — суперглобальные переменные, заголовки ответа, буферы вывода, стек VM — сохраняется при приостановке и восстанавливается при возобновлении. Файберы полностью изолированы друг от друга

```text
Поток воркера
  |
  +- Файбер A: обработка /api/users ---- oxphp_sleep(0.5) ---- [приостановлен] ---- [возобновлён] ---- ответ
  |
  +- Файбер B: обработка /api/orders ---- oxphp_async_await($p) ---- [приостановлен] ---- [возобновлён] ---- ответ
  |
  +- Файбер C: обработка /health ---- ответ (без приостановки, нулевые накладные расходы)
```

## Конфигурация

Мультиплексирование файберов активируется автоматически при включении worker mode. Дополнительных переменных окружения не требуется.

| Переменная | По умолчанию | Описание |
|------------|-------------|----------|
| `WORKER_FILE` | *(не задана)* | Путь к скрипту воркера. Установка включает worker mode и мультиплексирование файберов |
| `PHP_WORKERS` | CPU / 2 (мин. 1) | Количество потоков воркеров. Каждый поток запускает свой независимый планировщик с поддержкой до 256 одновременных файберов |

Максимальное количество одновременных файберов на поток воркера — 256. При 4 потоках воркеров OxPHP может обрабатывать до 1 024 запросов одновременно.

## Точки приостановки

Эти функции приостанавливают текущий файбер и позволяют другим запросам выполняться на том же потоке:

| Функция | Что происходит |
|---------|---------------|
| `oxphp_sleep(float $seconds)` | Приостанавливает файбер на указанное время. Другие файберы продолжают работать |
| `oxphp_usleep(int $microseconds)` | То же, что `oxphp_sleep()`, с точностью до микросекунд (минимум 1 мс) |
| `oxphp_async_await(int $promise_id)` | Приостанавливает файбер до завершения асинхронной задачи в фоновом пуле потоков |

Эти функции **не** приостанавливают файбер:

| Функция | Поведение |
|---------|----------|
| `oxphp_stream_flush()` | Немедленно отправляет чанк клиенту и возвращается. Используйте с `oxphp_sleep()` в SSE-циклах |
| `oxphp_finish_request()` | Отправляет полный ответ и продолжает выполнение PHP. Не приостанавливает |

> **Примечание:** Встроенные PHP-функции `sleep()` и `usleep()` блокируют весь поток воркера. Всегда используйте `oxphp_sleep()` и `oxphp_usleep()` для кооперативного поведения.

## Примеры PHP

### Базовая одновременная обработка

Запросы без приостановки выполняются на полной скорости без накладных расходов файберов:

```php
<?php
oxphp_worker(function () {
    $path = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);

    if ($path === '/health') {
        echo json_encode(['status' => 'ok']);
        return; // Без приостановки — работает на полной скорости
    }

    if ($path === '/slow') {
        oxphp_sleep(2.0); // Приостановка на 2 секунды — другие запросы выполняются
        echo "Готово после задержки в 2 секунды";
        return;
    }

    echo "Hello";
});
```

### Неблокирующие API-вызовы

Комбинируйте `oxphp_async()` с `oxphp_async_await()` для внешних API-вызовов без блокировки воркера:

```php
<?php
oxphp_worker(function () {
    $p1 = oxphp_async(fn() => file_get_contents('https://api.example.com/users'));
    $p2 = oxphp_async(fn() => file_get_contents('https://api.example.com/orders'));

    $users  = oxphp_async_await($p1);
    $orders = oxphp_async_await($p2);

    header('Content-Type: application/json');
    echo json_encode(['users' => json_decode($users), 'orders' => json_decode($orders)]);
});
```

### SSE с кооперативным сном

Чередование Server-Sent Events с другими запросами через `oxphp_stream_flush()` и `oxphp_sleep()`:

```php
<?php
oxphp_worker(function () {
    header('Content-Type: text/event-stream');
    header('Cache-Control: no-cache');

    for ($i = 0; $i < 30; $i++) {
        echo "data: " . json_encode(['count' => $i, 'time' => time()]) . "\n\n";
        oxphp_stream_flush();
        oxphp_sleep(1.0);
    }
});
```

## Блокирующий ввод/вывод

Мультиплексирование файберов — **кооперативное, а не вытесняющее**. Файбер, вызвавший блокирующую функцию, замораживает весь поток воркера — ни один другой файбер на этом потоке не сможет продвинуться.

### Функции, блокирующие воркер

- `file_get_contents()`, `fopen()`, `fread()`
- `curl_exec()`, `curl_multi_exec()`
- Запросы PDO, `mysqli_query()`
- PHP-функции `sleep()`, `usleep()` (используйте `oxphp_sleep()` вместо них)
- Разрешение DNS (`gethostbyname()`)
- Любой синхронный сетевой или дисковый ввод/вывод

### Как избежать блокировки

Оборачивайте блокирующие операции в `oxphp_async()` для выполнения в асинхронном пуле потоков:

```php
<?php
// НЕПРАВИЛЬНО — блокирует весь поток воркера
$html = file_get_contents('https://example.com');

// ПРАВИЛЬНО — выполняется в async-пуле, файбер приостанавливается
$promise = oxphp_async(fn() => file_get_contents('https://example.com'));
$html = oxphp_async_await($promise);
```

> **Важно:** `oxphp_async()` требует `ASYNC_WORKERS > 0`. Без включённого асинхронного пула вызов выбросит `OxPHP\Async\Exception`. Установите `ASYNC_WORKERS` в нужное значение перед использованием этого паттерна.

Для запросов к базе данных:

```php
<?php
// НЕПРАВИЛЬНО — блокирует воркер
$users = $db->query('SELECT * FROM users WHERE active = 1')->fetchAll();

// ПРАВИЛЬНО — запрос выполняется в async-потоке, файбер приостанавливается
$promise = oxphp_async(function () {
    $db = new PDO('mysql:host=db;dbname=app', 'root', 'secret');
    return $db->query('SELECT * FROM users WHERE active = 1')->fetchAll();
});
$users = oxphp_async_await($promise);
```

> **Примечание:** Соединения с базой данных нельзя передавать в `oxphp_async()`, так как объекты не сериализуемы между потоками. Создавайте соединение внутри async-замыкания или используйте прямой запрос в файбере, если запрос достаточно быстрый.

## Переиспользование файберов

C-стеки файберов выделяются один раз и переиспользуются между запросами. Когда файбер завершает обработку запроса, он не уничтожается — он приостанавливается обратно к планировщику и добавляется в пул свободных файберов. Следующий запрос переиспользует существующий C-стек, избегая дорогостоящего выделения памяти.

PHP VM-стеки (используемые для фреймов вызова функций) выделяются заново для каждого запроса и освобождаются при завершении обработчика.

## Пример Docker

```yaml
services:
  app:
    image: ghcr.io/oxphp/oxphp:0.2.0
    ports:
      - "80:80"
    environment:
      - DOCUMENT_ROOT=/var/www/html/public
      - WORKER_FILE=worker.php
      - PHP_WORKERS=4
      - ASYNC_WORKERS=8
```

При такой конфигурации каждый из 4 потоков воркеров может обрабатывать до 256 одновременных файберов, а блокирующий ввод/вывод выгружается на 8 асинхронных потоков.

## Устранение неполадок

### Запросы замедляются при тяжёлом I/O одного запроса

Файбер вызывает блокирующую функцию без `oxphp_async()`. Это блокирует весь поток воркера.

**Исправление:** оберните блокирующие вызовы в `oxphp_async()`:

```php
<?php
$promise = oxphp_async(fn() => file_get_contents($url));
$result = oxphp_async_await($promise);
```

### Асинхронный пул отключён при использовании oxphp_async()

`ASYNC_WORKERS` равен `0` (значение по умолчанию). При отключённом пуле `oxphp_async()` выбрасывает `OxPHP\Async\Exception`.

**Исправление:** установите `ASYNC_WORKERS` в нужное количество фоновых потоков:

```bash
ASYNC_WORKERS=8
```

### «Failed to dispatch async task» при использовании oxphp_async()

Асинхронный пул настроен, но очередь задач переполнена.

**Исправление:** увеличьте `ASYNC_QUEUE_CAPACITY`:

```bash
ASYNC_QUEUE_CAPACITY=512
```

### oxphp_sleep() не передаёт управление другим запросам

Мультиплексирование файберов работает только в worker mode. В традиционном режиме `oxphp_sleep()` использует блокирующий `usleep()`.

**Исправление:** включите worker mode, установив `WORKER_FILE`.

### Высокое потребление памяти

Каждый файбер использует C-стек (по умолчанию 8 МиБ, настраивается через `fiber.stack_size` в php.ini) плюс PHP VM-стек. При 256 одновременных файберах потребление C-стека в худшем случае — 2 ГиБ на поток воркера.

**Исправление:** уменьшите `fiber.stack_size` в `php.ini`:

```ini
fiber.stack_size = 512K
```

## Ограничения

- **Только worker mode** — мультиплексирование файберов недоступно в традиционном режиме
- **256 файберов на воркер** — жёсткий лимит, не настраиваемый во время выполнения
- **Только кооперативное** — CPU-нагруженный код голодает другие файберы. Вытеснения нет
- **Блокирующий I/O блокирует поток** — все блокирующие вызовы должны быть обёрнуты в `oxphp_async()`
- **Встроенные `sleep()`/`usleep()` PHP не поддерживают файберы** — используйте `oxphp_sleep()`/`oxphp_usleep()`
- **`oxphp_async_await_all()` и `oxphp_async_await_any()` не приостанавливают файбер** — используйте последовательные вызовы `oxphp_async_await()`
