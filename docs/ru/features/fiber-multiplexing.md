---
title: Мультиплексирование запросов на файберах
description: Кооперативная многозадачность, позволяющая PHP-воркерам обрабатывать несколько конкурентных запросов
---

Планировщик файберов OxPHP позволяет каждому потоку PHP-воркера обрабатывать несколько конкурентных HTTP-запросов. Когда запрос вызывает точку приостановки, такую как `oxphp_async_await()` или `oxphp_sleep()`, файбер передаёт управление, и воркер подхватывает другие запросы вместо блокировки.

## Как это работает

Каждый HTTP-запрос выполняется в собственном файбере (`zend_fiber_context` из низкоуровневого Fiber API PHP 8.4). C-стек файбера выделяется один раз через `mmap` и переиспользуется между запросами благодаря **зацикленной корутине** --- корутина обрабатывает запросы в цикле, приостанавливаясь между ними. Это позволяет избежать накладных расходов на `mmap`/`munmap` при каждом запросе.

Поток воркера выполняет цикл событий, который:

1. **Принимает новые запросы** из ограниченного канала (неблокирующий `try_recv`)
2. **Проверяет завершённые асинхронные результаты** для файберов, ожидающих `oxphp_async_await()`
3. **Проверяет истёкшие таймеры** для файберов, ожидающих `oxphp_sleep()` / `oxphp_usleep()`
4. **Возобновляет готовые файберы**, восстанавливая их состояние и переключаясь на их контекст файбера

Каждый файбер имеет собственное изолированное состояние:
- **Состояние PHP VM**: `EG(vm_stack)`, `EG(execute_data)`, `EG(bailout)` --- сохраняется и восстанавливается при каждом переключении контекста
- **Суперглобальные переменные PHP**: `$_SERVER`, `$_GET`, `$_POST` и др. --- перемещаются (не копируются) между TLS и хранилищем файбера
- **Заголовки SAPI**: заголовки ответа и HTTP-код статуса
- **Лимиты C-стека**: `EG(stack_base)` / `EG(stack_limit)` --- устанавливаются для каждого файбера, чтобы предотвратить ложное обнаружение переполнения стека
- **Rust TLS**: буфер вывода ответа, EARLY_TX (канал ответа), время начала запроса

С точки зрения PHP-скрипта выполнение непрерывно --- приостановка и возобновление невидимы.

### Последовательные запросы (без мультиплексирования)

Когда обработчик запроса завершается без вызова точек приостановки, зацикленная корутина обрабатывает его и сразу ожидает следующий запрос. Активен только один файбер, и его C-стек переиспользуется для каждого запроса. Производительность эквивалентна циклу воркера без файберов --- без дополнительного `mmap`, без сохранения/восстановления состояния, без опроса цикла событий.

### Мультиплексированные запросы

Когда обработчик вызывает точку приостановки, файбер приостанавливается и планировщик входит в цикл событий. Цикл событий принимает новые запросы (создавая дополнительные файберы по мере необходимости) и возобновляет файберы, условия приостановки которых выполнены. Каждый дополнительный файбер выделяет собственный C-стек (один раз) и переиспользует его через зацикленную корутину.

```
Worker Thread
===========================
                          ┌─ try_recv ──► new request? ──► create/reuse fiber, start handler
                          │
loop ─────────────────────┤─ poll awaits ► result ready? ─► resume waiting fiber
                          │
                          └─ poll timers ► timer expired? ► resume sleeping fiber

                          (fibers that complete are finalized and their response is sent)
```

## Точки приостановки

Следующие функции вызывают приостановку файбера при вызове внутри обработчика воркера:

| Функция | Поведение |
|---------|-----------|
| `oxphp_async_await(int $promise_id, ?float $timeout = null)` | Приостанавливает до завершения асинхронной задачи или истечения таймаута |
| `oxphp_async_await_all(array $promise_ids, ?float $timeout = null)` | В v1 использует блокирующий вариант (файбер-совместимая версия в будущем релизе) |
| `oxphp_async_await_any(array $promise_ids, ?float $timeout = null)` | В v1 использует блокирующий вариант (файбер-совместимая версия в будущем релизе) |
| `oxphp_sleep(float $seconds)` | Приостанавливает на указанную длительность (кооперативно) |
| `oxphp_usleep(int $microseconds)` | Приостанавливает на указанную длительность в микросекундах (кооперативно) |

При вызове вне файбера (традиционный режим) эти функции используют блокирующие аналоги.

## Конфигурация

Мультиплексирование файберов включается автоматически при активации режима воркера. Дополнительные переменные окружения не требуются.

| Константа | Значение | Описание |
|-----------|----------|----------|
| `OXPHP_MAX_FIBERS` | `256` | Максимальное количество конкурентных файберов на поток воркера (время компиляции) |

Лимит файберов предотвращает накопление слишком большого количества приостановленных запросов одним воркером. При достижении лимита цикл событий прекращает приём новых запросов, пока активный файбер не завершится.

### Масштабирование с несколькими воркерами

Каждый поток PHP-воркера запускает собственный независимый планировщик файберов. Всё состояние (файберы, таймеры, TLS-слоты) является потоко-локальным. Несколько воркеров масштабируются линейно:

| Воркеры | `/bench` (req/s) | `/sleep?ms=20` c40 (req/s) |
|---------|------------------|---------------------------|
| 1 | 40,144 | 867 |
| 2 | 66,619 | 1,378 |

Задайте `PHP_WORKERS=N` для управления количеством потоков воркеров. По умолчанию: `CPU / 2`.

## PHP API

### `oxphp_sleep`

Кооперативный sleep, приостанавливающий текущий файбер и позволяющий воркеру обрабатывать другие запросы во время ожидания.

```php
oxphp_sleep(float $seconds): void
```

**Параметры:**

| Имя | Тип | Описание |
|-----|-----|----------|
| `$seconds` | `float` | Длительность ожидания в секундах (например, `0.5` для 500 мс) |

**Поведение:**
- В режиме воркера: регистрирует таймер и приостанавливает файбер. Планировщик возобновляет его по истечении указанной длительности.
- Вне режима воркера: использует блокирующий `usleep()`.
- Значения, меньшие или равные нулю, возвращают управление немедленно без эффекта.

### `oxphp_usleep`

Кооперативный sleep с микросекундной точностью. Идентичен `oxphp_sleep()`, но принимает микросекунды как целое число, по аналогии со встроенной PHP-функцией `usleep()`.

```php
oxphp_usleep(int $microseconds): void
```

**Параметры:**

| Имя | Тип | Описание |
|-----|-----|----------|
| `$microseconds` | `int` | Длительность ожидания в микросекундах |

**Поведение:** То же, что и `oxphp_sleep()`, но с микросекундной точностью. Значения, меньшие или равные нулю, возвращают управление немедленно.

## Обратная совместимость

Мультиплексирование файберов полностью обратно совместимо:

- **Обработчики, не вызывающие точек приостановки**, проходят через зацикленную корутину без дополнительных накладных расходов. C-стек файбера переиспользуется, сохранение/восстановление состояния не выполняется. Производительность эквивалентна циклу воркера без файберов.
- **`oxphp_sleep()` и `oxphp_usleep()` вне режима воркера** используют блокирующий `usleep()`.
- **`oxphp_async_await()` вне файбера** блокируется на oneshot-канале.
- **Новые переменные окружения не требуются.**
- **Конфигурации с несколькими воркерами** работают идентично --- каждый воркер имеет собственный независимый планировщик файберов.

## Ограничения (v1)

- **`ob_start()` с пользовательскими callback-функциями** может вести себя неожиданно при пересечении точек приостановки. Буферы вывода сбрасываются в буфер ответа Rust при приостановке, поэтому пользовательские callback-функции OB видят частичный вывод на границах приостановки.
- **Разделяемые мутабельные переменные замыкания** (`use (&$var)`) подвержены чередованию в точках приостановки. Между двумя точками приостановки ваш код выполняется без прерывания. В каждой точке приостановки другие запросы могут выполняться на том же воркере. Это та же модель конкурентности, что и `async`/`await` в Node.js.
- **`oxphp_async_await_all` и `oxphp_async_await_any`** в режиме файберов (v1) используют блокирующий вариант. В будущем релизе будут добавлены файбер-совместимые реализации.
- **Максимум 256 конкурентных файберов на воркер.** Это константа времени компиляции (`OXPHP_MAX_FIBERS`).
- **REQUEST_DATA** (серверные переменные, cookie, тело запроса) пока не сохраняется/восстанавливается для каждого файбера. Когда активны несколько файберов, они разделяют последние загруженные данные запроса. Это влияет на `$_SERVER`, `$_GET`, `$_POST` после точки приостановки в сценариях мультиплексирования.

## Примеры

### SSE с кооперативным sleep

Этот пример выполняет потоковую отправку Server-Sent Events, уступая поток воркера во время задержки между событиями. Другие запросы обрабатываются во время каждого вызова `oxphp_sleep()`.

```php
<?php
oxphp_worker(function() {
    header('Content-Type: text/event-stream');
    header('Cache-Control: no-cache');

    for ($i = 0; $i < 10; $i++) {
        echo "data: " . json_encode(['counter' => $i]) . "\n\n";
        oxphp_stream_flush();
        oxphp_sleep(1.0); // yields fiber, worker handles other requests
    }

    echo "event: done\ndata: {}\n\n";
    oxphp_stream_flush();
});
```

### Async await с мультиплексированием

Когда `oxphp_async_await()` приостанавливает файбер, воркер обрабатывает другие HTTP-запросы, ожидая асинхронного результата:

```php
<?php
oxphp_worker(function() {
    $config = ['dsn' => 'mysql:host=localhost;dbname=app', 'user' => 'root', 'pass' => ''];

    // Dispatch async task
    $promise = oxphp_async(function() use ($config): array {
        $pdo = new PDO($config['dsn'], $config['user'], $config['pass']);
        return $pdo->query('SELECT count(*) as c FROM users')->fetch();
    });

    // Fiber suspends here — worker handles other requests
    $result = oxphp_async_await($promise);

    header('Content-Type: application/json');
    echo json_encode($result);
});
```
