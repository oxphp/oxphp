# Маршрутизация

OxPHP направляет входящие HTTP-запросы в одном из трёх режимов, управляемых единственной переменной окружения. Каждый режим воспроизводит знакомую конфигурацию nginx `try_files`, чтобы вы могли точно предсказать, что произойдёт с любым URL.

## Как это работает

Каждый запрос проходит через общий конвейер до того, как сработает логика конкретного режима:

1. **Фильтр dot-путей** — пути со скрытыми сегментами (`.git`, `.env`) блокируются, с исключением для `/.well-known/*` ([RFC 8615](https://www.rfc-editor.org/rfc/rfc8615))
2. **Поиск в кэше маршрутов** — недавно разрешённые URI возвращаются из LRU-кэша (10 000 записей)
3. **Декодирование процентных последовательностей и санитизация** — последовательности вида `%2e%2e` декодируются, а сегменты обхода (`..`, `.`, пустые) удаляются
4. **Блокировка PHP в well-known** — defense-in-depth: `.php`-скрипты внутри `/.well-known/` никогда не выполняются
5. **Классификация URI** — санитизированный путь один раз классифицируется как `NoExtension`, `Php` или `OtherExtension`
6. **Диспетчеризация по режиму** — каждый режим обрабатывает три типа URI по своим правилам
7. **Проверка символических ссылок** — каждый разрешённый путь должен канонизироваться внутри корневого каталога документов

Шаг классификации — ключевая оптимизация: проверка диска для статических ресурсов (`/style.css`, `/logo.png`) выполняется **один раз** в общем слое для URI `OtherExtension`, поэтому все три режима платят одинаковую цену.

## Конфигурация

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `DOCUMENT_ROOT` | `/var/www/html/public` | Корневой каталог для обслуживания файлов и PHP-скриптов |
| `ENTRY_FILE` | *(не задано)* | Единый канонический entry-скрипт. Не задано = Traditional. `*.php` = Framework. Не-`.php` = SPA. При `WORKER_MODE_ENABLED=true` = Worker. Принимает абсолютный путь или относительный к `DOCUMENT_ROOT` (`..` разрешён); итоговый путь должен существовать |
| `WORKER_MODE_ENABLED` | `false` | Включает режим постоянных воркеров. Требует, чтобы `ENTRY_FILE` указывал на `.php`-скрипт |

Старые `INDEX_FILE` и `WORKER_FILE` всё ещё парсятся (со startup `WARN`) и маппятся на новую модель. См. [Configuration → Устаревшие](../operations/configuration.md#устаревшие-index_file-и-worker_file).

## Традиционный режим (Traditional)

Активен, когда `ENTRY_FILE` **не задано** (или пусто) и `WORKER_MODE_ENABLED=false`. Эквивалент в nginx:

```nginx
location / {
    try_files $uri $uri/ /index.php /index.html =404;
}
location ~ \.php$ {
    try_files $uri =404;          # PATH_INFO splitting включён
}
```

**Порядок разрешения:**

1. **`$uri`** — точный файл на диске → отдать (или выполнить, если `.php`)
2. **`$uri/`** — каталог → искать `index.php`, затем `index.html` внутри
3. **PATH_INFO split** — когда URI содержит `.php/`, префикс скрипта матчится на диске, а остаток становится `PATH_INFO` (например, `/api.php/users/42` → скрипт `api.php`, `PATH_INFO=/users/42`)
4. **`/index.php`** — корневой фронт-контроллер как фолбэк
5. **`/index.html`** — корневой статический индекс как фолбэк
6. **Worker fallback** — если `WORKER_MODE_ENABLED=true`, диспатч в `ENTRY_FILE` воркера
7. **404**

**Примеры:**

| Запрос | Результат |
|---|---|
| `/about.php` | Выполнить `about.php` |
| `/style.css` | Отдать `style.css` |
| `/blog/` (с `blog/index.php`) | Выполнить `blog/index.php` |
| `/api.php/users/42` | Выполнить `api.php` с `PATH_INFO=/users/42` |
| `/missing.txt` | Фолбэк на `/index.php` |
| `/some/route` | Фолбэк на `/index.php` |

PATH_INFO splitting **всегда включён** в Traditional mode. Переключателя в env нет — переменная `SPLIT_PATH_INFO_ENABLED` удалена.

## Режим фреймворка (Framework)

Активен при `ENTRY_FILE=index.php` (или любом значении, оканчивающемся на `.php`) и `WORKER_MODE_ENABLED=false`. Эквивалент в nginx:

```nginx
location ~ \.(?!php$)[a-zA-Z0-9]+$ {
    try_files $uri =404;          # статика: жёсткий 404, если нет файла
}
location / {
    rewrite ^ /index.php last;    # всё остальное → фронт-контроллер
}
location = /index.php {
    fastcgi_param PATH_INFO $request_uri;
    fastcgi_pass ...;
}
```

**Правила разрешения:**

| Тип URI | Поведение |
|---|---|
| `.css`, `.png`, `.js`, … (любое расширение, кроме php) | Отдать файл, если он существует, иначе **жёсткий 404** |
| `.php` (любой путь) | Переписать на `/index.php` с `PATH_INFO`, равным оригинальному URI |
| без расширения (`/api/users`, `/`) | Переписать на `/index.php` с `PATH_INFO`, равным оригинальному URI |

**Примеры:**

| Запрос | Результат | `$_SERVER['PATH_INFO']` |
|---|---|---|
| `/style.css` (есть) | Отдать `style.css` | — |
| `/style.css` (нет) | **404** (без фолбэка) | — |
| `/api/users` | Выполнить `index.php` | `/api/users` |
| `/about.php` | Выполнить `index.php` | `/about.php` |
| `/api.php/v1/users` | Выполнить `index.php` | `/api.php/v1/users` |
| `/index.php` (напрямую) | Выполнить `index.php` | `/index.php` |
| `/` | Выполнить `index.php` | `/` |

Фронт-контроллер всегда получает **оригинальный URI** в `PATH_INFO`, что позволяет роутеру решать, что делать, без необходимости отдельно разбирать `REQUEST_URI`. Прямой доступ к `/index.php` больше не блокируется — переписывание на `/index.php` идемпотентно, поэтому прямое обращение даёт тот же результат, что и `/`.

## Режим SPA

Активен при `ENTRY_FILE=index.html` (или любом не-`.php` значении) и `WORKER_MODE_ENABLED=false`. Эквивалент в nginx:

```nginx
location ~ \.php$ {
    try_files $uri =404;          # PHP: файл должен существовать, без фолбэка
}
location ~ \. {
    try_files $uri =404;          # другие расширения: жёсткий 404, если нет файла
}
location / {
    try_files /index.html =404;   # пути без расширения: сразу на index.html
}
```

**Правила разрешения:**

| Тип URI | Поведение |
|---|---|
| `.php` | Выполнить файл, если он существует, иначе **жёсткий 404** |
| `.css`, `.png`, … (любое другое расширение) | Отдать файл, если он существует, иначе **жёсткий 404** |
| без расширения (`/dashboard`, `/api/users`, `/`) | Отдать `/index.html` напрямую — **без обращения к диску для `$uri`** |

**Примеры:**

| Запрос | Результат |
|---|---|
| `/style.css` (есть) | Отдать `style.css` |
| `/style.css` (нет) | **404** |
| `/dashboard` | Отдать `/index.html` |
| `/users/42/edit` | Отдать `/index.html` |
| `/api.php` (есть) | Выполнить `api.php` |
| `/api.php` (нет) | **404** |
| `/index.html` (напрямую) | Отдать `index.html` |

Две важные особенности семантики:

- **Пути без расширения не трогают диск** — режим SPA никогда не спрашивает «существует ли `/dashboard` на диске?» и всегда возвращает индекс. Это корректно для клиентских роутеров и избавляет от лишних `stat()`.
- **Отсутствующая статика — жёсткий 404, а не фолбэк** — отсутствующий `/style.css` не отдаст молча `index.html`. Это ловит битые ссылки на ассеты на ранней стадии вместо того, чтобы возвращать HTML там, где JS ждёт CSS.

## Режим воркера

Режим воркера активируется при `WORKER_MODE_ENABLED=true` и `ENTRY_FILE`, указывающем на `.php`-скрипт. Роутер обслуживает статику в стиле direct-mapping, а все остальные запросы диспатчит в `ENTRY_FILE` воркера вместо возврата 404.

| Шаг | Поведение |
|---|---|
| Статика (`.css`, `.png`, …) | Отдаётся напрямую с диска, если есть; иначе жёсткий 404 |
| Всё остальное | Диспатчится в `ENTRY_FILE` воркера |

Стартовая валидация отклоняет два сочетания:

- `WORKER_MODE_ENABLED=true` без `ENTRY_FILE` → `WORKER_MODE_ENABLED=true requires ENTRY_FILE to be set`.
- `WORKER_MODE_ENABLED=true` с не-`.php` `ENTRY_FILE` → `WORKER_MODE_ENABLED=true requires a .php ENTRY_FILE`.

Подробности конфигурации см. в [Режим воркера](worker-mode.md).

## Поведение PATH_INFO

`$_SERVER['PATH_INFO']` заполняется по-разному в зависимости от режима:

| Режим | Когда установлен | Значение |
|---|---|---|
| Traditional | Только когда URI содержит `.php/` (PATH_INFO split) | Хвост после сегмента скрипта, например `/users/42` |
| Framework | **Всегда** | Полный оригинальный URI, например `/api/users` |
| SPA | Никогда | (PHP вызывается только для точных `.php`-файлов; PATH_INFO нет) |

В Traditional mode разбиение всегда включено — переменная `SPLIT_PATH_INFO_ENABLED` удалена. Если вам нужна маршрутизация на основе PATH_INFO, используйте Traditional mode и поместите `.php`-скрипт в качестве префикса.

## Безопасность путей

OxPHP применяет несколько уровней защиты от обхода каталогов, утечки скрытых файлов и эскейпа через символические ссылки:

- **Декодирование процентных последовательностей** выполняется до санитизации, поэтому закодированные попытки обхода вроде `/%2e%2e/etc/passwd` перехватываются
- **Фильтрация сегментов** удаляет `..`, `.` и пустые сегменты из разрешённого пути
- **Проверка символических ссылок** канонизирует каждый разрешённый путь и проверяет, что он остаётся в пределах корневого каталога документов. Символические ссылки за пределы блокируются
- **Блокировка dot-путей** блокирует любой сегмент пути, начинающийся с `.` (например, `/.git/config`, `/.env`), с исключением для `/.well-known/*` по RFC 8615
- **Блокировка PHP в well-known** — даже с исключением dot-путей, `.php`-скрипты внутри `/.well-known/` никогда не выполняются (defense-in-depth)
- **Deny-лист выполнения PHP** — в режиме Traditional переменная `PHP_DENY_PATHS` блокирует выполнение `.php` для заданных glob-паттернов (например, `/uploads/**` или отдельный файл `/admin/legacy.php`) до любого обращения к диску. См. [Deny-лист выполнения PHP](../security/php-deny.md)

> **Примечание:** Если корневой каталог документов не существует при запуске, сервер завершает работу с фатальной ошибкой. Защита от symlink-эскейпа требует допустимого, разрешаемого пути к корневому каталогу документов.

## Устранение неполадок

### Все запросы возвращают 404 в Traditional mode

Убедитесь, что `index.php` или `index.html` существует в корне документов. Цепочка `try_files` Traditional падает только на них — если оба отсутствуют и URL ни с чем не сматчился, вы получаете 404.

```bash
docker exec <container> ls /var/www/html/public
```

### Отсутствующий статический ассет возвращает 404 вместо SPA-shell'а

Это намеренно в режимах Framework и SPA. Отсутствующий `/style.css` — это жёсткий 404, а не молчаливый фолбэк на `index.html`. Это ловит битые ссылки на ассеты на ранней стадии. Если нужен фолбэк — используйте Traditional mode.

### Прямой `/index.php` больше не возвращает 404

В Framework mode прямой доступ к фронт-контроллеру теперь разрешён (переписывание на `/index.php` идемпотентно). Если вы раньше полагались на 404 для отлова прямых обращений, переключитесь на проверку `PATH_INFO` внутри контроллера.

### `PATH_INFO` пустой в Framework mode

Убедитесь, что `ENTRY_FILE` оканчивается на `.php`. Иначе OxPHP выберет SPA mode, который не заполняет `PATH_INFO`. В Framework mode переменная теперь устанавливается безусловно — никаких feature flags больше не нужно.

### Символическая ссылка внутри корневого каталога возвращает 404

Символические ссылки, указывающие за пределы корневого каталога, блокируются намеренно. Переместите целевое содержимое внутрь корневого каталога документов или примонтируйте его как каталог по правильному пути.

## Пример Docker

```yaml
services:
  app:
    image: ghcr.io/oxphp/oxphp:0.5.0
    ports:
      - "8080:80"
    volumes:
      - ./src:/var/www/html
    environment:
      - DOCUMENT_ROOT=/var/www/html/public
      - ENTRY_FILE=index.php
```
