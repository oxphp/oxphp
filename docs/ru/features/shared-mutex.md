# Shared\Mutex

`OxPHP\Shared\Mutex` — это общепроцессный блокирующий примитив взаимного исключения, оборачивающий хранимое скалярное значение. Вы никогда не трогаете блокировку напрямую — вы передаёте замыкание в `with()` (блокирующий) или `tryWith()` (неблокирующий), и рантайм держит блокировку на протяжении замыкания, отпуская её даже если замыкание бросит исключение.

## Обзор

- **Охраняет значение, а не просто секцию.** Обёрнутое значение передаётся в ваше замыкание, и новое значение, которое оно возвращает, фиксируется обратно.
- **Отравляется при сбое замыкания.** Если замыкание бросает, mutex помечается отравлённым; последующие вызовы `with()` завершаются с `PoisonedException`, пока вы явно не вызовете `clearPoison()`. Это не даёт другим воркерам оперировать над состоянием, которое было на полпути обновления при возникновении ошибки.
- **Избегает дедлоков.** Повторный вход в тот же mutex на том же потоке (включая вложенные async-вызовы, захваченные на этом потоке) поднимает `DeadlockException` вместо зависания.
- **Захват с таймаутом.** `with($fn, $timeout)` ждёт до `$timeout` секунд; ноль означает ждать бесконечно. `tryWith` мгновенен.

## Справочник API

```php
namespace OxPHP\Shared;

final class Mutex implements Shareable
{
    public function __construct(mixed $initial = null, ?float $defaultTimeout = null);

    public function isPoisoned(): bool;
    public function clearPoison(): void;

    public function with(callable $fn, float $timeout = 0.0): mixed;
    public function tryWith(callable $fn): mixed;

    public function id(): int;
}
```

Сигнатура замыкания — `function (mixed $value): mixed` — оно получает текущее сохранённое значение по значению и возвращает новое значение для сохранения. Если замыкание возвращает `null`, сохранённое значение становится `null`.

| Метод         | Возврат                  | Применение                                                    |
|---------------|--------------------------|---------------------------------------------------------------|
| `with`        | возврат замыкания        | Атомарный RMW над сохранённым значением; блокирует до `$timeout`. |
| `tryWith`     | возврат замыкания или `null` | То же, но сразу возвращает `null`, если блокировка удерживается. |
| `isPoisoned`  | bool                     | Проверить, отравлён ли mutex.                                 |
| `clearPoison` | void                     | Сбросить в рабочее состояние после обработки предыдущего сбоя. |

## Примеры

### Атомарное обновление нескольких полей

Counter достаточно, когда значение — одно целое. Mutex выигрывает, когда несколько полей должны обновляться синхронно:

```php
<?php
$stats = new OxPHP\Shared\Mutex(['hits' => 0, 'bytes' => 0]);

$stats->with(function (array $s) use ($responseBytes) {
    $s['hits']  += 1;
    $s['bytes'] += $responseBytes;
    return $s;                     // атомарно записано обратно
});
```

Другой воркер, читающий `$stats->with(fn ($s) => $s)`, видит либо оба поля обновлёнными, либо ни одного — никогда бампнутый `hits` без соответствующих `bytes`.

### Неблокирующая проверка + деградация

```php
<?php
$budget = new OxPHP\Shared\Mutex(['tokens' => 100, 'refill_at' => time()]);

$allowed = $budget->tryWith(function (array $b) {
    if ($b['tokens'] <= 0) return $b;     // no-op, просто посмотреть
    $b['tokens'] -= 1;
    return $b;
});

if ($allowed === null) {
    // Блокировку держит другой воркер — сбрасываем запрос вместо очереди.
    http_response_code(503);
    return;
}
```

### Захват с таймаутом

```php
<?php
$cache = new OxPHP\Shared\Mutex(null, defaultTimeout: 2.0);

try {
    $result = $cache->with(function ($c) { /* ... */ return $c; }, timeout: 5.0);
} catch (OxPHP\Shared\TimeoutException $e) {
    // Кто-то другой держал блокировку дольше 5 с.
}
```

### Восстановление отравлённого mutex

```php
<?php
try {
    $state->with(function ($s) {
        doRiskyThing($s);          // бросает
        return $s;
    });
} catch (Throwable $e) {
    // Другие воркеры теперь получают PoisonedException из $state->with(...).
    if ($state->isPoisoned()) {
        reinitialiseFromPersistentStore($state);
        $state->clearPoison();
    }
    throw $e;
}
```

## Семантика и подводные камни

- **Замыкание выполняется с удерживаемой блокировкой.** Держите его коротким. Не вызывайте `sleep`, не блокируйтесь на сетевом I/O, не входите повторно в другие типы Shared\*, которые могут позвать обратно в этот mutex.
- **Отравление строгое по умолчанию.** Любое исключение внутри замыкания отравляет mutex, даже если сохранённое значение не было тронуто. Если нужен паттерн «попробовать-вычислить без отравления», делайте это вне mutex, а `with` вызывайте только для коммита.
- **`$defaultTimeout` применяется, когда вы передаёте `0.0` в `with`.** Передавайте именованный аргумент `timeout:` явно, чтобы переопределить per-call.
- **Сохранённое значение в v1 только скалярное.** Строки, int'ы, float'ы, boolean'ы и вложенные массивы из них работают; объекты, замыкания и ресурсы поднимают `TypeException`.
- **Реентрантность на том же потоке бросает.** Используйте другой mutex или перестройте код — повторный вход — это баг, а не фича.

## Исключения

| Исключение               | Бросается                                                           |
|--------------------------|---------------------------------------------------------------------|
| `PoisonedException`      | `with` / `tryWith` на отравлённом mutex (после предыдущего throw).  |
| `TimeoutException`       | `with` превысил `$timeout` (или `defaultTimeout`) без захвата.      |
| `DeadlockException`      | Реентрантный `with`/`tryWith` на том же mutex на том же потоке.     |
| `TypeException`          | Конструктор или возвращаемое замыканием значение не сериализуемо.   |
| `StaleHandleException`   | Вызов метода на хэндле, чья запись реестра была вытеснена.          |
| `UninitializedException` | `id()` на обёртке, которая не завершила `__construct`.               |

`tryWith` намеренно возвращает `null` при конкуренции, а не бросает — конкуренция не ошибка.

## Наблюдаемость

См. [Shared Observability](../operations/shared-observability.md). Краткие отсылки:

- `GET /__ox_shared/entry?id=N` показывает `{ type: "Mutex", poisoned, waiters, last_acquire_ms, held_by_thread }`.
- Prometheus-метрики per instance:
  - `oxphp_shared_mutex_waiters{mutex_id="…"}` — текущее число ждущих.
  - `oxphp_shared_mutex_acquires_total{mutex_id="…"}` — захваты за время жизни.
  - `oxphp_shared_mutex_contended_total{mutex_id="…"}` — захваты, которым пришлось ждать.
  - `oxphp_shared_mutex_poisoned{mutex_id="…"}` — 0 / 1.

## Когда не использовать

- **Одно атомарное значение.** Если охраняемое значение — одно int или один bool, используйте `Shared\Counter` или `Shared\Flag` — оба lock-free и дешевле.
- **Долгая работа.** Не держите mutex через I/O, `sleep` или fiber-await'ы. Используйте вместо этого паттерн producer/consumer на `Shared\Channel`.
- **Горячий путь с высокой конкуренцией.** Если каждый запрос должен взять один и тот же mutex, вы сериализовали свою пропускную способность. Разбейте состояние на партиции (например, `Shared\Map<tenant_id, Mutex>`) или агрегируйте предварительно в per-worker локальных переменных и периодически сливайте.
- **Межхостовое взаимное исключение.** Только в процессе. Для межхостовой координации используйте распределённую блокировку (Redis `SET NX`, etcd).
