# Разделяемое состояние

`OxPHP\Shared\*` — это набор конкурентных примитивов, живущих внутри процесса сервера и видимых каждому PHP-воркеру. Они позволяют воркерам координировать изменяемое состояние — счётчики, feature-флаги, кэши, очереди задач, пулы соединений — без обращения к Redis, Memcached или APCu.

Всё, что описано здесь, полностью находится внутри процесса. Разделяемое состояние теряется при остановке сервера. Если вам нужна долговечность или координация между несколькими хостами, см. [Миграция на внешнее хранилище](migrating-to-external-store.md).

## Зачем нужно разделяемое состояние

PHP-воркеры под традиционным SAPI не разделяют память. У каждого воркера свои опкоды, свои статические свойства классов, свои глобалы. Координация состояния между воркерами исторически означала внешнюю зависимость: APCu для кэшей на одном хосте, Redis для счётчиков, отдельный брокер очередей для fan-out.

OxPHP запускает движок PHP как многопоточный in-process SAPI. Это означает, что тщательно спроектированный набор примитивов *может* предоставить воркерам безопасный взгляд на одно и то же состояние. Именно это и даёт `OxPHP\Shared\*`:

- **Доступ с нулевой задержкой.** Нет сетевого round-trip; нет сериализации в сокет. Стоимость операции — микросекунды.
- **Отсутствие внешней зависимости.** На один сервис меньше для деплоя, мониторинга и поддержания живым.
- **Типизированные примитивы.** `Shared\Counter` — это атомарное целое. `Shared\Map` — конкурентный hash-map. Вам не нужно переизобретать корректность поверх семантики `INCR`.
- **Безопасность циклов и жизненного цикла.** Рантайм отслеживает ссылки, так что хэндл не может пережить свою запись в реестре, а хранилища отклоняют графы, которые привели бы к утечке памяти.

Разделяемое состояние — не серебряная пуля. Оно не заменяет Redis, когда нужна долговечность между перезапусками, и не заменяет настоящий брокер сообщений, когда нужно несколько хостов. Зона применимости описана ниже в [Когда не использовать](#когда-не-использовать).

## Ментальная модель

Каждый экземпляр `Shared\*` подкреплён записью в общепроцессном **реестре**. PHP-объект (хэндл, который вы держите) несёт идентификатор реестра; реестр владеет настоящим состоянием.

```
 ┌──────────────────── PHP worker 1 ────────────────────┐
 │  $counter (Shared\Counter, id=7) ──┐                  │
 └────────────────────────────────────┼─────────────────┘
                                      │
                                      ▼
                            ┌─────────────────────┐
                            │   Shared registry   │
                            │                     │
                            │   id=7: Counter = 42│
                            │   id=8: Map { … }   │
                            │   id=9: Channel(16) │
                            └─────────▲───────────┘
                                      │
 ┌────────────────────────────────────┼─────────────────┐
 │  $counter (Shared\Counter, id=7) ──┘                  │
 └──────────────────── PHP worker 2 ────────────────────┘
```

Следствия:

- **Хэндлы разделяют состояние по ссылке.** Два воркера, держащие «один и тот же» счётчик, немедленно видят записи друг друга.
- **Время жизни следует за ссылками.** Запись в реестре освобождается после того, как последний хэндл уходит и ни одна другая Shared-запись на неё не указывает.
- **`clone` запрещён.** Клонирование хэндла создало бы два PHP-объекта, которые выглядят разными, но мутируют одну и ту же запись реестра — запутанно и чревато багами. Все типы бросают исключение при `clone`.
- **Межпоточная передача явная.** Чтобы передать Shared-значение в фоновый файбер, используйте `oxphp_async(fn () use ($thing) { ... })`. Импорт через `use` передаёт хэндл; сама запись реестра потокобезопасна.

## Примитивы v1

OxPHP 0.3 поставляется с семью типами. Выбирайте по семантике, а не по привычке:

| Тип                                      | Форма                    | Подходит для                                                              |
|------------------------------------------|--------------------------|-----------------------------------------------------------------------|
| [`Shared\Counter`](shared-counter.md)    | атомарный int64          | счётчики запросов, использование на тенант, отслеживание срабатываний фич |
| [`Shared\Flag`](shared-flag.md)          | атомарный bool           | kill-switch'и, маркеры одноразовой инициализации, состояние circuit-breaker |
| [`Shared\Once`](shared-once.md)          | контейнер с init-once    | дорогая инициализация синглтона между воркерами (побеждает один запуск) |
| [`Shared\Mutex`](shared-mutex.md)        | отравляющийся mutex      | критические секции над неатомарным значением                               |
| [`Shared\Channel`](shared-channel.md)    | ограниченная MPMC-очередь | пайплайны producer/consumer, fan-out задач                            |
| [`Shared\Map`](shared-map.md)            | конкурентный string→mixed | кэши по ключу, состояние на тенант, lookup'ы в стиле реестра         |
| [`Shared\Pool`](shared-pool.md)          | ограниченный пул объектов | дорогие потокозависимые ресурсы (DB-хэндлы, парсеры)                  |

> **Берите самый простой тип, который подходит.** `Counter` побеждает `Map<string, int>` с одним ключом; `Flag` побеждает `Counter` для true/false; `Mutex<T>` побеждает сэмодельные цепочки compare-and-set.

## Быстрый старт — атомарный счётчик под конкурентностью

```php
<?php
// worker.php — загружается через WORKER_FILE, выполняется один раз на PHP-воркер
require __DIR__ . '/vendor/autoload.php';

$requests = new OxPHP\Shared\Counter();

oxphp_worker(function () use ($requests) {
    $requests->inc();                 // атомарно под конкурентностью
    header('X-Request-Count: ' . $requests->get());
    echo 'hello';
});
```

[Worker mode](worker-mode.md) выполняет внешнюю область видимости один раз на поток воркера; захват `use ($requests)` сохраняет тот же хэндл `Shared\Counter` живым между всеми запросами, которые обрабатывает этот воркер. Между потоками воркеров сама запись реестра одна и та же — все потоки воркеров, которые держат хэндлы с одинаковым `id()`, мутируют один и тот же атомарный int64.

Когда файберу тоже нужно увидеть счётчик, передайте его через `use`:

```php
<?php
oxphp_async(function () use ($requests) {
    $requests->inc();                 // выполняется на том воркере, который подхватит файбер
});
```

> Создание `new OxPHP\Shared\Counter()` в двух разных местах создаёт два независимых счётчика с разными `id()`. Разделяемое состояние разделяется *по хэндлу*, а не по имени. Пробрасывайте хэндл через DI, захваты замыкания или bootstrap-файл — не конструируйте заново в каждом воркере и не ожидайте, что они сольются.

## Канонический пример — миграция самописного счётчика

Команды часто пишут координацию поверх APCu или статических массивов. Вот шаблон миграции на `Shared\*`, на примере per-IP rate limiter.

### До: static + внешняя блокировка

```php
<?php
// Хрупко: не атомарно под конкурентностью, не переживает перезагрузки
// на некоторых сборках APCu разделяет счётчики между несвязанными хостами в пуле.
final class NaiveRateLimiter
{
    public function __construct(
        private int $maxRequests,
        private int $windowSeconds,
    ) {}

    public function allow(string $ip): bool
    {
        $key     = "rl:{$ip}";
        $now     = time();
        $current = apcu_fetch($key);

        if ($current === false || $now - $current['start'] >= $this->windowSeconds) {
            apcu_store($key, ['count' => 1, 'start' => $now], $this->windowSeconds * 2);
            return true;
        }

        apcu_store(
            $key,
            ['count' => $current['count'] + 1, 'start' => $current['start']],
            $this->windowSeconds * 2,
        );

        return $current['count'] + 1 <= $this->maxRequests;
    }
}
```

В этом коде спрятаны три бага: пара `apcu_fetch` + `apcu_store` не атомарна, начало окна теряется при близкой гонке, а очистка — это фактически то, что APCu решит вытеснить по TTL.

### После: Shared\Map + update()

```php
<?php
final class RateLimiter
{
    public function __construct(
        private OxPHP\Shared\Map $buckets,
        private int $maxRequests,
        private int $windowSeconds,
    ) {}

    public function allow(string $ip): bool
    {
        $now = time();

        // Атомарный read-modify-write. Замыкание видит текущее значение
        // (или null при первом попадании) и возвращает новую форму для хранения.
        $state = $this->buckets->update($ip, function ($current) use ($now) {
            if ($current === null || $now - $current['start'] >= $this->windowSeconds) {
                return ['count' => 1, 'start' => $now];
            }
            return ['count' => $current['count'] + 1, 'start' => $current['start']];
        });

        return $state['count'] <= $this->maxRequests;
    }

    /** Фоновая очистка — вызывайте из планируемого воркера или цикла oxphp_async. */
    public function sweep(): void
    {
        $now    = time();
        $cutoff = $this->windowSeconds * 2;
        foreach ($this->buckets->keys() as $ip) {
            $state = $this->buckets->get($ip);
            if ($state !== null && $now - $state['start'] >= $cutoff) {
                $this->buckets->remove($ip);
            }
        }
    }
}

// Bootstrap
$limiter = new RateLimiter(
    buckets:       new OxPHP\Shared\Map(maxEntries: 50_000),
    maxRequests:   100,
    windowSeconds: 60,
);

// На каждый запрос
if (!$limiter->allow($_SERVER['REMOTE_ADDR'])) {
    http_response_code(429);
    header('Retry-After: 60');
    echo '429 Too Many Requests';
    return;
}
```

Что принесла миграция:

- **Атомарность.** `update($key, fn)` — это один RMW; гонки read-then-store нет.
- **Детерминированная очистка.** `sweep()` предсказуем и выполняется по расписанию, которое вы контролируете.
- **На одну зависимость меньше.** APCu больше нет в истории деплоя.
- **Точный счёт под нагрузкой.** Два конкурентных хита на один IP никогда не затирают друг друга.

> Встроенный [Rate Limiting](rate-limiting.md) (`RATE_LIMIT=...`) продолжает работать на уровне соединения и быстрее, чем лимитер на уровне PHP. Берите самописный лимитер только когда нужна политика уровня PHP — per-tenant, per-route, per-user-id, а не per-IP.

### Когда выбрать Map, а когда Counter

В примере используется `Map<string, array{count,start}>`, потому что каждому IP нужны два поля, синхронизированных между собой. Когда нужен только текущий итог без состояния окна, `Counter` дешевле:

```php
<?php
$hits = new OxPHP\Shared\Counter();

// Каждый запрос инкрементирует, цикл read-modify-write не нужен.
$current = $hits->inc();          // атомарный inc-и-вернуть
```

Берите `Map<string, Counter>` (map из счётчиков), когда нужны per-key итоги без логики окон:

```php
<?php
$perTenant = new OxPHP\Shared\Map();

$counter = $perTenant->getOrSet($tenantId, fn () => new OxPHP\Shared\Counter());
$counter->inc();
```

## Семантика хэндла

Каждый объект `Shared\*` — тонкая PHP-обёртка вокруг идентификатора реестра. Отсюда несколько правил:

1. **Идентичность — это ID реестра, а не PHP-объект.** Два хэндла с одинаковым ID указывают на одно и то же состояние. Проверка равенства — это `$a->id() === $b->id()`.
2. **Сериализация заблокирована.** `serialize($counter)` бросает исключение. Реестр живёт только в этом процессе — в провод нечего класть. Используйте [гайд по миграции](migrating-to-external-store.md), когда вам действительно нужно пересечь границу процесса.
3. **`clone` заблокирован.** По той же причине — клонированная обёртка выглядела бы другой, но разделяла бы состояние. Сконструируйте свежий экземпляр, если хотите независимое значение.
4. **`id()` стабилен до потери последней ссылки.** Сохраняйте его в логах, включайте в trace-спаны, используйте как ключ поиска, когда внутренний сервер возвращает запись в [Наблюдаемости](../operations/shared-observability.md).

## Жизненный цикл

Записи reference-counted. Запись реестра остаётся живой, пока выполняется **любое** из следующего:

- PHP-обёртка в каком-либо воркере ссылается на неё.
- Она — значение, хранящееся внутри другого живого `Shared\Map` / `Shared\Channel`.
- Ожидающая async-операция захватила её через замыкание.

Как только refcount достигает нуля, реестр вызывает типоспецифичный `on_drop` (который освобождает вложенные ссылки, закрывает каналы, сбрасывает слоты пулов и т. д.), затем освобождает слот.

Явного `close()` на большинстве типов нет. У `Shared\Channel` он есть, потому что отправителям и получателям нужен способ сигнализировать «больше элементов не будет»; он **не** освобождает запись реестра раньше — для этого всё равно нужно сбросить все ссылки. `Shared\Pool::evict()` сбрасывает простаивающие слоты, но оставляет сам пул на месте.

## Безопасность циклов

Хранить один Shareable внутри другого разрешено; хранить A внутри B, когда B (напрямую или транзитивно) уже достигает A, создало бы цикл и утечку. Каждая мутация, добавляющая ссылку, сначала запускает ограниченный BFS и отвергает запись с `OxPHP\Shared\CycleException` до того, как тронуть состояние:

```php
<?php
$a = new OxPHP\Shared\Map();
$b = new OxPHP\Shared\Map();
$a->set('b', $b);                // ок

try {
    $b->set('a', $a);            // замыкает петлю — отклонено
} catch (OxPHP\Shared\CycleException $e) {
    // $b не тронут, частичного состояния нет, удержание на $a не утекло
}
```

Бюджет обходчика настраивается: `SHARED_CYCLE_DETECT_DEPTH` (по умолчанию 16) и `SHARED_CYCLE_DETECT_EDGES` (по умолчанию 10 000). Очень большие легитимные графы, превышающие бюджет, получают `CycleException` с сообщением `bounds exceeded`.

## Межпоточная передача

Shared-хэндлы безопасно использовать из любого воркера и из async-контекстов. Единственное правило: **передавайте их через `use`, а не `global`.** Замыкания, захваченные async-операциями, нуждаются в явных импортах, чтобы рантайм корректно удерживал refcount.

```php
<?php
$queue = new OxPHP\Shared\Channel(256);

oxphp_async(function () use ($queue) {              // ← явный use
    while (($job = $queue->recv(timeout: 30.0)) !== null) {
        process($job);
    }
});

$queue->send(['url' => $_POST['url']]);
```

Экземпляры `Shared\*` **не** сериализуемы, так что не пытайтесь перевозить их через shell-команды, HTTP-тела или сессионное хранилище.

## Наблюдаемость

Каждая запись реестра видна через [внутренний сервер](../operations/internal-server.md). Полную экскурсию см. в [Shared Observability](../operations/shared-observability.md). Кратко:

- `GET /__ox_shared/summary` — агрегированные счётчики, память и операции по типу.
- `GET /__ox_shared/entries` — каждая живая запись с id, типом, refcount и размером.
- `GET /__ox_shared/entry?id=N` — типоспецифичные детали одной записи.
- `GET /__ox_shared/graph?id=N` — BFS-обход исходящих ссылок (полезно после `CycleException`).
- `/metrics` — Prometheus-счётчики и gauge'ы с префиксом `oxphp_shared_*`.

Отключайте интроспекцию в production-развёртываниях с недоверенными тенантами через `SHARED_INTROSPECTION_ENABLED=false`; метрики остаются включёнными.

## Конфигурация

Все переменные окружения читаются при старте. Значения по умолчанию рассчитаны на сотни записей на одном хосте; увеличивайте их для развёртываний с тяжёлым реестром.

| Переменная                       | По умолчанию | Эффект                                                                |
|----------------------------------|---------|-----------------------------------------------------------------------|
| `SHARED_MAX_ENTRIES`             | 100 000 | Глобальный потолок на все Shared-записи вместе. Вставка сверх — ошибка. |
| `SHARED_MAX_BYTES`               | 1 GiB   | Глобальный потолок на оценочную память по всем Shared-записям.          |
| `SHARED_SOFT_LIMIT_RATIO`        | 0.7     | Начать сбрасывать низкоприоритетную работу при пересечении этой доли. |
| `SHARED_CYCLE_DETECT_DEPTH`      | 16      | Глубина BFS при проверке циклов. Поднимайте для глубоких легитимных графов. |
| `SHARED_CYCLE_DETECT_EDGES`      | 10 000  | Пройденных рёбер при проверке циклов. Поднимайте для плотных легитимных графов. |
| `SHARED_PREVIEW_ARRAY_LIMIT`     | 20      | Записей, семплируемых в превью `/entry?id=…`.                          |
| `SHARED_PREVIEW_STRING_LIMIT`    | 256     | Обрезка каждой строки в превью.                                        |
| `SHARED_INTROSPECTION_ENABLED`   | true    | Переключает API `/__ox_shared/*`.                                      |
| `SHARED_METRICS_ENABLED`         | true    | Переключает Prometheus-экспозицию `oxphp_shared_*`.                    |
| `SHARED_SHUTDOWN_TIMEOUT_SECONDS`| 5.0     | Максимум ожидания заблокированных отправителей/получателей/вызовов пула при остановке сервера. |

## Когда не использовать

Разделяемое состояние живёт внутри процесса. Это ограничивает его применение.

- **Несколько хостов.** Если вы запускаете более одного процесса OxPHP (обычный случай для всего, что больше одной машины), воркеры в процессе A не видят записи `Shared\*` в процессе B. Используйте Redis, NATS или что уже развёрнуто. [Миграция на внешнее хранилище](migrating-to-external-store.md) разбирает распространённые паттерны.
- **Долговечность.** Разделяемое состояние испаряется при перезапуске процесса. Если ваш счётчик должен пережить деплой, храните его в другом месте.
- **Неограниченные значения.** `Shared\Map` без `maxEntries` может быть доведён до OOM злоумышленником. Всегда ставьте потолок на всё, что ключуется пользовательским вводом.
- **Большие пэйлоады.** Значения копируются через FFI-границу при чтении. Пихать массивы по 10 МБ в `Shared\Map` — неверная форма — положите блоб в объектное хранилище и разделяйте URL.
- **Замена кэшированию OPcache / APCu.** OPcache уже кэширует скомпилированные скрипты; APCu кэширует данные области запроса per-worker (что дешевле, когда на самом деле не нужна межворкерная видимость).

## Распространённые ошибки

- **Забыть ограничить `Shared\Map`.** Неограниченные map'ы, ключуемые IP-адресами / user-ID / session-токенами, — топ-1 самонанесённый OOM. Всегда передавайте `maxEntries` и ловите `CapacityException`.
- **Читать целый массив на каждом запросе.** `Map::get` копирует. Если вы трогаете большой массив десятки раз за запрос, кэшируйте копию в переменной области запроса.
- **Трактовать `recv` / `get` как non-null.** Каждое чтение может легитимно вернуть `null` (закрытый канал, отсутствующий ключ). Всегда проверяйте на null.
- **Использовать `global` с async.** Файберы, запущенные `oxphp_async`, требуют свои захваты в клаузе `use (…)`. Ссылки `global` не отслеживаются.
- **Сюрприз клонирования.** `clone $counter` бросает. Новые пользователи часто это пробуют; выучите альтернативу (`new Shared\Counter($counter->get())`) один раз.
