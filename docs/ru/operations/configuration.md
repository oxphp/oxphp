---
title: Конфигурация
description: Полный справочник переменных окружения OxPHP

OxPHP настраивается исключительно через переменные окружения. Файлы конфигурации отсутствуют. Каждая переменная имеет разумное значение по умолчанию, поэтому деплой без конфигурации работает из коробки для разработки.

## Справочник переменных окружения

### Сервер

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `LISTEN_ADDR` | `0.0.0.0:8080` | Адрес и порт основного HTTP-сервера |
| `DOCUMENT_ROOT` | `/var/www/html/public` | Корневая директория для обслуживания файлов и PHP-скриптов |
| `INDEX_FILE` | *(пусто)* | Управляет режимом маршрутизации. См. [Режимы маршрутизации](#режимы-маршрутизации) |
| `TOKIO_WORKERS` | `0` | Потоки асинхронного ввода-вывода Tokio. `0` = авто (CPU / 2, мин. 1), `1` = однопоточная среда, `N` = многопоточная среда с N рабочими потоками |
| `MAX_CONNECTIONS` | `10000` | Максимальное количество одновременных TCP-соединений. Новые соединения сверх этого лимита ожидают разрешения семафора |

### Выполнение PHP

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `EXECUTOR` | `sapi` | Тип PHP-исполнителя. `sapi` для реального выполнения PHP, `stub` для заглушки ответа (бенчмаркинг) |
| `PHP_WORKERS` | `0` (CPU / 2, мин. 1, статический) | Режим пула воркеров. Укажите `N` для фиксированного пула или `MIN:MAX` для динамического масштабирования. См. [Режимы воркеров](#режимы-воркеров) |
| `PHP_WORKERS_IDLE_SEC` | `30` | Секунды бездействия динамического воркера до его вывода из пула. Применяется только в динамическом режиме |
| `QUEUE_CAPACITY` | `PHP_WORKERS * 128` | Максимальное количество запросов в очереди PHP. При заполнении новые PHP-запросы получают ответ `503 Service Unavailable`. Использует начальное количество воркеров для динамического режима |

### Логирование

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `LOG_LEVEL` | `info` | Уровень детализации логов. Один из: `trace`, `debug`, `info`, `warn`, `error` |
| `ACCESS_LOG` | *(выкл.)* | JSON access log: `all` (все запросы), `error` (только 4xx/5xx), пустое/не задано = выключен |

### Таймауты

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `HEADER_TIMEOUT_SECS` | `5` | Максимальное время ожидания заголовков запроса после TCP-соединения в секундах |
| `IDLE_TIMEOUT_SECS` | `60` | Таймаут бездействия keep-alive. Соединения без активности в течение этого времени закрываются |
| `REQUEST_TIMEOUT_SECS` | `120` | Максимальное время всего цикла запрос-ответ в секундах. Установите `0` для отключения |
| `DRAIN_TIMEOUT_SECS` | `30` | Максимальное время ожидания завершения текущих соединений при плавной остановке в секундах |

### Ограничение частоты запросов

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `RATE_LIMIT` | `0` | Максимальное количество запросов с одного IP-адреса за временное окно. `0` отключает ограничение частоты |
| `RATE_WINDOW_SECS` | `60` | Длительность окна ограничения частоты в секундах |

### TLS

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `TLS_CERT` | *(нет)* | Путь к PEM-файлу TLS-сертификата. Для включения TLS необходимо установить оба параметра: `TLS_CERT` и `TLS_KEY` |
| `TLS_KEY` | *(нет)* | Путь к PEM-файлу закрытого TLS-ключа |

### Наблюдаемость

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `INTERNAL_ADDR` | *(нет)* | Адрес внутреннего сервера (проверки состояния, метрики, конфигурация). Не запускается, если не установлен |
| `ERROR_PAGES_DIR` | *(нет)* | Директория с HTML-файлами пользовательских страниц ошибок, именованными `{status}.html` (например, `404.html`, `503.html`) |

### Режим воркера

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `WORKER_FILE` | *(нет)* | Путь к PHP-скрипту воркера (относительно `DOCUMENT_ROOT`). При установке включает персистентный режим воркера, в котором PHP-процессы остаются живыми между запросами |
| `WORKER_MAX_REQUESTS` | `0` | Максимальное количество запросов, которое воркер обрабатывает до рециклирования. `0` отключает лимит |
| `WORKER_MAX_MEMORY` | `0` | Максимальная память (в мегабайтах), которую воркер может использовать до рециклирования. `0` отключает лимит |

### Сжатие

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `COMPRESSION` | `true` | Включить сжатие Brotli для сжимаемых типов ответов. Отключить значением `false`, `0` или `off` |

## Режимы воркеров

Переменная `PHP_WORKERS` определяет, использует ли пул PHP-воркеров фиксированный размер или масштабируется динамически.

### Статический режим (по умолчанию)

Установите `PHP_WORKERS` в числовое значение (или оставьте пустым/`0` для автоопределения):

```bash
PHP_WORKERS=8      # Фиксированные 8 воркеров
PHP_WORKERS=0      # Автоопределение: CPU / 2 (мин. 1)
```

Воркеры создаются при запуске и никогда не изменяются. Каждый воркер использует блокирующий `recv()` с нулевой нагрузкой на CPU в простое.

### Динамический режим

Установите `PHP_WORKERS` в формат `MIN:MAX` для включения автомасштабирования:

```bash
PHP_WORKERS=2:16       # Масштабирование от 2 до 16 воркеров
PHP_WORKERS=4:0        # Минимум 4, автоопределение максимума (CPU * 2)
PHP_WORKERS=0:0        # Автоопределение обоих (CPU/4 мин (мин 1), CPU*2 макс)
```

ScaleManager запускается каждые 500 мс и:
- **Масштабирует вверх**, когда все воркеры заняты и пул ниже MAX (задержка 500 мс)
- **Масштабирует вниз**, когда воркер простаивает дольше `PHP_WORKERS_IDLE_SEC` и пул выше MIN (задержка 5 с)

Динамические воркеры используют `recv_timeout(200ms)` для периодической проверки флага завершения.

## Режимы маршрутизации

Переменная `INDEX_FILE` определяет, как OxPHP маршрутизирует входящие запросы. Существует три режима:

| Режим | Значение `INDEX_FILE` | Поведение |
|-------|----------------------|-----------|
| Традиционный | *(пусто / не установлено)* | Прямое сопоставление файлов. `/about.php` обслуживает `about.php`. `/` обслуживает `index.php` или `index.html`, если они существуют |
| Фреймворк | `index.php` | Все запросы к несуществующим файлам направляются в `index.php` (фронт-контроллер). Прямой доступ к `.php` заблокирован |
| SPA | `index.html` | Несуществующие файлы возвращают `index.html`. `.php`-файлы по-прежнему выполняются нормально |

### Традиционный режим (по умолчанию)

URL-адреса напрямую соответствуют файлам на диске. Это стандартное поведение для классических PHP-приложений.

```bash
# INDEX_FILE не установлен — традиционный режим по умолчанию
DOCUMENT_ROOT=/var/www/html/public
```

### Режим фреймворка

Все запросы проходят через единую точку входа. Это стандартный паттерн для Laravel, Symfony и аналогичных фреймворков.

```bash
INDEX_FILE=index.php
DOCUMENT_ROOT=/var/www/html/public
```

### Режим SPA

Статические ресурсы обслуживаются напрямую. Все остальные запросы получают `index.html`, позволяя JavaScript-маршрутизатору обрабатывать навигацию.

```bash
INDEX_FILE=index.html
DOCUMENT_ROOT=/var/www/html/dist
```

## Примеры конфигураций

### Разработка

```bash
LISTEN_ADDR=127.0.0.1:8080
DOCUMENT_ROOT=./www
LOG_LEVEL=debug
PHP_WORKERS=1
INTERNAL_ADDR=127.0.0.1:9090
```

### Laravel продакшен (статический пул)

```bash
LISTEN_ADDR=0.0.0.0:8080
DOCUMENT_ROOT=/var/www/html/public
INDEX_FILE=index.php
PHP_WORKERS=8
QUEUE_CAPACITY=1024
LOG_LEVEL=warn
MAX_CONNECTIONS=10000
INTERNAL_ADDR=127.0.0.1:9090
RATE_LIMIT=100
RATE_WINDOW_SECS=60
HEADER_TIMEOUT_SECS=5
IDLE_TIMEOUT_SECS=30
REQUEST_TIMEOUT_SECS=60
DRAIN_TIMEOUT_SECS=30
COMPRESSION=true
```

### Laravel продакшен (динамический пул)

```bash
LISTEN_ADDR=0.0.0.0:8080
DOCUMENT_ROOT=/var/www/html/public
INDEX_FILE=index.php
PHP_WORKERS=4:32
PHP_WORKERS_IDLE_SEC=60
QUEUE_CAPACITY=512
LOG_LEVEL=warn
MAX_CONNECTIONS=10000
INTERNAL_ADDR=127.0.0.1:9090
RATE_LIMIT=100
RATE_WINDOW_SECS=60
HEADER_TIMEOUT_SECS=5
IDLE_TIMEOUT_SECS=30
REQUEST_TIMEOUT_SECS=60
DRAIN_TIMEOUT_SECS=30
COMPRESSION=true
```

### Docker Compose

```yaml
services:
  oxphp:
    image: oxphp:latest
    ports:
      - "8080:8080"
    environment:
      LISTEN_ADDR: "0.0.0.0:8080"
      DOCUMENT_ROOT: "/var/www/html/public"
      INDEX_FILE: "index.php"
      PHP_WORKERS: "4"             # Или "2:16" для динамического масштабирования
      # PHP_WORKERS_IDLE_SEC: "30" # Таймаут бездействия (только динамический режим)
      QUEUE_CAPACITY: "512"
      LOG_LEVEL: "info"
      INTERNAL_ADDR: "127.0.0.1:9090"
      COMPRESSION: "true"
    volumes:
      - ./src:/var/www/html
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://127.0.0.1:9090/health"]
      interval: 10s
      timeout: 5s
      retries: 3
```

### Режим воркера (персистентный PHP)

```bash
LISTEN_ADDR=0.0.0.0:8080
DOCUMENT_ROOT=/var/www/html/public
WORKER_FILE=../worker.php
PHP_WORKERS=8
WORKER_MAX_REQUESTS=10000
WORKER_MAX_MEMORY=128
QUEUE_CAPACITY=1024
LOG_LEVEL=warn
INTERNAL_ADDR=127.0.0.1:9090
```

Режим воркера сохраняет PHP-процессы живыми между запросами. Скрипт воркера вызывает `oxphp_worker()` с callback-обработчиком. Воркеры автоматически рециклируются при достижении `WORKER_MAX_REQUESTS` или `WORKER_MAX_MEMORY`. Установите оба значения в `0` для отключения рециклирования.

### Терминация TLS

```bash
LISTEN_ADDR=0.0.0.0:443
TLS_CERT=/etc/oxphp/tls/cert.pem
TLS_KEY=/etc/oxphp/tls/key.pem
```

OxPHP использует rustls для TLS, поэтому зависимость от OpenSSL отсутствует. Сертификат и ключ должны быть в формате PEM.

## Просмотр активной конфигурации

Когда внутренний сервер работает, вы можете просмотреть текущую конфигурацию:

```bash
curl -s http://localhost:9090/config | jq .
```

```json
{
  "listen_addr": "0.0.0.0:8080",
  "document_root": "/var/www/html/public",
  "index_file": "index.php",
  "executor_type": "sapi",
  "max_connections": 10000,
  "drain_timeout_secs": 30,
  "header_timeout_secs": 5,
  "idle_timeout_secs": 60,
  "request_timeout_secs": 120,
  "rate_limit": 100,
  "rate_window_secs": 60,
  "tls_enabled": true,
  "error_pages_dir": "/etc/oxphp/error-pages",
  "compression": true,
  "access_log": true,
  "plugins": {}
}
```

Пути к TLS-ключу и сертификату не включаются в вывод. Булево значение `tls_enabled` указывает, активен ли TLS. Объект `plugins` содержит конфигурацию загруженных плагинов.
