Расширение `oxphp_sapi` для PHP регистрирует восемь встроенных функций, которые предоставляют вашему PHP-коду доступ к внутренним механизмам сервера OxPHP. Эти функции доступны в каждом PHP-скрипте, выполняемом OxPHP --- директива `extension=` не требуется, поскольку расширение скомпилировано в пользовательский SAPI.

Плагины могут регистрировать дополнительные PHP-функции при запуске. Эти функции, предоставляемые плагинами, регистрируются во время `MINIT` через C-мост и отображаются наряду со встроенными.

## `oxphp_request_id`

Возвращает уникальный идентификатор, присвоенный текущему запросу.

```php
oxphp_request_id(): string
```

**Параметры:** Нет.

**Возвращаемое значение:** 16-символьная шестнадцатеричная строка. Формат: `{timestamp_hex}{counter_hex}`, где первые 8 символов --- Unix-метка времени, а последние 8 --- монотонный счётчик. Возвращает пустую строку, если идентификатор запроса не установлен (не должно происходить при нормальной обработке запросов).

**Пример:**

```php
<?php
$requestId = oxphp_request_id();
// "67a3b1c400000042"

header("X-Request-Id: $requestId");

// Использование в логировании приложения
error_log("[$requestId] Processing payment for order #1234");
```

**Примечания:**
- Идентификатор запроса устанавливается сервером до начала выполнения PHP.
- Тот же идентификатор доступен на стороне Rust для логирования доступа и заголовков ответа.
- Идентификатор уникален в рамках времени жизни одного серверного процесса.

## `oxphp_worker_id`

Возвращает индекс потока PHP-воркера, обрабатывающего текущий запрос.

```php
oxphp_worker_id(): int
```

**Параметры:** Нет.

**Возвращаемое значение:** Целое число с нулевой базой, идентифицирующее поток воркера. Значения варьируются от `0` до `PHP_WORKERS - 1` для статических воркеров. Динамические воркеры получают идентификаторы выше начального диапазона.

**Пример:**

```php
<?php
$workerId = oxphp_worker_id();
// 3

// Использование для временных директорий конкретного воркера или отладки
$tmpDir = "/tmp/oxphp-worker-$workerId";
```

**Примечания:**
- Идентификаторы воркеров стабильны в течение всего времени жизни потока воркера.
- В режиме динамического масштабирования воркеры, запущенные после старта, получают инкрементные идентификаторы выше начального размера пула.
- Полезно для отладки проблем конкурентности или разделения ресурсов, специфичных для воркера.

## `oxphp_server_info`

Возвращает ассоциативный массив с метаданными сервера и воркера.

```php
oxphp_server_info(): array
```

**Параметры:** Нет.

**Возвращаемое значение:** Ассоциативный массив со следующими ключами:

| Ключ | Тип | Описание |
|------|-----|----------|
| `sapi` | `string` | Всегда `"oxphp"` |
| `version` | `string` | Версия сервера (в настоящее время `"0.1.0"`) |
| `worker_id` | `int` | То же значение, что и `oxphp_worker_id()` |
| `request_time` | `float` | Unix-метка времени с точностью до микросекунд, когда запрос начался |

**Пример:**

```php
<?php
$info = oxphp_server_info();
// [
//     "sapi"         => "oxphp",
//     "version"      => "0.1.0",
//     "worker_id"    => 3,
//     "request_time" => 1738800000.123456,
// ]

// Вычисление прошедшего времени
$elapsed = microtime(true) - $info['request_time'];
echo "Request processing took {$elapsed}s so far";
```

**Примечания:**
- `request_time` читается из локального хранилища потока C-библиотеки моста, которое устанавливается до `php_request_startup()`.
- Это значение также используется проверкой `file_update_protection` в OPcache.

## `oxphp_request_heartbeat`

Заглушка для будущего механизма продления таймаута сторожевого таймера. В настоящее время ничего не делает.

```php
oxphp_request_heartbeat(int $time = 10): bool
```

**Параметры:**

| Имя | Тип | По умолчанию | Описание |
|-----|-----|--------------|----------|
| `$time` | `int` | `10` | Запрашиваемое продление таймаута в секундах |

**Возвращаемое значение:** В текущей реализации всегда возвращает `true`.

**Пример:**

```php
<?php
// Длительный импорт данных
foreach ($records as $record) {
    process($record);
    oxphp_request_heartbeat(30); // Сигнал о том, что скрипт ещё жив
}
```

**Примечания:**
- Эта функция существует для обеспечения совместимости с будущими версиями. В будущем релизе она будет сбрасывать сторожевой таймер таймаута запроса.
- Вызов сейчас безопасен и не влияет на производительность.

## `oxphp_finish_request`

Отмечает текущий запрос как завершённый, позволяя серверу отправить ответ клиенту, пока PHP-скрипт продолжает выполняться в фоновом режиме. Это аналог `fastcgi_finish_request()` в OxPHP.

```php
oxphp_finish_request(): bool
```

**Параметры:** Нет.

**Возвращаемое значение:** Возвращает `true` при первом вызове. Возвращает `false`, если запрос уже был завершён (т.е. функция вызвана более одного раза в рамках одного запроса).

**Пример:**

```php
<?php
// Немедленная отправка ответа клиенту
echo json_encode(['status' => 'accepted']);
oxphp_finish_request();

// Продолжение фоновой работы — клиент уже получил ответ
send_notification_email($userId);
update_analytics($eventData);
cleanup_temp_files();
```

**Примечания:**
- После вызова этой функции любой дальнейший вывод через `echo` или `print` не включается в ответ клиенту.
- Поток PHP-воркера остаётся занятым до завершения выполнения скрипта, поэтому длительные фоновые задачи уменьшают доступный пул воркеров.
- Повторный вызов этой функции в том же запросе возвращает `false` при втором вызове.

## `oxphp_is_streaming`

Проверяет, находится ли текущий запрос в режиме потоковой передачи.

```php
oxphp_is_streaming(): bool
```

**Параметры:** Нет.

**Возвращаемое значение:** `true`, если режим потоковой передачи активен, `false` в противном случае.

**Пример:**

```php
<?php
if (oxphp_is_streaming()) {
    // Инкрементальная отправка вывода
    echo "data: " . json_encode($event) . "\n\n";
    flush();
} else {
    // Буферизация полного ответа
    echo json_encode($allData);
}
```

**Примечания:**
- Режим потоковой передачи активируется автоматически при установке заголовка `Content-Type: text/event-stream` или вручную через `oxphp_stream_flush()`.
- Эта функция полезна для скриптов, которым необходимо адаптировать поведение вывода в зависимости от режима транспорта.

---

## `oxphp_stream_flush`

Активирует режим потоковой передачи (если он ещё не активен) и сбрасывает текущий буфер вывода клиенту в виде чанка. Это основная функция для реализации Server-Sent Events (SSE) в OxPHP.

```php
oxphp_stream_flush(): bool
```

**Параметры:** Нет.

**Возвращаемое значение:** Возвращает `true` при успехе. Возвращает `false`, если запрос уже был завершён через `oxphp_finish_request()`.

**Пример:**

```php
<?php
header('Content-Type: text/event-stream');
header('Cache-Control: no-cache');

for ($i = 0; $i < 10; $i++) {
    echo "id: $i\n";
    echo "data: " . json_encode(['counter' => $i, 'time' => microtime(true)]) . "\n\n";
    oxphp_stream_flush();
    sleep(1);
}
```

**Как это работает:**

1. При первом вызове активирует режим потоковой передачи через C-мост (`oxphp_bridge_set_stream_mode`)
2. Сбрасывает все буферы вывода PHP (`php_output_flush_all`)
3. Вызывает callback SAPI flush, который отправляет буферизованный вывод как HTTP-чанк клиенту

**Примечания:**
- Заголовки отправляются клиенту при первом сбросе. Последующие вызовы отправляют только чанки тела.
- Можно также использовать нативный PHP `flush()` с `Content-Type: text/event-stream` — OxPHP автоматически определяет SSE content type и активирует режим потоковой передачи. В этом случае сначала вызовите `ob_end_flush()`, чтобы отключить буферизацию вывода PHP.
- Если `oxphp_finish_request()` был вызван ранее, функция возвращает `false` и ничего не делает.
- HTTP-соединение закрывается автоматически, когда PHP-скрипт завершается и канал потоковой передачи закрывается.
- Обратное давление обеспечивается через ограниченный канал (ёмкость 64) — если клиент медленный, `oxphp_stream_flush()` блокируется, пока клиент не догонит.

## `oxphp_worker`

Входит в цикл персистентного режима воркера. Вызывает предоставленный callback-обработчик для каждого входящего HTTP-запроса. Между запросами выполняется мягкий сброс, который очищает состояние текущего запроса (суперглобальные переменные, буферы вывода, `$_SESSION`) без уничтожения PHP-кучи, поэтому состояние начальной загрузки (автозагрузчики, подключения к базе данных, кешированная конфигурация) сохраняется между запросами.

```php
oxphp_worker(callable $handler): bool
```

**Параметры:**

| Имя | Тип | Описание |
|-----|-----|----------|
| `$handler` | `callable` | Callback, вызываемый один раз на каждый HTTP-запрос. Не принимает аргументов. |

**Возвращаемое значение:** Возвращает `true` при плавной остановке (сервер останавливается). Немедленно возвращает `false`, если режим воркера не включён (т.е. `WORKER_FILE` не установлен).

**Пример:**

```php
<?php
// worker.php — точка входа персистентного воркера

// Начальная загрузка: выполняется один раз за время жизни воркера
require __DIR__ . '/vendor/autoload.php';
$db = new PDO('mysql:host=localhost;dbname=app', 'root', '');
$config = json_decode(file_get_contents(__DIR__ . '/config.json'), true);

// Обработка запросов в цикле
oxphp_worker(function () use ($db, $config) {
    $uri = $_SERVER['REQUEST_URI'];
    $method = $_SERVER['REQUEST_METHOD'];

    // Маршрутизация и обработка запроса
    if ($uri === '/api/users' && $method === 'GET') {
        $users = $db->query('SELECT id, name FROM users')->fetchAll();
        header('Content-Type: application/json');
        echo json_encode($users);
    } else {
        http_response_code(404);
        echo 'Not Found';
    }
});
```

**Как это работает:**

1. Callback-обработчик вызывается для каждого HTTP-запроса, полученного от уровня Rust.
2. Между запросами выполняется мягкий сброс:
   - Суперглобальные переменные (`$_GET`, `$_POST`, `$_SERVER`, `$_COOKIE`, `$_FILES`) заполняются данными нового запроса
   - Буферы вывода очищаются
   - Заголовки HTTP-ответа сбрасываются
   - Функции завершения, зарегистрированные через `register_shutdown_function()`, вызываются и очищаются
3. Сборка мусора запускается периодически (каждые 100 запросов) для освобождения циклических ссылок без влияния на задержку каждого запроса.
4. Цикл завершается, когда:
   - Сервер останавливается (сигнал плавной остановки)
   - Обработчик выбрасывает неперехваченное исключение или фатальную ошибку (причина выхода: `error`)
   - Воркер достиг `WORKER_MAX_REQUESTS` (причина выхода: `max_requests`)
   - Воркер превысил `WORKER_MAX_MEMORY` (причина выхода: `max_memory`)

**Примечания:**
- Эта функция работает только при установленном `WORKER_FILE`. Вызов из обычного PHP-скрипта генерирует `E_WARNING` и возвращает `false`.
- Переменные, объявленные вне замыкания обработчика, сохраняются между запросами. Используйте это для подключений к базе данных, конфигурации и другой затратной инициализации.
- Конструкция `use` замыкания обработчика захватывает переменные по ссылке или значению как обычно. Переменные, захваченные по ссылке, разделяют состояние между запросами.
- Рециклирование воркера (через `WORKER_MAX_REQUESTS` или `WORKER_MAX_MEMORY`) вызывает завершение и пересоздание процесса воркера, что повторно выполняет весь скрипт воркера, включая начальную загрузку.
- Метрики режима воркера (`oxphp_worker_requests_handled_total`, `oxphp_worker_recycles_total` и др.) доступны на эндпоинте `/metrics` при работающем внутреннем сервере.

## Функции плагинов

Плагины могут регистрировать пользовательские PHP-функции, вызываемые из ваших скриптов. Эти функции регистрируются во время инициализации PHP-модуля (`MINIT`) и диспетчеризуются через C-мост к коду обработчика на Rust.

Функции плагинов используют нативный мост для диспетчеризации с нулевой сериализацией. Аргументы и возвращаемые значения передаются как сырые указатели `zval` — Rust читает и пишет их напрямую через C-функции доступа, без накладных расходов на JSON-кодирование. Если обработчик возвращает ошибку, генерируется PHP-предупреждение `E_WARNING` и возвращается `NULL`.

```php
<?php
// Пример: вызов функции, зарегистрированной плагином
$result = some_plugin_function('arg1', 42, ['key' => 'value']);
```

Функции плагинов отображаются наряду со встроенными функциями в выводе `phpinfo()`, но они регистрируются глобально (не под расширением `oxphp_sapi`), поэтому не появляются в `get_extension_funcs('oxphp_sapi')`.

## Информация о расширении

Метаданные расширения видны в выводе `phpinfo()`:

| Поле | Значение |
|------|----------|
| Имя расширения | `oxphp_sapi` |
| Версия | `0.1.0` |

Вы можете проверить, что расширение загружено:

```php
<?php
var_dump(extension_loaded('oxphp_sapi'));
// bool(true)

// Список встроенных функций расширения
print_r(get_extension_funcs('oxphp_sapi'));
// Array
// (
//     [0] => oxphp_request_id
//     [1] => oxphp_worker_id
//     [2] => oxphp_server_info
//     [3] => oxphp_request_heartbeat
//     [4] => oxphp_finish_request
//     [5] => oxphp_is_streaming
//     [6] => oxphp_stream_flush
//     [7] => oxphp_worker
// )
```
