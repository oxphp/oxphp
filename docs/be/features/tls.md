OxPHP тэрмінуе TLS непасрэдна з дапамогай rustls, без залежнасці ад OpenSSL. Калі TLS наладжаны, сервер прымае HTTPS-злучэнні і ўзгадняе HTTP/2 або HTTP/1.1 праз ALPN.

## Канфігурацыя

| Зменная | Апісанне | Змаўчанне |
|---------|---------|-----------|
| `TLS_CERT` | Шлях да файла сертыфіката ў фармаце PEM | *(не зададзена)* |
| `TLS_KEY` | Шлях да файла прыватнага ключа ў фармаце PEM | *(не зададзена)* |

Абедзве зменныя павінны быць зададзены для ўключэння TLS. Калі зададзена толькі адна, TLS не ўключаецца.

```bash
TLS_CERT=/etc/oxphp/cert.pem
TLS_KEY=/etc/oxphp/key.pem
LISTEN_ADDR=0.0.0.0:443
```

## Як гэта працуе

Пры запуску OxPHP чытае файлы сертыфіката і ключа, разбірае іх як PEM і стварае `TlsAcceptor` з канфігурацыі rustls.

Канфігурацыя TLS уключае:

- **Крыптаправайдар**: ring (праз `rustls::crypto::ring::default_provider()`)
- **Версіі пратакола**: бяспечныя змаўчанні, абраныя rustls (TLS 1.2 і 1.3)
- **Аўтэнтыфікацыя кліента**: адключана (без праверкі кліенцкага сертыфіката)
- **Пратаколы ALPN**: `h2` і `http/1.1`, у гэтым парадку

Калі паступае TCP-злучэнне, сервер выклікае `acceptor.accept(stream)` для выканання TLS-рукапаціскання перад перадачай зашыфраванага патоку ў hyper для HTTP-апрацоўкі.

## Фарматы сертыфікатаў

Файл сертыфіката павінен утрымліваць адзін або некалькі сертыфікатаў у фармаце PEM (сертыфікат сервера, за якім ідуць прамежкавыя сертыфікаты, калі яны маюцца). Файл ключа павінен утрымліваць адзін прыватны ключ у фармаце PEM (RSA, ECDSA або Ed25519).

### Самападпісаны сертыфікат для распрацоўкі

Стварыце самападпісаны сертыфікат для лакальнай распрацоўкі:

```bash
openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:prime256v1 \
  -keyout key.pem -out cert.pem -days 365 -nodes \
  -subj "/CN=localhost"
```

Потым наладзьце OxPHP:

```bash
TLS_CERT=./cert.pem
TLS_KEY=./key.pem
```

### Прыклад для Docker

Змантуйце сертыфікаты ў кантэйнер:

```yaml
services:
  oxphp:
    image: oxphp:latest
    ports:
      - "443:443"
    environment:
      LISTEN_ADDR: "0.0.0.0:443"
      TLS_CERT: /certs/cert.pem
      TLS_KEY: /certs/key.pem
    volumes:
      - ./certs:/certs:ro
```

## Праца ў змешаным рэжыме

OxPHP не абслугоўвае адначасова HTTP і HTTPS на адным слухачы. Каб падтрымліваць абодва пратаколы, запусціце два экзэмпляры або выкарыстоўвайце зваротны проксі для перанакіравання з HTTP на HTTPS.

## Без залежнасці ад OpenSSL

Выкарыстанне rustls азначае, што бінарны файл сервера наогул не злучаецца з OpenSSL. Гэта выключае распаўсюджаную крыніцу CVE ў вытворчых разгортваннях і спрашчае вобраз кантэйнера (не патрэбны пакеты `libssl`).
