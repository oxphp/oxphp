title: Карыстальніцкія старонкі памылак
description: Папярэдне загружаныя HTML-старонкі памылак для адказаў 4xx і 5xx
---

OxPHP можа аддаваць карыстальніцкія HTML-старонкі памылак для адказаў 4xx і 5xx. Старонкі памылак загружаюцца з дыска аднойчы пры запуску і аддаюцца з памяці на гарачым шляху.

## Канфігурацыя

| Пераменная | Апісанне | Па змаўчанні |
|------------|----------|--------------|
| `ERROR_PAGES_DIR` | Каталог з HTML-файламі старонак памылак | *(не зададзена)* |

```bash
ERROR_PAGES_DIR=/var/www/errors
```

Калі гэтая пераменная не зададзена, адказы з памылкамі выкарыстоўваюць звычайныя тэкставыя целы па змаўчанні (напрыклад, `404 Not Found`).

## Наіменаванне файлаў

Файлы старонак памылак павінны адпавядаць канвенцыі назваў `{status}.html`, дзе `{status}` — гэта код стану HTTP:

```
errors/
  403.html
  404.html
  500.html
  502.html
  503.html
  529.html
```

Загружаюцца толькі коды стану ў дыяпазоне 400-599. Файлы з нелічбавымі назвамі, назвамі па-за гэтым дыяпазонам або з пашырэннямі, адрознымі ад `.html`, ігнаруюцца.

## Як гэта працуе

### Загрузка

Пры запуску OxPHP чытае сканфігураваны каталог і загружае кожны валідны файл `{status}.html` у `HashMap<u16, Bytes>`. Змесціва файлаў захоўваецца як байтавыя буферы з падлікам спасылак для аддачы без капіравання. Кожная загружаная старонка лагіруецца на ўзроўні `info`.

Калі каталог не існуе або не можа быць прачытаны, запісваецца папярэджанне і сервер запускаецца без карыстальніцкіх старонак памылак.

### Аддача

`ErrorPagesHandler` працуе як апрацоўшчык падзей для падзей `ResponseBuilding` з прыярытэтам **60**. Гэта размяшчае яго пасля большасці апрацоўкі, але перад апрацоўшчыкамі загалоўкаў сервера і журнала доступу (прыярытэт 100).

Для кожнага адказу з кодам стану 400 і вышэй апрацоўшчык правярае папярэдне загружаныя старонкі. Калі адпаведная старонка існуе, цела адказу замяняецца карыстальніцкім HTML-змесцівам, а загаловак `Content-Type` усталёўваецца ў `text/html; charset=utf-8`.

Адказы з кодамі стану 2xx або 3xx не закранаюцца.

### Прыклад старонкі

Мінімальная старонка памылкі 404:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>404 - Page Not Found</title>
</head>
<body>
  <h1>Page Not Found</h1>
  <p>The requested page does not exist.</p>
</body>
</html>
```

Захавайце гэта як `404.html` у каталогу, зададзеным у `ERROR_PAGES_DIR`.

## Прадукцыйнасць

Старонкі памылак загружаюцца ў памяць аднойчы пры запуску. Аддача карыстальніцкай старонкі памылкі — гэта `HashMap::get()`, за якім ідзе `Bytes::clone()` (атамарнае павелічэнне лічыльніка спасылак). Дыскавы ўвод-вывад пры апрацоўцы запытаў не адбываецца.

## Абмежаванні

Карыстальніцкія старонкі памылак прымяняюцца толькі да адказаў, якія праходзяць праз звычайны канвеер апрацоўкі запытаў. Адказы, усталяваныя як ранні вяртанне (напрыклад, 429 ад абмежавання хуткасці), абыходзяць падзею `ResponseBuilding` і не закранаюцца карыстальніцкімі старонкамі памылак.
