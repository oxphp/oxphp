OxPHP падтрымлівае тры рэжымы маршрутызацыі, якія кіруюцца адной зменнай асяроддзя. Кожны рэжым вызначае, як уваходныя URL-шляхі супастаўляюцца з файламі на дыску.

## Рэжымы маршрутызацыі

Зменная асяроддзя `INDEX_FILE` выбірае рэжым маршрутызацыі:

| Рэжым | Значэнне `INDEX_FILE` | Выпадак выкарыстання |
|-------|----------------------|---------------------|
| Традыцыйны | *(не зададзена)* | Класічны PHP-хостынг, WordPress з пафайлавай маршрутызацыяй |
| Фрэймворк | `index.php` | Laravel, Symfony або любы фрэймворк з франт-кантролерам |
| SPA | `index.html` | React, Vue, Angular з кліенцкай маршрутызацыяй |

### Традыцыйны рэжым

Калі `INDEX_FILE` не зададзена, OxPHP супастаўляе URL непасрэдна з файламі на дыску.

- `/style.css` аддае `DOCUMENT_ROOT/style.css`
- `/about.php` выконвае `DOCUMENT_ROOT/about.php`
- `/` вяртае `index.php`, калі ён існуе, інакш `index.html`
- `/subdir/` спрабуе `subdir/index.php`, потым `subdir/index.html`
- Адсутныя файлы вяртаюць 404

```bash
# INDEX_FILE не зададзена -- традыцыйны рэжым па змаўчанні
DOCUMENT_ROOT=/var/www/html
```

### Рэжым фрэймворка

Калі `INDEX_FILE=index.php`, усе запыты, якія не супадаюць з існуючым статычным файлам, накіроўваюцца да франт-кантролера.

- `/style.css` аддае статычны файл непасрэдна
- `/api/users` выконвае `index.php` (файл не існуе на дыску)
- `/about.php` вяртае 404 (прамы доступ да `.php` заблакіраваны)
- `/index.php` вяртае 404 (прамы доступ да індэкснага файла заблакіраваны)

```bash
INDEX_FILE=index.php
DOCUMENT_ROOT=/var/www/html
```

Блакіроўка прамога доступу да `.php` прадухіляе ўцечкі URL і забяспечвае праходжанне ўсіх PHP-запытаў праз маршрутызатар фрэймворка.

### Рэжым SPA

Калі `INDEX_FILE=index.html`, адсутныя шляхі перанакіроўваюцца на HTML-кропку ўваходу. PHP-файлы па-ранейшаму выконваюцца нармальна.

- `/style.css` аддае статычны файл
- `/app/dashboard` аддае `index.html` (кліенцкі маршрутызатар апрацоўвае запыт)
- `/api.php` выконвае PHP-скрыпт
- `/index.html` вяртае 404 (прамы доступ да індэкснага файла заблакіраваны)

```bash
INDEX_FILE=index.html
DOCUMENT_ROOT=/var/www/html
```

## Вызначэнне каранёвага шляху

Запыты да `/` выкарыстоўваюць загадзя вылічаныя шляхі, каб пазбегнуць алакацый пры кожным запыце. Сервер спачатку правярае наяўнасць `index.php`, потым `index.html`. Калі ні адзін з іх не існуе, вяртаецца 404.

Шляхі да паддырэкторый з завяршальным слэшам (напрыклад, `/blog/`) выкарыстоўваюць такое ж вызначэнне індэкснага файла: спачатку `index.php`, потым `index.html`.

## Санітарызацыя шляхоў

Кожны ўваходны URI-шлях праходзіць праз канвеер санітарызацыі перад доступам да файлавай сістэмы:

1. **Працэнтнае дэкадаванне** -- `%2e%2e` дэкадуецца ў `..` перад тым, як санітарызацыя яго перахопіць
2. **Фільтрацыя сегментаў** -- `..`, `.` і пустыя сегменты выдаляюцца
3. **Праверка сімвалічных спасылак** -- вызначаныя шляхі правяраюцца адносна кананічнага кораня дакументаў

Запыт накшталт `/%2e%2e/etc/passwd` дэкадуецца ў `/../etc/passwd`, санітарызуецца да `etc/passwd`, а потым правяраецца адносна мяжы кораня дакументаў.

## Абарона ад выхаду праз сімвалічныя спасылкі

Пры запуску OxPHP кананізуе шлях кораня дакументаў. Кожны вызначаны шлях да файла кананізуецца і правяраецца, каб пераканацца, што ён застаецца ў межах кораня дакументаў. Гэта блакуе сімвалічныя спасылкі, якія паказваюць за межы каталога, які абслугоўваецца.

Вынікі кананізацыі шляхоў кэшуюцца, каб пазбегнуць паўторных сістэмных выклікаў `realpath(3)`. Кэш кананічных шляхоў мае тую ж ёмістасць у 200 запісаў, што і кэш метаданых, але захоўваецца і выцясняецца незалежна ва ўласным HashMap.

Калі корань дакументаў не можа быць кананізаваны пры запуску (напрыклад, каталог яшчэ не існуе), абарона ад сімвалічных спасылак адключаецца і запісваецца папярэджанне.

### Змякчэнне TOCTOU

Кэш маршрутаў кэшуе правераныя запісы `RouteResult`. Паўторная кананізацыя TOCTOU пры кожным запыце выконваецца ў `static_file::serve()`, непасрэдна перад чытаннем з дыска, а не на ўзроўні маршрутызацыі. Гэта змякчае атакі тыпу time-of-check-to-time-of-use, калі сімвалічная спасылка падмяняецца паміж вызначэннем маршруту і чытаннем файла.

## Канфігурацыя

| Зменная | Апісанне | Змаўчанне |
|---------|---------|-----------|
| `DOCUMENT_ROOT` | Шлях у файлавай сістэме для аддачы файлаў | `/var/www/html` |
| `INDEX_FILE` | Імя індэкснага файла, кіруе рэжымам маршрутызацыі | *(не зададзена)* |
