OxPHP аддае статычныя файлы непасрэдна з кораня дакументаў з аўтаматычным вызначэннем MIME-тыпаў, трохузроўневым LRU-кэшам, HTTP-кэшаваннем (ETag / Last-Modified / 304) і струменевай перадачай вялікіх файлаў.

## Вызначэнне MIME-тыпаў

MIME-тыпы вызначаюцца па пашырэнні файла з дапамогай крэйта `mime_guess`. Калі тып не можа быць вызначаны, сервер выкарыстоўвае `application/octet-stream`. Тыповыя супастаўленні ўключаюць:

| Пашырэнне | Content-Type |
|-----------|-------------|
| `.html` | `text/html` |
| `.css` | `text/css` |
| `.js` | `application/javascript` |
| `.json` | `application/json` |
| `.png` | `image/png` |
| `.svg` | `image/svg+xml` |
| `.woff2` | `font/woff2` |

## Файлавы кэш

Файлавы кэш зніжае колькасць сістэмных выклікаў да файлавай сістэмы падчас маршрутызацыі і аддачы. Ён выкарыстоўвае `RwLock<FileCacheInner>`, які ахоплівае тры асобныя HashMap (кэшы метаданых, змесціва і кананічных шляхоў), з LRU-выцясненнем на аснове лічыльніка і працуе на трох узроўнях:

### Кэш метаданых

Захоўвае інфармацыю аб тым, ці з'яўляецца шлях файлам, каталогам, ці не існуе. Маршрутызатар правярае гэты кэш пры кожным запыце, каб вызначыць, ці трэба аддаць файл, выканаць скрыпт або вярнуць 404 без звароту да файлавай сістэмы.

- Ёмістасць: 200 запісаў (наладжваецца пры кампіляцыі)
- Выцясненне: LRU па лічыльніку доступу
- Промах кэша выклікае асінхронны выклік `tokio::fs::metadata()`

### Кэш змесціва

Захоўвае поўны змест невялікіх файлаў, каб паўторныя запыты абслугоўваліся з памяці без дыскавага ўводу-вываду.

- Максімум на файл: 1 МБ
- Агульны бюджэт кэша: 64 МБ
- Выцясненне: LRU, калі агульны аб'ём перавышае бюджэт
- Даныя захоўваюцца як `Bytes` (з падлікам спасылак, нулявое капіраванне)
- MIME-тып захоўваецца побач са змесцівам як `Arc<str>`

Файлы большыя за 1 МБ ніколі не кэшуюцца і заўсёды перадаюцца струменева з дыска.

### Кэш кананічных шляхоў

Захоўвае вынікі выклікаў `canonicalize()`, якія выкарыстоўваюцца для абароны ад выхаду праз сімвалічныя спасылкі. Гэта дазваляе пазбегнуць паўторных сістэмных выклікаў `realpath(3)` для тых самых шляхоў.

- Падзяляе тую ж ёмістасць у 200 запісаў з кэшам метаданых
- Захоўвае `Option<PathBuf>` -- `None` азначае, што файл не існаваў на момант кэшавання
- Выцясненне: LRU па лічыльніку доступу

## HTTP-кэшаванне

OxPHP падтрымлівае HTTP-кэшаванне для статычных файлаў з валідацыяй ETag і ўмоўнымі запытамі, кіраванае зменнай асяроддзя `STATIC_CACHE_TTL`.

### Канфігурацыя

| Зменная | Па змаўчанні | Апісанне |
|----------|---------|-------------|
| `STATIC_CACHE_TTL` | `30d` | TTL кэша для статычных файлаў. Падтрымлівае гнуткія фарматы працягласці або `off` для адключэння |

Падтрымліваемыя фарматы працягласці:

| Фармат | Прыклад | Секунды |
|--------|---------|---------|
| Секунды | `30s` | 30 |
| Хвіліны | `5m` | 300 |
| Гадзіны | `2h` | 7,200 |
| Дні | `30d` | 2,592,000 |
| Тыдні | `1w` | 604,800 |
| Гады | `1y` | 31,536,000 |
| Голы лік | `3600` | 3,600 |
| Адключана | `off` | *(без загалоўкаў кэшавання)* |

### Загалоўкі адказу

Калі кэшаванне ўключана, кожны адказ са статычным файлам уключае:

| Загаловак | Значэнне | Прыклад |
|--------|-------|---------|
| `Cache-Control` | `public, max-age={ttl}` | `public, max-age=2592000` |
| `ETag` | Слабы ETag з памеру файла і mtime | `W/"1024-65a1b2c3"` |
| `Last-Modified` | HTTP-дата па RFC 7231 | `Tue, 14 Nov 2023 18:13:20 GMT` |

### Умоўныя запыты (304 Not Modified)

Калі кліент адпраўляе загалоўкі `If-None-Match` або `If-Modified-Since`, OxPHP валідуе іх адносна бягучых метаданых файла:

1. **If-None-Match** мае прыярытэт (згодна з RFC 7232 §3.3). ETag параўноўваецца са спісам тэгаў, раздзеленых коскамі. Значэнне `*` заўсёды супадае.
2. **If-Modified-Since** правяраецца як рэзервны варыянт. Час мадыфікацыі файла (абрэзаны да сэкунднай дакладнасці) параўноўваецца са значэннем загалоўка.

Калі файл не змяніўся, OxPHP вяртае адказ `304 Not Modified` з загалоўкамі `ETag`, `Last-Modified` і `Cache-Control`, але без цела. Гэтая праверка выконваецца **да** любога файлавага ўводу-вываду:

- Для **закэшаваных файлаў**: умоўная праверка выконваецца пад блакіроўкай чытання без кланавання якіх-небудзь дадзеных
- Для **незакэшаваных файлаў**: умоўная праверка выконваецца пасля `fs::metadata()`, але да `fs::read()`, пазбягаючы чытання з дыска для нязмененых файлаў

### Фармат ETag

ETag выкарыстоўвае слабы фармат `W/"<size>-<mtime_hex>"`, дзе:

- `<size>` -- памер файла ў байтах (дзесятковы)
- `<mtime_hex>` -- Unix-часовая пазнака апошняй мадыфікацыі (шаснаццатковы ў ніжнім рэгістры)

Слабыя ETag паказваюць семантычную эквівалентнасць — адказ можа адрознівацца на ўзроўні байтаў (напрыклад, пасля Brotli-кампрэсіі), але прадстаўляе той самы кантэнт.

### Адключэнне кэшавання

Усталюйце `STATIC_CACHE_TTL=off`, каб адключыць усе загалоўкі кэшавання. Загалоўкі `Cache-Control`, `ETag` і `Last-Modified` не будуць адпраўляцца, і ўмоўныя запыты не будуць апрацоўвацца.

## Паводзіны пры аддачы

Калі паступае запыт на статычны файл:

1. **Умоўная праверка (кэш)** -- калі файл знаходзіцца ў кэшы змесціва і мае супадаючыя ўмоўныя загалоўкі, неадкладна вяртаецца 304
2. **Праверка кэша змесціва** -- калі файл закэшаваны, ён вяртаецца з захаваным MIME-тыпам і загалоўкамі кэшавання
3. **Вызначэнне MIME-тыпу** -- тып змесціва вылічаецца па пашырэнні файла
4. **Паўторная праверка TOCTOU** -- калі абарона ад сімвалічных спасылак уключана, шлях паўторна кананізуецца перад чытаннем
5. **Метаданыя + умоўная праверка (без кэша)** -- чытаюцца метаданыя файла; калі ўмоўныя загалоўкі супадаюць, вяртаецца 304 да чытання файла
6. **Праверка памеру** -- вызначаецца стратэгія аддачы на аснове памеру файла

### Невялікія файлы (да 1 МБ)

Увесь файл чытаецца ў памяць з дапамогай `tokio::fs::read()`, устаўляецца ў кэш змесціва і вяртаецца як буферызаванае цела адказу. Загаловак `Content-Length` усталёўваецца ў дакладную колькасць байтаў.

### Вялікія файлы (больш за 1 МБ)

Файл адкрываецца з дапамогай `tokio::fs::File::open()` і перадаецца кліенту струменева праз `ReaderStream`. Загаловак `Content-Length` усталёўваецца з метаданых файла, каб кліент ведаў агульны памер.

## Загалоўкі адказу

Кожны адказ са статычным файлам уключае:

| Загаловак | Значэнне |
|-----------|---------|
| `Content-Type` | Вызначаны MIME-тып |
| `Content-Length` | Памер файла ў байтах |
| `Cache-Control` | `public, max-age={ttl}` *(калі кэшаванне ўключана)* |
| `ETag` | `W/"<size>-<mtime_hex>"` *(калі кэшаванне ўключана)* |
| `Last-Modified` | HTTP-дата па RFC 7231 *(калі кэшаванне ўключана)* |

## Апрацоўка памылак

- **Файл не знойдзены**: вяртае 404 з тэкставым целам
- **Памылкі дазволаў**: перадаюцца як памылка 500
- **Збоі чытання пасля праверкі метаданых**: вяртае 404 (файл мог быць выдалены паміж праверкай і чытаннем)
