OxPHP аддае статычныя файлы непасрэдна з кораня дакументаў з аўтаматычным вызначэннем MIME-тыпаў, трохузроўневым LRU-кэшам і струменевай перадачай вялікіх файлаў.

## Вызначэнне MIME-тыпаў

MIME-тыпы вызначаюцца па пашырэнні файла з дапамогай крэйта `mime_guess`. Калі тып не можа быць вызначаны, сервер выкарыстоўвае `application/octet-stream`. Тыповыя супастаўленні ўключаюць:

| Пашырэнне | Content-Type |
|-----------|-------------|
| `.html` | `text/html` |
| `.css` | `text/css` |
| `.js` | `application/javascript` |
| `.json` | `application/json` |
| `.png` | `image/png` |
| `.svg` | `image/svg+xml` |
| `.woff2` | `font/woff2` |

## Файлавы кэш

Файлавы кэш зніжае колькасць сістэмных выклікаў да файлавай сістэмы падчас маршрутызацыі і аддачы. Ён выкарыстоўвае `Mutex<HashMap>` з LRU-выцясненнем на аснове лічыльніка і працуе на трох узроўнях:

### Кэш метаданых

Захоўвае інфармацыю аб тым, ці з'яўляецца шлях файлам, каталогам, ці не існуе. Маршрутызатар правярае гэты кэш пры кожным запыце, каб вызначыць, ці трэба аддаць файл, выканаць скрыпт або вярнуць 404 без звароту да файлавай сістэмы.

- Ёмістасць: 200 запісаў (наладжваецца пры кампіляцыі)
- Выцясненне: LRU па лічыльніку доступу
- Промах кэша выклікае асінхронны выклік `tokio::fs::metadata()`

### Кэш змесціва

Захоўвае поўны змест невялікіх файлаў, каб паўторныя запыты абслугоўваліся з памяці без дыскавага ўводу-вываду.

- Максімум на файл: 1 МБ
- Агульны бюджэт кэша: 64 МБ
- Выцясненне: LRU, калі агульны аб'ём перавышае бюджэт
- Даныя захоўваюцца як `Bytes` (з падлікам спасылак, нулявое капіраванне)
- MIME-тып захоўваецца побач са змесцівам як `Arc<str>`

Файлы большыя за 1 МБ ніколі не кэшуюцца і заўсёды перадаюцца струменева з дыска.

### Кэш кананічных шляхоў

Захоўвае вынікі выклікаў `canonicalize()`, якія выкарыстоўваюцца для абароны ад выхаду праз сімвалічныя спасылкі. Гэта дазваляе пазбегнуць паўторных сістэмных выклікаў `realpath(3)` для тых самых шляхоў.

- Падзяляе тую ж ёмістасць у 200 запісаў з кэшам метаданых
- Захоўвае `Option<PathBuf>` -- `None` азначае, што файл не існаваў на момант кэшавання
- Выцясненне: LRU па лічыльніку доступу

## Паводзіны пры аддачы

Калі паступае запыт на статычны файл:

1. **Праверка кэша змесціва** -- калі файл закэшаваны, ён вяртаецца неадкладна з захаваным MIME-тыпам
2. **Вызначэнне MIME-тыпу** -- тып змесціва вылічаецца па пашырэнні файла
3. **Паўторная праверка TOCTOU** -- калі абарона ад сімвалічных спасылак уключана, шлях паўторна кананізуецца перад чытаннем
4. **Праверка памеру** -- чытаюцца метаданыя файла для вызначэння стратэгіі аддачы

### Невялікія файлы (да 1 МБ)

Увесь файл чытаецца ў памяць з дапамогай `tokio::fs::read()`, устаўляецца ў кэш змесціва і вяртаецца як буферызаванае цела адказу. Загаловак `Content-Length` усталёўваецца ў дакладную колькасць байтаў.

### Вялікія файлы (больш за 1 МБ)

Файл адкрываецца з дапамогай `tokio::fs::File::open()` і перадаецца кліенту струменева праз `ReaderStream`. Загаловак `Content-Length` усталёўваецца з метаданых файла, каб кліент ведаў агульны памер.

## Загалоўкі адказу

Кожны адказ са статычным файлам уключае:

| Загаловак | Значэнне |
|-----------|---------|
| `Content-Type` | Вызначаны MIME-тып |
| `Content-Length` | Памер файла ў байтах |

## Апрацоўка памылак

- **Файл не знойдзены**: вяртае 404 з тэкставым целам
- **Памылкі дазволаў**: перадаюцца як памылка 500
- **Збоі чытання пасля праверкі метаданых**: вяртае 404 (файл мог быць выдалены паміж праверкай і чытаннем)
