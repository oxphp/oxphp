Планіроўшчык файбераў OxPHP дазваляе кожнаму патоку PHP-воркера апрацоўваць некалькі адначасовых HTTP-запытаў. Калі запыт выклікае кропку прыпынку, напрыклад `oxphp_async_await()` або `oxphp_sleep()`, файбер перадае кіраванне, і воркер падхоплівае іншыя запыты замест блакіроўкі.

## Як гэта працуе

Кожны HTTP-запыт выконваецца ва ўласным файберы (`zend_fiber_context` з нізкаўзроўневага Fiber API PHP 8.4). C-стэк файбера выдзяляецца адзін раз праз `mmap` і паўторна выкарыстоўваецца паміж запытамі праз **цыклічную карутыну** — карутына апрацоўвае запыты ў цыкле, прыпыняючыся паміж кожным. Гэта пазбягае накладных выдаткаў `mmap`/`munmap` пры кожным запыце.

Паток воркера запускае цыкл падзей, які:

1. **Прымае новыя запыты** з абмежаванага канала (неблакіруючы `try_recv`)
2. **Правярае завершаныя асінхронныя вынікі** для файбераў, якія чакаюць на `oxphp_async_await()`
3. **Правярае скончаныя таймеры** для файбераў, якія чакаюць на `oxphp_sleep()` / `oxphp_usleep()`
4. **Узнаўляе гатовыя файберы**, аднаўляючы іх стан і пераключаючыся на іх кантэкст файбера

Кожны файбер мае ўласны ізаляваны стан:
- **Стан PHP VM**: `EG(vm_stack)`, `EG(execute_data)`, `EG(bailout)` — захоўваецца і аднаўляецца пры кожным пераключэнні кантэксту
- **Суперглабалы PHP**: `$_SERVER`, `$_GET`, `$_POST` і інш. — перамяшчаюцца (не капіруюцца) паміж TLS і сховішчам файбера
- **Загалоўкі SAPI**: загалоўкі адказу і HTTP-код стану
- **Абмежаванні C-стэка**: `EG(stack_base)` / `EG(stack_limit)` — усталёўваюцца для кожнага файбера, каб прадухіліць ілжывае вызначэнне перапаўнення стэка
- **Rust TLS**: буфер вываду адказу, EARLY_TX (канал адказу), час пачатку запыту

З пункту гледжання PHP-скрыпту выкананне бесперапыннае — прыпынак і ўзнаўленне нябачныя.

### Паслядоўныя запыты (без мультыплексавання)

Калі апрацоўшчык запыту завяршаецца без выкліку якой-небудзь кропкі прыпынку, цыклічная карутына апрацоўвае яго і неадкладна чакае наступнага запыту. Толькі адзін файбер актыўны, і яго C-стэк паўторна выкарыстоўваецца для кожнага запыту. Прадукцыйнасць эквівалентна цыклу воркера да файбераў — без дадатковага `mmap`, без захавання/аднаўлення стану, без апытвання цыклу падзей.

### Мультыплексаваныя запыты

Калі апрацоўшчык выклікае кропку прыпынку, файбер прыпыняецца і планіроўшчык уваходзіць у цыкл падзей. Цыкл падзей прымае новыя запыты (ствараючы дадатковыя файберы па неабходнасці) і ўзнаўляе файберы, умовы прыпынку якіх выкананы. Кожны дадатковы файбер выдзяляе ўласны C-стэк (адзін раз) і паўторна выкарыстоўвае яго праз цыклічную карутыну.

```
Worker Thread
===========================
                          ┌─ try_recv ──► new request? ──► create/reuse fiber, start handler
                          │
loop ─────────────────────┤─ poll awaits ► result ready? ─► resume waiting fiber
                          │
                          └─ poll timers ► timer expired? ► resume sleeping fiber

                          (fibers that complete are finalized and their response is sent)
```

## Кропкі прыпынку

Наступныя функцыі выклікаюць прыпынак файбера пры выкліку ўнутры апрацоўшчыка воркера:

| Функцыя | Паводзіны |
|----------|----------|
| `oxphp_async_await(int $promise_id, ?float $timeout = null)` | Прыпыняецца да завяршэння асінхроннай задачы або тайм-аўту |
| `oxphp_async_await_all(array $promise_ids, ?float $timeout = null)` | Адкат да блакіроўкі ў v1 (файбер-сумяшчальнасць у будучым рэлізе) |
| `oxphp_async_await_any(array $promise_ids, ?float $timeout = null)` | Адкат да блакіроўкі ў v1 (файбер-сумяшчальнасць у будучым рэлізе) |
| `oxphp_sleep(float $seconds)` | Прыпыняецца на зададзены час (кааператыўна) |
| `oxphp_usleep(int $microseconds)` | Прыпыняецца на зададзены час у мікрасекундах (кааператыўна) |

Калі гэтыя функцыі выклікаюцца па-за файберам (традыцыйны рэжым), яны адкатваюцца да іх блакіруючых аналагаў.

## Канфігурацыя

Мультыплексаванне файбераў аўтаматычнае, калі ўключаны рэжым воркера. Дадатковыя зменныя асяроддзя не патрэбныя.

| Канстанта | Значэнне | Апісанне |
|----------|-------|-------------|
| `OXPHP_MAX_FIBERS` | `256` | Максімальная колькасць адначасовых файбераў на паток воркера (канстанта часу кампіляцыі) |

Абмежаванне файбераў прадухіляе назапашванне занадта вялікай колькасці прыпыненых запытаў адным воркерам. Калі абмежаванне дасягнута, цыкл падзей спыняе прыём новых запытаў, пакуль актыўны файбер не завершыцца.

### Маштабаванне з некалькімі воркерамі

Кожны паток PHP-воркера запускае свой уласны незалежны планіроўшчык файбераў. Увесь стан (файберы, таймеры, TLS-слоты) — лакальны для патоку. Некалькі воркераў маштабуюцца лінейна:

| Воркеры | `/bench` (req/s) | `/sleep?ms=20` c40 (req/s) |
|---------|------------------|---------------------------|
| 1 | 40,144 | 867 |
| 2 | 66,619 | 1,378 |

Усталюйце `PHP_WORKERS=N` для кіравання колькасцю патокаў воркераў. Па змаўчанні: `CPU / 2`.

## PHP API

### `oxphp_sleep`

Кааператыўны сон, які прыпыняе бягучы файбер, дазваляючы воркеру апрацоўваць іншыя запыты падчас чакання.

```php
oxphp_sleep(float $seconds): void
```

**Параметры:**

| Імя | Тып | Апісанне |
|------|------|-------------|
| `$seconds` | `float` | Працягласць сну ў секундах (напрыклад, `0.5` для 500мс) |

**Паводзіны:**
- У рэжыме воркера: рэгіструе таймер і прыпыняе файбер. Планіроўшчык узнаўляе яго пасля ўказанай працягласці.
- Па-за рэжымам воркера: адкатваецца да блакіруючага `usleep()`.
- Значэнні, роўныя нулю або адмоўныя, вяртаюцца неадкладна без эфекту.

### `oxphp_usleep`

Кааператыўны мікрасекундны сон. Ідэнтычны `oxphp_sleep()`, але прымае мікрасекунды як цэлы лік, у адпаведнасці з убудаваным PHP `usleep()`.

```php
oxphp_usleep(int $microseconds): void
```

**Параметры:**

| Імя | Тып | Апісанне |
|------|------|-------------|
| `$microseconds` | `int` | Працягласць сну ў мікрасекундах |

**Паводзіны:** Такія ж, як у `oxphp_sleep()`, але з мікрасекунднай дакладнасцю. Значэнні, роўныя нулю або адмоўныя, вяртаюцца неадкладна.

## Зваротная сумяшчальнасць

Мультыплексаванне файбераў цалкам зваротна сумяшчальнае:

- **Апрацоўшчыкі, якія не выклікаюць кропкі прыпынку**, выконваюцца праз цыклічную карутыну без дадатковых накладных выдаткаў. C-стэк файбера паўторна выкарыстоўваецца, захаванне/аднаўленне стану не адбываецца. Прадукцыйнасць эквівалентна цыклу воркера да файбераў.
- **`oxphp_sleep()` і `oxphp_usleep()` па-за рэжымам воркера** адкатваюцца да блакіруючага `usleep()`.
- **`oxphp_async_await()` па-за файберам** адкатваецца да блакіроўкі на oneshot-канале.
- **Новыя зменныя асяроддзя не патрэбныя.**
- **Канфігурацыі з некалькімі воркерамі** працуюць ідэнтычна — кожны воркер мае ўласны незалежны планіроўшчык файбераў.

## Абмежаванні (v1)

- **`ob_start()` з карыстальніцкімі callback-функцыямі** можа паводзіць сябе нечакана праз кропкі прыпынку. Буферы вываду скідваюцца ў буфер адказу Rust пры прыпынку, таму карыстальніцкія OB-callback-функцыі бачаць частковы вывад на межах прыпынку.
- **Агульныя зменлівыя зменныя замыканняў** (`use (&$var)`) падвяргаюцца чаргаванню на кропках прыпынку. Паміж двума кропкамі прыпынку ваш код выконваецца без перапынку. На кожнай кропцы прыпынку іншыя запыты могуць выконвацца на тым жа воркеры. Гэта тая ж мадэль канкурэнтнасці, што і `async`/`await` у Node.js.
- **`oxphp_async_await_all` і `oxphp_async_await_any`** адкатваюцца да блакіроўкі ў рэжыме файбераў (v1). У будучым рэлізе будуць дададзены файбер-сумяшчальныя рэалізацыі.
- **Максімум 256 адначасовых файбераў на воркер.** Гэта канстанта часу кампіляцыі (`OXPHP_MAX_FIBERS`).
- **REQUEST_DATA** (зменныя сервера, кукі, цела запыту) пакуль не захоўваюцца/аднаўляюцца для кожнага файбера. Калі актыўныя некалькі файбераў, яны разалоўваюць апошнія загружаныя даныя запыту. Гэта ўплывае на `$_SERVER`, `$_GET`, `$_POST` пасля кропкі прыпынку ў сцэнарыях мультыплексавання.

## Прыклад

### SSE з кааператыўным сном

Гэты прыклад стрымінгуе Server-Sent Events, перадаючы паток воркера падчас затрымкі паміж падзеямі. Іншыя запыты апрацоўваюцца падчас кожнага выкліку `oxphp_sleep()`.

```php
<?php
oxphp_worker(function() {
    header('Content-Type: text/event-stream');
    header('Cache-Control: no-cache');

    for ($i = 0; $i < 10; $i++) {
        echo "data: " . json_encode(['counter' => $i]) . "\n\n";
        oxphp_stream_flush();
        oxphp_sleep(1.0); // yields fiber, worker handles other requests
    }

    echo "event: done\ndata: {}\n\n";
    oxphp_stream_flush();
});
```

### Async await з мультыплексаваннем

Калі `oxphp_async_await()` прыпыняе файбер, воркер апрацоўвае іншыя HTTP-запыты, чакаючы асінхроннага выніку:

```php
<?php
oxphp_worker(function() {
    $config = ['dsn' => 'mysql:host=localhost;dbname=app', 'user' => 'root', 'pass' => ''];

    // Dispatch async task
    $promise = oxphp_async(function() use ($config): array {
        $pdo = new PDO($config['dsn'], $config['user'], $config['pass']);
        return $pdo->query('SELECT count(*) as c FROM users')->fetch();
    });

    // Fiber suspends here — worker handles other requests
    $result = oxphp_async_await($promise);

    header('Content-Type: application/json');
    echo json_encode($result);
});
```
