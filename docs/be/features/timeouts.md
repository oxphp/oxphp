title: Тайм-аўты

OxPHP прымяняе наладжвальныя тайм-аўты для абароны ад павольных кліентаў і неабмежаваных запытаў. Кожны тайм-аўт наладжваецца праз пераменную асяроддзя.

## Канфігурацыя

| Пераменная | Апісанне | Па змаўчанні |
|------------|----------|--------------|
| `HEADER_TIMEOUT_SECS` | Максімальны час для атрымання HTTP-загалоўкаў пасля TCP-злучэння | `5` |
| `IDLE_TIMEOUT_SECS` | Максімальны час прастою паміж запытамі на keep-alive злучэнні | `60` |
| `REQUEST_TIMEOUT_SECS` | Максімальны агульны час апрацоўкі запыту (уключаючы выкананне PHP) | `120` |

```bash
HEADER_TIMEOUT_SECS=5
IDLE_TIMEOUT_SECS=60
REQUEST_TIMEOUT_SECS=120
```

Усталяванне `HEADER_TIMEOUT_SECS=0` прапускае рэгістрацыю тайм-аўту чытання загалоўкаў у hyper. Усталяванне `REQUEST_TIMEOUT_SECS=0` цалкам адключае тайм-аўт запыту.

## Тыпы тайм-аўтаў

### Тайм-аўт чытання загалоўкаў

Кантралюе, як доўга сервер чакае, пакуль кліент адправіць поўны набор HTTP-загалоўкаў пасля ўсталявання TCP-злучэння (або пасля завяршэння TLS-рукапаціскання).

Гэта абараняе ад атак тыпу slowloris, калі кліент адпраўляе загалоўкі па адным байце, каб утрымліваць злучэнне адкрытым бясконца.

**Заўвага па рэалізацыі**: hyper-util патрабуе рэгістрацыі таймера з дапамогай `builder.http1().timer(TokioTimer::new())` перад тым, як можна ўсталяваць `header_read_timeout`. OxPHP заўсёды рэгіструе гэты таймер. Калі тайм-аўт усталяваны ў нуль, выклік `header_read_timeout` прапускаецца.

### Тайм-аўт прастою

Зарэзерваваны для кантролю таго, як доўга keep-alive злучэнне можа заставацца неактыўным паміж запытамі. Пераменная `IDLE_TIMEOUT_SECS` чытаецца з асяроддзя і ўключаецца ў ўнутраную канчатковую кропку `/config`, але канструктар HTTP/1.1 hyper-util не прадастаўляе наладку `keep_alive_timeout`. Гэты тайм-аўт у цяперашні час не прымяняецца на ўзроўні злучэння.

### Тайм-аўт запыту

Кантралюе максімальны агульны час апрацоўкі аднаго запыту, ад вызначэння маршруту праз выкананне PHP, пабудову адказу і сціск. Рэалізаваны як абгортка `tokio::time::timeout` вакол канвеера дыспетчарызацыі. Гэта прымяняецца як да звычайнага выканання скрыптоў, так і да запытаў у рэжыме апрацоўшчыка.

Калі тайм-аўт спрацоўвае, сервер вяртае адказ `504 Gateway Timeout` з запісам папярэджання ў журнале, які ўключае ідэнтыфікатар запыту і шлях.

Для PHP-запытаў тайм-аўт запыту з'яўляецца знешняй мяжой. PHP-наладка `max_execution_time` можа спрацаваць раней, але тайм-аўт запыту гарантуе вызваленне рэсурсаў на баку сервера, нават калі PHP не выконвае ўласнае абмежаванне часу.

## Узаемадзеянне тайм-аўтаў

Тайм-аўт чытання загалоўкаў і тайм-аўт запыту пакрываюць розныя фазы запыту:

```
TCP connect (+ TLS handshake if enabled)
  |
  +-- [HEADER_TIMEOUT_SECS] --> headers received
  |                               |
  |                               +-- [REQUEST_TIMEOUT_SECS] --> response sent
  |                                                                |
  |                                                                +-- next request or close
  |                                                                     |
  |                                                                     +-- [HEADER_TIMEOUT_SECS] --> ...
```

На keep-alive злучэнні тайм-аўт загалоўкаў і тайм-аўт запыту прымяняюцца да кожнага запыту індывідуальна.

## Рэкамендаваныя значэнні

| Сцэнарый | Загалоўкі | Запыт |
|----------|-----------|-------|
| Агульнае вэб-абслугоўванне | 5 с | 120 с |
| API-сервер | 3 с | 30 с |
| Доўгія PHP-задачы | 5 с | 300 с |
| Высокая бяспека / анты-slowloris | 2 с | 30 с |

Наладжвайце гэтыя значэнні ў залежнасці ад характарыстык вашага прыкладання. Калі вашы PHP-скрыпты выконваюць працяглыя аперацыі (генерацыя справаздач, імпарт дадзеных), павялічце тайм-аўт запыту адпаведна.
