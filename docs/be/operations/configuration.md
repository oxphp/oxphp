---
title: Канфігурацыя
description: Поўная даведка па зменных асяроддзя для OxPHP
---

OxPHP канфігуруецца цалкам праз зменныя асяроддзя. Файлы канфігурацыі адсутнічаюць. Кожная зменная мае разумнае значэнне па змаўчанні, таму разгортванне без канфігурацыі працуе адразу для распрацоўкі.

## Даведка па зменных асяроддзя

### Сервер

| Зменная | Па змаўчанні | Апісанне |
|----------|---------|-------------|
| `LISTEN_ADDR` | `0.0.0.0:8080` | Адрас і порт для асноўнага HTTP-сервера |
| `DOCUMENT_ROOT` | `/var/www/html/public` | Каранёвы каталог для абслугоўвання файлаў і PHP-скрыптоў |
| `INDEX_FILE` | *(пуста)* | Кантралюе рэжым маршрутызацыі. Глядзіце [Рэжымы маршрутызацыі](#рэжымы-маршрутызацыі) |
| `TOKIO_WORKERS` | `0` (CPU / 2, мін. 1) | Патокі асінхроннага ўводу-вываду Tokio. `0` = аўтавызначэнне (CPU / 2, мінімум 1), `1` = аднапатоковы рантайм, `N` = шматпатоковы рантайм з N працоўнымі патокамі |
| `MAX_CONNECTIONS` | `10000` | Максімальная колькасць адначасовых TCP-злучэнняў. Новыя злучэнні звыш гэтага ліміту чакаюць дазволу семафора |

### Выкананне PHP

| Зменная | Па змаўчанні | Апісанне |
|----------|---------|-------------|
| `EXECUTOR` | `sapi` | Тып PHP-выканаўцы. `sapi` для рэальнага выканання PHP, `stub` для адказу-заглушкі (бенчмаркі) |
| `PHP_WORKERS` | `0` (CPU / 2, мін. 1, статычна) | Рэжым пула воркераў. Усталюйце `N` для фіксаванага пула або `MIN:MAX` для дынамічнага маштабавання. Глядзіце [Рэжымы воркераў](#рэжымы-воркераў) |
| `PHP_WORKERS_IDLE_SECONDS` | `30` | Секунды, на працягу якіх дынамічны воркер павінен быць бяздзейным перад спісаннем. Ужываецца толькі ў дынамічным рэжыме |
| `QUEUE_CAPACITY` | `PHP_WORKERS * 128` | Максімальная колькасць запытаў, якія чакаюць у чарзе PHP. Калі чарга поўная, новыя PHP-запыты атрымліваюць адказ `529 Site is overloaded`. Выкарыстоўвае пачатковую колькасць воркераў для дынамічнага рэжыму |

### Лагіраванне

| Зменная | Па змаўчанні | Апісанне |
|----------|---------|-------------|
| `LOG_LEVEL` | `info` | Узровень дэталізацыі логаў. Адзін з: `trace`, `debug`, `info`, `warn`, `error` |
| `ACCESS_LOG` | *(выкл.)* | JSON-лог доступу: `all` (усе запыты), `error` (толькі 4xx/5xx), пустое/не зададзена = выключана |

### Тайм-аўты

| Зменная | Па змаўчанні | Апісанне |
|----------|---------|-------------|
| `HEADER_TIMEOUT_SECONDS` | `5` | Максімум секунд для чакання загалоўкаў запыту пасля TCP-злучэння |
| `REQUEST_TIMEOUT_SECONDS` | `120` | Максімум секунд для ўсяго цыклу запыт-адказ. Усталюйце `0` для адключэння |
| `DRAIN_TIMEOUT_SECONDS` | `30` | Максімум секунд для чакання завяршэння злучэнняў у апрацоўцы падчас плаўнай спынкі |

### Абмежаванне хуткасці

| Зменная | Па змаўчанні | Апісанне |
|----------|---------|-------------|
| `RATE_LIMIT` | `0` | Максімальная колькасць запытаў на IP-адрас за часовае акно. `0` адключае абмежаванне хуткасці |
| `RATE_WINDOW_SECONDS` | `60` | Працягласць акна абмежавання хуткасці ў секундах |

### TLS

| Зменная | Па змаўчанні | Апісанне |
|----------|---------|-------------|
| `TLS_CERT` | *(няма)* | Шлях да PEM-файла TLS-сертыфіката. Абодва `TLS_CERT` і `TLS_KEY` павінны быць усталяваны для ўключэння TLS |
| `TLS_KEY` | *(няма)* | Шлях да PEM-файла прыватнага TLS-ключа |

### Назіральнасць

| Зменная | Па змаўчанні | Апісанне |
|----------|---------|-------------|
| `INTERNAL_ADDR` | *(няма)* | Адрас для ўнутранага сервера (праверкі стану, метрыкі, канфігурацыя). Не запускаецца, калі не ўсталяваны |
| `ERROR_PAGES_DIR` | *(няма)* | Каталог з карыстальніцкімі HTML-файламі старонак памылак з назвамі `{status}.html` (напрыклад, `404.html`, `503.html`, `529.html`) |

### Рэжым воркера

| Зменная | Па змаўчанні | Апісанне |
|----------|---------|-------------|
| `WORKER_FILE` | *(няма)* | Шлях да PHP-скрыпту воркера (адносна `DOCUMENT_ROOT`). Калі ўсталяваны, уключае рэжым персістэнтнага воркера, дзе PHP-працэсы застаюцца жывымі паміж запытамі |
| `WORKER_MAX_REQUESTS` | `0` | Максімальная колькасць запытаў, якую воркер апрацоўвае перад рэцыклінгам. `0` адключае ліміт |
| `WORKER_MAX_MEMORY_MIB` | `0` | Максімальная памяць (у мегабайтах), якую воркер можа выкарыстоўваць перад рэцыклінгам. `0` адключае ліміт |

### Асінхронны пул

| Зменная | Па змаўчанні | Апісанне |
|----------|---------|-------------|
| `ASYNC_WORKERS` | `0` (выключана) | Колькасць выдзеленых патокаў асінхронных воркераў для `oxphp_async()`. `0` адключае асінхронны пул |
| `ASYNC_QUEUE_CAPACITY` | `ASYNC_WORKERS * 64` | Памер абмежаванага канала для чаканых асінхронных задач. Задачы адхіляюцца, калі канал поўны |

### Кэшаванне статычных файлаў

| Зменная | Па змаўчанні | Апісанне |
|----------|---------|-------------|
| `STATIC_CACHE_TTL` | `30d` | TTL кэша для адказаў са статычнымі файламі. Кіруе загалоўкамі `Cache-Control`, `ETag` і `Last-Modified`. Падтрымлівае: `30s`, `5m`, `2h`, `30d`, `1w`, `1y`, голыя секунды (`3600`) або `off` для адключэння |

### Сціск

| Зменная | Па змаўчанні | Апісанне |
|----------|---------|-------------|
| `COMPRESSION_LEVEL` | `4` | Узровень якасці сціску Brotli (0-11). `0` адключае сціск, `1`-`11` задаюць узровень якасці |

### Размеркаваная трасіроўка

| Зменная | Па змаўчанні | Апісанне |
|----------|---------|-------------|
| `TRACE_CONTEXT` | `false` | Уключыць распаўсюджванне W3C Trace Context. Разбірае ўваходныя загалоўкі `traceparent`/`tracestate`, генеруе trace ID, устаўляе ў адказы і PHP `$_SERVER`. Аўтаматычна ўключаецца, калі `OTEL_ENABLED=true` |

### OpenTelemetry (фіча `plugin-otel`)

Распаўсюджванне W3C Trace Context заўсёды даступна (без залежнасцяў). Экспарт спанаў OpenTelemetry патрабуе зборкі з `--features plugin-otel`.

| Зменная | Па змаўчанні | Апісанне |
|----------|---------|-------------|
| `OTEL_ENABLED` | `false` | Уключыць экспарт спанаў OpenTelemetry. Мяркуе `TRACE_CONTEXT=true` |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `http://localhost:4317` | Канчатковая кропка калектара OTLP |
| `OTEL_EXPORTER_OTLP_PROTOCOL` | `grpc` | Пратакол экспарту: `grpc` (порт 4317) або `http/protobuf` (порт 4318) |
| `OTEL_EXPORTER_OTLP_TIMEOUT` | `10000` | Тайм-аўт экспарту ў мілісекундах |
| `OTEL_EXPORTER_OTLP_HEADERS` | *(няма)* | Загалоўкі аўтэнтыфікацыі для хастэд-бэкендаў (`key=value,key=value`) |
| `OTEL_SERVICE_NAME` | `oxphp` | Назва сэрвісу ў экспартаваных трэйсах |
| `OTEL_SERVICE_VERSION` | *(няма)* | Версія сэрвісу ў экспартаваных трэйсах |
| `OTEL_RESOURCE_ATTRIBUTES` | *(няма)* | Атрыбуты рэсурсаў, далучаныя да кожнага спана (`key=value,key=value`) |
| `OTEL_TRACES_SAMPLER` | `parentbased_traceidratio` | Стратэгія семплінгу: `always_on`, `always_off`, `traceidratio`, `parentbased_traceidratio` |
| `OTEL_TRACES_SAMPLER_ARG` | `1.0` | Каэфіцыент семплінгу для семплераў на аснове каэфіцыента (0.0–1.0) |

## Рэжымы воркераў

Зменная `PHP_WORKERS` кантралюе, ці выкарыстоўвае пул PHP-воркераў фіксаваны памер або дынамічнае маштабаванне.

### Статычны рэжым (па змаўчанні)

Усталюйце `PHP_WORKERS` у лік (або пакіньце без значэння/`0` для аўтаматычнага вызначэння):

```bash
PHP_WORKERS=8      # Фіксавана 8 воркераў
PHP_WORKERS=0      # Аўтавызначэнне: CPU / 2 (мінімум 1)
```

Воркеры ствараюцца пры запуску і ніколі не змяняюцца. Кожны воркер выкарыстоўвае блакіруючы `recv()` з нулявымі выдаткамі CPU пры бяздзейнасці.

### Дынамічны рэжым

Усталюйце `PHP_WORKERS` у `MIN:MAX` для ўключэння аўтаматычнага маштабавання:

```bash
PHP_WORKERS=2:16       # Маштабаванне паміж 2 і 16 воркерамі
PHP_WORKERS=4:0        # 4 мінімум, аўтавызначэнне максімуму (CPU * 2)
PHP_WORKERS=0:0        # Аўтавызначэнне абодвух (CPU/4 мін (мін 1), CPU*2 макс)
```

ScaleManager працуе кожныя 500 мс і:
- **Маштабуе ўверх**, калі ўсе воркеры занятыя і пул ніжэй за MAX (затрымка 500 мс)
- **Маштабуе ўніз**, калі воркер быў бяздзейны даўжэй за `PHP_WORKERS_IDLE_SECONDS` і пул вышэй за MIN (затрымка 5 с)

Дынамічныя воркеры выкарыстоўваюць `recv_timeout(200ms)` для перыядычных праверак сцяга спынкі.

## Рэжымы маршрутызацыі

Зменная `INDEX_FILE` кантралюе, як OxPHP маршрутызуе ўваходныя запыты. Ёсць тры рэжымы:

| Рэжым | Значэнне `INDEX_FILE` | Паводзіны |
|------|-------------------|----------|
| Традыцыйны | *(пуста / не ўсталявана)* | Прамое супастаўленне файлаў. `/about.php` абслугоўвае `about.php`. `/` абслугоўвае `index.php` або `index.html`, калі прысутнічае |
| Фрэймворк | `index.php` | Усе запыты, якія не адпавядаюць файлам, маршрутызуюцца на `index.php` (франт-кантролер). Прамы доступ да `.php` заблакіраваны |
| SPA | `index.html` | Адсутнічаючыя файлы адпраўляюцца на `index.html`. `.php` файлы ўсё роўна выконваюцца нармальна |

### Традыцыйны рэжым (па змаўчанні)

URL-адрасы прама супастаўляюцца з файламі на дыску. Гэта стандартныя паводзіны для класічных PHP-праграм.

```bash
# INDEX_FILE не ўсталяваны — традыцыйны рэжым па змаўчанні
DOCUMENT_ROOT=/var/www/html/public
```

### Рэжым фрэймворка

Усе запыты праходзяць праз адзіную кропку ўваходу. Гэта стандартны шаблон для Laravel, Symfony і падобных фрэймворкаў.

```bash
INDEX_FILE=index.php
DOCUMENT_ROOT=/var/www/html/public
```

### Рэжым SPA

Статычныя рэсурсы абслугоўваюцца напрамую. Усе іншыя запыты атрымліваюць `index.html`, дазваляючы JavaScript-маршрутызатару апрацоўваць навігацыю.

```bash
INDEX_FILE=index.html
DOCUMENT_ROOT=/var/www/html/dist
```

## Прыклады канфігурацый

### Распрацоўка

```bash
LISTEN_ADDR=127.0.0.1:8080
DOCUMENT_ROOT=./www
LOG_LEVEL=debug
PHP_WORKERS=1
INTERNAL_ADDR=127.0.0.1:9090
```

### Laravel у вытворчасці (статычны пул)

```bash
LISTEN_ADDR=0.0.0.0:8080
DOCUMENT_ROOT=/var/www/html/public
INDEX_FILE=index.php
PHP_WORKERS=8
QUEUE_CAPACITY=1024
LOG_LEVEL=warn
MAX_CONNECTIONS=10000
INTERNAL_ADDR=127.0.0.1:9090
RATE_LIMIT=100
RATE_WINDOW_SECONDS=60
HEADER_TIMEOUT_SECONDS=5
REQUEST_TIMEOUT_SECONDS=60
DRAIN_TIMEOUT_SECONDS=30
COMPRESSION_LEVEL=4
STATIC_CACHE_TTL=30d
```

### Laravel у вытворчасці (дынамічны пул)

```bash
LISTEN_ADDR=0.0.0.0:8080
DOCUMENT_ROOT=/var/www/html/public
INDEX_FILE=index.php
PHP_WORKERS=4:32
PHP_WORKERS_IDLE_SECONDS=60
QUEUE_CAPACITY=512
LOG_LEVEL=warn
MAX_CONNECTIONS=10000
INTERNAL_ADDR=127.0.0.1:9090
RATE_LIMIT=100
RATE_WINDOW_SECONDS=60
HEADER_TIMEOUT_SECONDS=5
REQUEST_TIMEOUT_SECONDS=60
DRAIN_TIMEOUT_SECONDS=30
COMPRESSION_LEVEL=4
STATIC_CACHE_TTL=30d
```

### Docker Compose

```yaml
services:
  oxphp:
    image: oxphp:latest
    ports:
      - "8080:8080"
    environment:
      LISTEN_ADDR: "0.0.0.0:8080"
      DOCUMENT_ROOT: "/var/www/html/public"
      INDEX_FILE: "index.php"
      PHP_WORKERS: "4"             # Або "2:16" для дынамічнага маштабавання
      # PHP_WORKERS_IDLE_SECONDS: "30" # Тайм-аўт бяздзейнасці (толькі дынамічны рэжым)
      QUEUE_CAPACITY: "512"
      LOG_LEVEL: "info"
      INTERNAL_ADDR: "127.0.0.1:9090"
      COMPRESSION_LEVEL: "4"
      # STATIC_CACHE_TTL: "30d"       # TTL кэша статычных файлаў (па змаўчанні: 30d)
      # ASYNC_WORKERS: "4"            # Патокі асінхронных воркераў для oxphp_async() (па змаўчанні: 0 = выключана)
      # TRACE_CONTEXT: "true"         # Уключыць распаўсюджванне W3C Trace Context
      # OTEL_ENABLED: "true"          # Уключыць экспарт спанаў OpenTelemetry (мяркуе TRACE_CONTEXT=true)
    volumes:
      - ./src:/var/www/html
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://127.0.0.1:9090/health"]
      interval: 10s
      timeout: 5s
      retries: 3
```

### Рэжым воркера (персістэнтны PHP)

```bash
LISTEN_ADDR=0.0.0.0:8080
DOCUMENT_ROOT=/var/www/html/public
WORKER_FILE=../worker.php
PHP_WORKERS=8
WORKER_MAX_REQUESTS=10000
WORKER_MAX_MEMORY_MIB=128
QUEUE_CAPACITY=1024
LOG_LEVEL=warn
INTERNAL_ADDR=127.0.0.1:9090
```

Рэжым воркера падтрымлівае PHP-працэсы жывымі паміж запытамі. Скрыпт воркера выклікае `oxphp_worker()` з callback-апрацоўшчыкам. Воркеры аўтаматычна перазапускаюцца, калі дасягаюць `WORKER_MAX_REQUESTS` або `WORKER_MAX_MEMORY_MIB`. Усталюйце абодва ў `0`, каб адключыць рэцыклінг.

### Тэрмінацыя TLS

```bash
LISTEN_ADDR=0.0.0.0:443
TLS_CERT=/etc/oxphp/tls/cert.pem
TLS_KEY=/etc/oxphp/tls/key.pem
```

OxPHP выкарыстоўвае rustls для TLS, таму залежнасці ад OpenSSL няма. Сертыфікат і ключ павінны быць у фармаце PEM.

## Інспекцыя актыўнай канфігурацыі

Калі ўнутраны сервер працуе, вы можаце прагледзець вырашаную канфігурацыю:

```bash
curl -s http://localhost:9090/config | jq .
```

```json
{
  "listen_addr": "0.0.0.0:8080",
  "document_root": "/var/www/html/public",
  "index_file": "index.php",
  "executor_type": "sapi",
  "max_connections": 10000,
  "drain_timeout_seconds": 30,
  "header_timeout_seconds": 5,
  "idle_timeout_seconds": 60,
  "request_timeout_seconds": 120,
  "rate_limit": 100,
  "rate_window_seconds": 60,
  "tls_enabled": true,
  "error_pages_dir": "/etc/oxphp/error-pages",
  "compression_level": 4,
  "static_cache_ttl": 2592000,
  "access_log": "all",
  "async_workers": 4,
  "async_queue_capacity": 256,
  "plugins": {}
}
```

Шляхі да TLS-ключа і сертыфіката не ўключаюцца ў вывад. Лагічнае значэнне `tls_enabled` паказвае, ці актыўны TLS. Аб'ект `plugins` змяшчае канфігурацыю ад любых загружаных плагінаў.
