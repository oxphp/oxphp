OPcache працуе з OxPHP без дадатковай наладкі. PHP-скрыпты кампілююцца аднойчы і кэшуюцца ў агульнай памяці, паўторна выкарыстоўваючыся ўсімі патокамі воркераў на працягу жыцця серверанага працэсу.

## Як гэта працуе

OxPHP выкарыстоўвае карыстальніцкі SAPI, які ідэнтыфікуе сябе як `cli-server` для PHP. OPcache распазнае гэтую назву SAPI і аўтаматычна ўключае паскарэнне — спецыяльная канфігурацыя не патрэбна.

Паколькі OxPHP выкарыстоўвае PHP ZTS (Zend Thread Safety), усе патокі воркераў выкарыстоўваюць адзін сегмент агульнай памяці OPcache. Скрыпт, скампіляваны адным воркерам, адразу даступны ўсім астатнім воркерам. Гэта забяспечвае паводзіны «скампіляваць аднойчы — выконваць шмат разоў» з канкурэнтнасцю некалькіх патокаў воркераў.

## Патрабаванне часу запыту

Функцыя `file_update_protection` OPcache прадухіляе кэшаванне файлаў, якія былі зменены нядаўна (на працягу 2 секунд па змаўчанні). Падчас ініцыялізацыі кожнага запыту OPcache параўноўвае час мадыфікацыі файла з бягучым часам запыту.

SAPI OxPHP прадастаўляе зваротны выклік `get_request_time`, які вяртае бягучую Unix-часовую пазнаку. Гэты зваротны выклік выклікаецца PHP падчас `php_request_startup()`, а гэта азначае, што час запыту **павінен** быць даступны да гэтага моманту.

### Што адбываецца без часу запыту

Калі час запыту вяртае `0` (нулявая эпоха), праверка абароны файлаў OPcache параўноўвае `mtime` кожнага файла з 1 студзеня 1970 года. Паколькі ўсе файлы былі зменены пасля гэтай даты, OPcache лічыць іх «занадта новымі» і адмаўляецца кэшаваць. Вынік — **0% частка трапленняў у кэш** — кожны запыт перакампілюе кожны скрыпт.

OxPHP пазбягае гэтага, рэалізуючы зваротны выклік SAPI `get_request_time`, які вяртае `SystemTime::now()` як Unix-часовую пазнаку з мікрасекунднай дакладнасцю.

## Праверка стану OPcache

Стварыце дыягнастычны скрыпт для пацверджання, што OPcache актыўны:

```php
<?php
// www/opcache_check.php
if (!function_exists('opcache_get_status')) {
    echo "OPcache extension is not loaded\n";
    exit(1);
}

$status = opcache_get_status();

echo "OPcache enabled: " . ($status['opcache_enabled'] ? 'yes' : 'no') . "\n";
echo "Cached scripts:  " . $status['opcache_statistics']['num_cached_scripts'] . "\n";
echo "Cache hits:      " . $status['opcache_statistics']['hits'] . "\n";
echo "Cache misses:    " . $status['opcache_statistics']['misses'] . "\n";
echo "Hit rate:        " . round($status['opcache_statistics']['opcache_hit_rate'], 1) . "%\n";
echo "Memory used:     " . round($status['memory_usage']['used_memory'] / 1048576, 1) . " MB\n";
echo "Memory free:     " . round($status['memory_usage']['free_memory'] / 1048576, 1) . " MB\n";
```

Праверце:

```bash
curl http://localhost:8080/opcache_check.php
# Першы запыт: промах (скрыпт кампілюецца і кэшуецца)
curl http://localhost:8080/opcache_check.php
# Другі запыт: трапленне (скрыпт аддаецца з кэша)
```

Здаровая ўстаноўка OPcache паказвае частку трапленняў, якая набліжаецца да 100% пасля пачатковага перыяду разагрэву.

## Кампіляцыя JIT

Кампілятар JIT OPcache падтрымліваецца пры працы з PHP 8.0+. Уключыце яго ў вашым `php.ini`:

```ini
opcache.enable=1
opcache.jit=1255
opcache.jit_buffer_size=64M
```

JIT дае найбольшую карысць для PHP-кода з інтэнсіўнымі вылічэннямі (матэматыка, цыклы, апрацоўка радкоў). Для праграм, абмежаваных уводам-вывадам (запыты да базы даных, выклікі API), паляпшэнне мінімальнае.

## Рэкамендаваныя налады

Гэтыя налады `php.ini` з'яўляюцца добрай адпраўной кропкай для вытворчага выкарыстання з OxPHP:

```ini
[opcache]
opcache.enable=1
opcache.memory_consumption=128
opcache.max_accelerated_files=10000
opcache.validate_timestamps=1
opcache.revalidate_freq=2
opcache.file_update_protection=2
opcache.save_comments=1
```

| Налада | Апісанне |
|---------|-------------|
| `memory_consumption` | Агульная памяць у МБ для скампіляваных скрыптоў. Павялічце, калі `opcache_get_status()` паказвае мала свабоднай памяці. |
| `max_accelerated_files` | Максімальная колькасць кэшаваных скрыптоў. Усталюйце вышэй за агульную колькасць вашых `.php` файлаў. |
| `validate_timestamps` | Калі `1`, OPcache правярае часы мадыфікацыі файлаў на дыску. Усталюйце `0` у вытворчасці, калі вы разгортваеце шляхам замены вобраза кантэйнера. |
| `revalidate_freq` | Секунды паміж праверкамі мадыфікацыі файлаў. Ужываецца толькі калі `validate_timestamps=1`. |
| `file_update_protection` | Секунды пасля мадыфікацыі файла перад кэшаваннем. Прадухіляе кэшаванне часткова запісаных файлаў падчас разгортвання. |
| `save_comments` | Захоўваць каментарыі дакументацыі ў кэшаваных скрыптах. Неабходна для фрэймворкаў, якія выкарыстоўваюць маршрутызацыю на аснове анатацый (напрыклад, Symfony, Laravel). |

### Аптымізацыя для вытворчасці

Для разгортванняў у кантэйнерах, дзе PHP-файлы ніколі не змяняюцца падчас працы, адключыце праверку часовых адзнак для максімальнай прадукцыйнасці:

```ini
opcache.validate_timestamps=0
```

Гэта кажа OPcache ніколі не правяраць файлавую сістэму на змены пасля кэшавання скрыпту. Вы павінны перазапусціць кантэйнер (або выклікаць `opcache_reset()`) для прымянення зменаў кода.

## ZTS і агульная памяць

OxPHP запускае PHP у рэжыме ZTS, дзе кожны паток воркера мае свой уласны кантэкст выканання, але ўсе патокі выкарыстоўваюць адзін сегмент агульнай памяці OPcache. Гэта азначае:

- Скрыпт, скампіляваны воркерам 0, адразу даступны воркерам 1, 2, 3 і г.д.
- Унутранняя блакіроўка OPcache бяспечна апрацоўвае канкурэнтную кампіляцыю.
- Спажыванне памяці не маштабуецца з колькасцю воркераў — адна копія кожнага скампіляванага скрыпту абслугоўвае ўсе патокі.

Гэта больш эфектыўна па памяці, чым PHP-FPM, дзе кожны працэс падтрымлівае свой уласны сегмент OPcache (калі вы не выкарыстоўваеце `opcache.file_cache` з `file_cache_only=1` для агульнага сховішча).
