Пашырэнне `oxphp_sapi` для PHP рэгіструе шэсць убудаваных функцый, якія даюць вашаму PHP-коду доступ да ўнутраных механізмаў сервера OxPHP. Гэтыя функцыі даступныя ў кожным PHP-скрыпце, які выконвае OxPHP — дырэктыва `extension=` не патрэбна, бо пашырэнне скампілявана ў карыстальніцкі SAPI.

Плагіны могуць рэгістраваць дадатковыя PHP-функцыі пры запуску. Гэтыя функцыі, прадастаўленыя плагінамі, рэгіструюцца падчас `MINIT` праз C-мост і з'яўляюцца побач з убудаванымі.

## `oxphp_request_id`

Вяртае ўнікальны ідэнтыфікатар запыту, прызначаны бягучаму запыту.

```php
oxphp_request_id(): string
```

**Параметры:** Няма.

**Вяртаемае значэнне:** 16-сімвальны шаснаццатковы радок. Фармат — `{timestamp_hex}{counter_hex}`, дзе першыя 8 сімвалаў — Unix-часовая пазнака, а апошнія 8 — манатонны лічыльнік. Вяртае пусты радок, калі ідэнтыфікатар запыту не быў усталяваны (не павінна адбывацца падчас звычайнай апрацоўкі запытаў).

**Прыклад:**

```php
<?php
$requestId = oxphp_request_id();
// "67a3b1c400000042"

header("X-Request-Id: $requestId");

// Выкарыстанне ў лагіраванні праграмы
error_log("[$requestId] Processing payment for order #1234");
```

**Заўвагі:**
- Ідэнтыфікатар запыту ўсталёўваецца серверам перад пачаткам выканання PHP.
- Той жа ідэнтыфікатар даступны на баку Rust для лагіравання доступу і загалоўкаў адказу.
- Ідэнтыфікатар унікальны на працягу жыцця аднаго серверанга працэсу.

## `oxphp_worker_id`

Вяртае індэкс патоку PHP-воркера, які апрацоўвае бягучы запыт.

```php
oxphp_worker_id(): int
```

**Параметры:** Няма.

**Вяртаемае значэнне:** Цэлы лік з нулявой базай, які ідэнтыфікуе паток воркера. Значэнні знаходзяцца ў дыяпазоне ад `0` да `PHP_WORKERS - 1` для статычных воркераў. Дынамічныя воркеры атрымліваюць ідэнтыфікатары вышэй за пачатковы дыяпазон.

**Прыклад:**

```php
<?php
$workerId = oxphp_worker_id();
// 3

// Выкарыстанне для каталогаў часовых файлаў, спецыфічных для воркера, або адладкі
$tmpDir = "/tmp/oxphp-worker-$workerId";
```

**Заўвагі:**
- Ідэнтыфікатары воркераў стабільныя на працягу жыцця патоку воркера.
- У рэжыме дынамічнага маштабавання воркеры, створаныя пасля запуску, атрымліваюць нарастаючыя ідэнтыфікатары вышэй за пачатковы памер пула.
- Карысна для адладкі праблем з канкурэнтнасцю або раздзялення рэсурсаў, спецыфічных для воркера.

## `oxphp_server_info`

Вяртае асацыятыўны масіў з метаданымі сервера і воркера.

```php
oxphp_server_info(): array
```

**Параметры:** Няма.

**Вяртаемае значэнне:** Асацыятыўны масіў з наступнымі ключамі:

| Ключ | Тып | Апісанне |
|-----|------|-------------|
| `sapi` | `string` | Заўсёды `"oxphp"` |
| `version` | `string` | Версія сервера (цяпер `"0.1.0"`) |
| `worker_id` | `int` | Тое ж значэнне, што і `oxphp_worker_id()` |
| `request_time` | `float` | Unix-часовая пазнака з мікрасекунднай дакладнасцю, калі запыт пачаўся |

**Прыклад:**

```php
<?php
$info = oxphp_server_info();
// [
//     "sapi"         => "oxphp",
//     "version"      => "0.1.0",
//     "worker_id"    => 3,
//     "request_time" => 1738800000.123456,
// ]

// Вылічэнне часу, які прайшоў
$elapsed = microtime(true) - $info['request_time'];
echo "Request processing took {$elapsed}s so far";
```

**Заўвагі:**
- `request_time` чытае з лакальнага для патоку сховішча C-бібліятэкі маста, якое ўсталёўваецца перад `php_request_startup()`.
- Гэта значэнне таксама выкарыстоўваецца праверкай `file_update_protection` у OPcache.

## `oxphp_request_heartbeat`

Запаўняльнік для будучага механізму падаўжэння тайм-аўту вартавога таймера. Цяпер не выконвае ніякіх дзеянняў.

```php
oxphp_request_heartbeat(int $time = 10): bool
```

**Параметры:**

| Імя | Тып | Па змаўчанні | Апісанне |
|------|------|---------|-------------|
| `$time` | `int` | `10` | Запытанае падаўжэнне тайм-аўту ў секундах |

**Вяртаемае значэнне:** Заўсёды вяртае `true` у бягучай рэалізацыі.

**Прыклад:**

```php
<?php
// Працяглы імпарт даных
foreach ($records as $record) {
    process($record);
    oxphp_request_heartbeat(30); // Сігнал, што скрыпт яшчэ працуе
}
```

**Заўвагі:**
- Гэта функцыя існуе для забеспячэння сумяшчальнасці з будучымі версіямі. У будучым выпуску яна будзе скідваць таймер вартавога тайм-аўту запыту.
- Выклікаць яе сёння бяспечна і не мае выдаткаў на прадукцыйнасць.

## `oxphp_finish_request`

Пазначае бягучы запыт як завершаны, дазваляючы серверу адправіць адказ кліенту, пакуль PHP-скрыпт працягвае выкананне ў фонавым рэжыме. Гэта эквівалент `fastcgi_finish_request()` у OxPHP.

```php
oxphp_finish_request(): bool
```

**Параметры:** Няма.

**Вяртаемае значэнне:** Вяртае `true` пры першым выкліку. Вяртае `false`, калі запыт ужо быў завершаны (г.зн. функцыя была выклікана больш за адзін раз у тым жа запыце).

**Прыклад:**

```php
<?php
// Адправіць адказ кліенту неадкладна
echo json_encode(['status' => 'accepted']);
oxphp_finish_request();

// Працягнуць фонавую працу — кліент ужо атрымаў адказ
send_notification_email($userId);
update_analytics($eventData);
cleanup_temp_files();
```

**Заўвагі:**
- Пасля выкліку гэтай функцыі любы далейшы вывад з `echo` або `print` адкідваецца з адказу кліенту.
- Паток PHP-воркера застаецца занятым да завяршэння выканання скрыпту, таму працяглыя фонавыя задачы памяншаюць даступны пул воркераў.
- Выклік гэтай функцыі двойчы ў тым жа запыце вяртае `false` пры другім выкліку.

## `oxphp_is_streaming`

Правярае, ці знаходзіцца бягучы запыт у рэжыме стрымінгу.

```php
oxphp_is_streaming(): bool
```

**Параметры:** Няма.

**Вяртаемае значэнне:** `true`, калі рэжым стрымінгу актыўны, `false` у адваротным выпадку.

**Прыклад:**

```php
<?php
if (oxphp_is_streaming()) {
    // Інкрыментальны скід вываду
    echo "data: " . json_encode($event) . "\n\n";
    flush();
} else {
    // Буферызаваць поўны адказ
    echo json_encode($allData);
}
```

**Заўвагі:**
- Рэжым стрымінгу кантралюецца серверным асяроддзем выканання, а не PHP-кодам.
- Гэта функцыя ў першую чаргу карысная для скрыптоў, якім трэба адаптаваць паводзіны вываду ў залежнасці ад рэжыму транспарту.

## Функцыі плагінаў

Плагіны могуць рэгістраваць карыстальніцкія PHP-функцыі, якія можна выклікаць з вашых скрыптоў. Гэтыя функцыі рэгіструюцца падчас ініцыялізацыі PHP-модуля (`MINIT`) і адпраўляюцца праз C-мост у код апрацоўшчыка на Rust.

Функцыі плагінаў выкарыстоўваюць натыўны мост для дыспетчарызацыі з нулявой серыялізацыяй. Аргументы і вяртаемыя значэнні перадаюцца як сырыя ўказальнікі `zval` — Rust чытае і піша іх напрамую праз C-функцыі доступу, без накладных выдаткаў на JSON-кадаванне. Калі апрацоўшчык вяртае памылку, PHP выдае `E_WARNING`, і вяртаецца `NULL`.

```php
<?php
// Прыклад: выклік функцыі, зарэгістраванай плагінам
$result = some_plugin_function('arg1', 42, ['key' => 'value']);
```

Функцыі плагінаў пералічаны побач з убудаванымі функцыямі ў вывадзе `phpinfo()`, але яны зарэгістраваны глабальна (не пад пашырэннем `oxphp_sapi`), таму яны не з'яўляюцца ў `get_extension_funcs('oxphp_sapi')`.

## Інфармацыя аб пашырэнні

Метаданыя пашырэння бачныя ў вывадзе `phpinfo()`:

| Поле | Значэнне |
|-------|-------|
| Назва пашырэння | `oxphp_sapi` |
| Версія | `0.1.0` |

Вы можаце праверыць, што пашырэнне загружана:

```php
<?php
var_dump(extension_loaded('oxphp_sapi'));
// bool(true)

// Спіс убудаваных функцый пашырэння
print_r(get_extension_funcs('oxphp_sapi'));
// Array
// (
//     [0] => oxphp_request_id
//     [1] => oxphp_worker_id
//     [2] => oxphp_server_info
//     [3] => oxphp_request_heartbeat
//     [4] => oxphp_finish_request
//     [5] => oxphp_is_streaming
// )
```
