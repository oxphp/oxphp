Пашырэнне `oxphp_sapi` для PHP рэгіструе дзевяць убудаваных функцый, якія даюць вашаму PHP-коду доступ да ўнутраных механізмаў сервера OxPHP. Гэтыя функцыі даступныя ў кожным PHP-скрыпце, які выконвае OxPHP — дырэктыва `extension=` не патрэбна, бо пашырэнне скампілявана ў карыстальніцкі SAPI.

Плагіны могуць рэгістраваць дадатковыя PHP-функцыі пры запуску. Гэтыя функцыі, прадастаўленыя плагінамі, рэгіструюцца падчас `MINIT` праз C-мост і з'яўляюцца побач з убудаванымі.

## `oxphp_request_id`

Вяртае ўнікальны ідэнтыфікатар запыту, прызначаны бягучаму запыту.

```php
oxphp_request_id(): string
```

**Параметры:** Няма.

**Вяртаемае значэнне:** 16-сімвальны шаснаццатковы радок. Фармат — `{timestamp_hex}{counter_hex}`, дзе першыя 8 сімвалаў — Unix-часовая пазнака, а апошнія 8 — манатонны лічыльнік. Вяртае пусты радок, калі ідэнтыфікатар запыту не быў усталяваны (не павінна адбывацца падчас звычайнай апрацоўкі запытаў).

**Прыклад:**

```php
<?php
$requestId = oxphp_request_id();
// "67a3b1c400000042"

header("X-Request-Id: $requestId");

// Выкарыстанне ў лагіраванні праграмы
error_log("[$requestId] Processing payment for order #1234");
```

**Заўвагі:**
- Ідэнтыфікатар запыту ўсталёўваецца серверам перад пачаткам выканання PHP.
- Той жа ідэнтыфікатар даступны на баку Rust для лагіравання доступу і загалоўкаў адказу.
- Ідэнтыфікатар унікальны на працягу жыцця аднаго серверанга працэсу.

## `oxphp_worker_id`

Вяртае індэкс патоку PHP-воркера, які апрацоўвае бягучы запыт.

```php
oxphp_worker_id(): int
```

**Параметры:** Няма.

**Вяртаемае значэнне:** Цэлы лік з нулявой базай, які ідэнтыфікуе паток воркера. Значэнні знаходзяцца ў дыяпазоне ад `0` да `PHP_WORKERS - 1` для статычных воркераў. Дынамічныя воркеры атрымліваюць ідэнтыфікатары вышэй за пачатковы дыяпазон.

**Прыклад:**

```php
<?php
$workerId = oxphp_worker_id();
// 3

// Выкарыстанне для каталогаў часовых файлаў, спецыфічных для воркера, або адладкі
$tmpDir = "/tmp/oxphp-worker-$workerId";
```

**Заўвагі:**
- Ідэнтыфікатары воркераў стабільныя на працягу жыцця патоку воркера.
- У рэжыме дынамічнага маштабавання воркеры, створаныя пасля запуску, атрымліваюць нарастаючыя ідэнтыфікатары вышэй за пачатковы памер пула.
- Карысна для адладкі праблем з канкурэнтнасцю або раздзялення рэсурсаў, спецыфічных для воркера.

## `oxphp_server_info`

Вяртае асацыятыўны масіў з метаданымі сервера і воркера.

```php
oxphp_server_info(): array
```

**Параметры:** Няма.

**Вяртаемае значэнне:** Асацыятыўны масіў з наступнымі ключамі:

| Ключ | Тып | Апісанне |
|-----|------|-------------|
| `sapi` | `string` | Заўсёды `"oxphp"` |
| `version` | `string` | Версія сервера (цяпер `"0.1.0"`) |
| `worker_id` | `int` | Тое ж значэнне, што і `oxphp_worker_id()` |
| `request_time` | `float` | Unix-часовая пазнака з мікрасекунднай дакладнасцю, калі запыт пачаўся |
| `worker_mode` | `bool` | `true`, калі сервер працуе ў рэжыме воркера, `false` у традыцыйным рэжыме |

**Прыклад:**

```php
<?php
$info = oxphp_server_info();
// [
//     "sapi"         => "oxphp",
//     "version"      => "0.1.0",
//     "worker_id"    => 3,
//     "request_time" => 1738800000.123456,
//     "worker_mode"  => true,
// ]

// Вылічэнне часу, які прайшоў
$elapsed = microtime(true) - $info['request_time'];
echo "Request processing took {$elapsed}s so far";
```

**Заўвагі:**
- `request_time` чытае з лакальнага для патоку сховішча C-бібліятэкі маста, якое ўсталёўваецца перад `php_request_startup()`.
- Гэта значэнне таксама выкарыстоўваецца праверкай `file_update_protection` у OPcache.

## `oxphp_request_heartbeat`

Запаўняльнік для будучага механізму падаўжэння тайм-аўту вартавога таймера. Цяпер не выконвае ніякіх дзеянняў.

```php
oxphp_request_heartbeat(int $time = 10): bool
```

**Параметры:**

| Імя | Тып | Па змаўчанні | Апісанне |
|------|------|---------|-------------|
| `$time` | `int` | `10` | Запытанае падаўжэнне тайм-аўту ў секундах |

**Вяртаемае значэнне:** Заўсёды вяртае `true` у бягучай рэалізацыі.

**Прыклад:**

```php
<?php
// Працяглы імпарт даных
foreach ($records as $record) {
    process($record);
    oxphp_request_heartbeat(30); // Сігнал, што скрыпт яшчэ працуе
}
```

**Заўвагі:**
- Гэта функцыя існуе для забеспячэння сумяшчальнасці з будучымі версіямі. У будучым выпуску яна будзе скідваць таймер вартавога тайм-аўту запыту.
- Выклікаць яе сёння бяспечна і не мае выдаткаў на прадукцыйнасць.

## `oxphp_finish_request`

Пазначае бягучы запыт як завершаны, дазваляючы серверу адправіць адказ кліенту, пакуль PHP-скрыпт працягвае выкананне ў фонавым рэжыме. Гэта эквівалент `fastcgi_finish_request()` у OxPHP.

```php
oxphp_finish_request(): bool
```

**Параметры:** Няма.

**Вяртаемае значэнне:** Вяртае `true` пры першым выкліку. Вяртае `false`, калі запыт ужо быў завершаны (г.зн. функцыя была выклікана больш за адзін раз у тым жа запыце).

**Прыклад:**

```php
<?php
// Адправіць адказ кліенту неадкладна
echo json_encode(['status' => 'accepted']);
oxphp_finish_request();

// Працягнуць фонавую працу — кліент ужо атрымаў адказ
send_notification_email($userId);
update_analytics($eventData);
cleanup_temp_files();
```

**Заўвагі:**
- Пасля выкліку гэтай функцыі любы далейшы вывад з `echo` або `print` адкідваецца з адказу кліенту.
- Паток PHP-воркера застаецца занятым да завяршэння выканання скрыпту, таму працяглыя фонавыя задачы памяншаюць даступны пул воркераў.
- Выклік гэтай функцыі двойчы ў тым жа запыце вяртае `false` пры другім выкліку.

## `oxphp_is_worker`

Правярае, ці працуе сервер у рэжыме воркера.

```php
oxphp_is_worker(): bool
```

**Параметры:** Няма.

**Вяртаемае значэнне:** `true`, калі бягучы запыт апрацоўваецца персістэнтным воркер-працэсам (г.зн. `WORKER_FILE` усталяваны), `false`, калі сервер працуе ў традыцыйным рэжыме, дзе кожны запыт запускае новы PHP-працэс.

**Прыклад:**

```php
<?php
if (oxphp_is_worker()) {
    // Worker mode: reuse persistent database connection
    $db = $GLOBALS['db'] ?? ($GLOBALS['db'] = new PDO($dsn));
} else {
    // Traditional mode: connect per request
    $db = new PDO($dsn);
}
```

**Заўвагі:**
- Гэтую функцыю можна выклікаць як унутры, так і за межамі callback-апрацоўшчыка `oxphp_worker()`.
- Тое ж значэнне даступна праз `oxphp_server_info()['worker_mode']`.
- Карысна для бібліятэк і фрэймворкаў, якім трэба адаптаваць паводзіны ў залежнасці ад мадэлі выканання (напр., аб'яднанне злучэнняў, статычныя кэшы, апрацоўка сесій).

## `oxphp_is_streaming`

Правярае, ці знаходзіцца бягучы запыт у рэжыме стрымінгу.

```php
oxphp_is_streaming(): bool
```

**Параметры:** Няма.

**Вяртаемае значэнне:** `true`, калі рэжым стрымінгу актыўны, `false` у адваротным выпадку.

**Прыклад:**

```php
<?php
if (oxphp_is_streaming()) {
    // Інкрыментальны скід вываду
    echo "data: " . json_encode($event) . "\n\n";
    flush();
} else {
    // Буферызаваць поўны адказ
    echo json_encode($allData);
}
```

**Заўвагі:**
- Рэжым стрымінгу актывуецца аўтаматычна пры ўстаноўцы загалоўка `Content-Type: text/event-stream` або ўручную праз `oxphp_stream_flush()`.
- Гэта функцыя карысная для скрыптоў, якім трэба адаптаваць паводзіны вываду ў залежнасці ад рэжыму транспарту.

## `oxphp_stream_flush`

Актывуе рэжым стрымінгу (калі ён яшчэ не актыўны) і скідвае бягучы буфер вываду кліенту ў выглядзе чанка. Гэта асноўная функцыя для рэалізацыі Server-Sent Events (SSE) у OxPHP.

```php
oxphp_stream_flush(): bool
```

**Параметры:** Няма.

**Вяртаемае значэнне:** Вяртае `true` пры поспеху. Вяртае `false`, калі запыт ужо быў завершаны праз `oxphp_finish_request()`.

**Прыклад:**

```php
<?php
header('Content-Type: text/event-stream');
header('Cache-Control: no-cache');

for ($i = 0; $i < 10; $i++) {
    echo "id: $i\n";
    echo "data: " . json_encode(['counter' => $i, 'time' => microtime(true)]) . "\n\n";
    oxphp_stream_flush();
    sleep(1);
}
```

**Як гэта працуе:**

1. Пры першым выкліку актывуе рэжым стрымінгу праз C-мост (`oxphp_bridge_set_stream_mode`)
2. Скідвае ўсе буферы вываду PHP (`php_output_flush_all`)
3. Выклікае callback SAPI flush, які адпраўляе буферызаваны вывад як HTTP-чанк кліенту

**Заўвагі:**
- Загалоўкі адпраўляюцца кліенту пры першым скідзе. Наступныя выклікі адпраўляюць толькі чанкі цела.
- Можна таксама выкарыстоўваць натыўны PHP `flush()` з `Content-Type: text/event-stream` — OxPHP аўтаматычна вызначае SSE content type і актывуе рэжым стрымінгу. У гэтым выпадку спачатку выклічце `ob_end_flush()`, каб адключыць буферызацыю вываду PHP.
- Калі `oxphp_finish_request()` быў выкліканы раней, функцыя вяртае `false` і нічога не робіць.
- HTTP-злучэнне закрываецца аўтаматычна, калі PHP-скрыпт завяршаецца і канал стрымінгу закрываецца.
- Зваротны ціск забяспечваецца праз абмежаваны канал (ёмістасць 64) — калі кліент павольны, `oxphp_stream_flush()` блакуецца, пакуль кліент не дагоніць.

## `oxphp_worker`

Уваходзіць у цыкл рэжыму персістэнтнага воркера. Выклікае наданы callback-апрацоўшчык для кожнага ўваходнага HTTP-запыту. Паміж запытамі мяккі скід ачышчае стан кожнага запыту (суперглабалы, буферы вываду, `$_SESSION`) без знішчэння PHP-кучы, таму стан загрузкі (аўтазагрузчыкі, злучэнні з базай даных, кэшаваная канфігурацыя) захоўваецца паміж запытамі.

```php
oxphp_worker(callable $handler): bool
```

**Параметры:**

| Імя | Тып | Апісанне |
|------|------|-------------|
| `$handler` | `callable` | Callback, які выклікаецца адзін раз на кожны HTTP-запыт. Не атрымлівае аргументаў. |

**Вяртаемае значэнне:** Вяртае `true` пры плаўнай спынцы (спыненне сервера). Вяртае `false` неадкладна, калі рэжым воркера не ўключаны (г.зн. `WORKER_FILE` не ўсталяваны).

**Прыклад:**

```php
<?php
// worker.php — кропка ўваходу персістэнтнага воркера

// Загрузка: выконваецца адзін раз за жыццё воркера
require __DIR__ . '/vendor/autoload.php';
$db = new PDO('mysql:host=localhost;dbname=app', 'root', '');
$config = json_decode(file_get_contents(__DIR__ . '/config.json'), true);

// Апрацоўка запытаў у цыкле
oxphp_worker(function () use ($db, $config) {
    $uri = $_SERVER['REQUEST_URI'];
    $method = $_SERVER['REQUEST_METHOD'];

    // Маршрутызацыя і апрацоўка запыту
    if ($uri === '/api/users' && $method === 'GET') {
        $users = $db->query('SELECT id, name FROM users')->fetchAll();
        header('Content-Type: application/json');
        echo json_encode($users);
    } else {
        http_response_code(404);
        echo 'Not Found';
    }
});
```

**Як гэта працуе:**

1. Callback-апрацоўшчык выклікаецца для кожнага HTTP-запыту, атрыманага ад узроўню Rust.
2. Паміж запытамі адбываецца мяккі скід:
   - Суперглабалы (`$_GET`, `$_POST`, `$_SERVER`, `$_COOKIE`, `$_FILES`) запаўняюцца данымі новага запыту
   - Буферы вываду ачышчаюцца
   - Загалоўкі HTTP-адказу скідваюцца
   - Функцыі, зарэгістраваныя праз `register_shutdown_function()`, выклікаюцца і ачышчаюцца
3. Зборка смецця запускаецца перыядычна (кожныя 100 запытаў) для вызвалення цыклічных спасылак без уплыву на затрымку кожнага запыту.
4. Цыкл завяршаецца, калі:
   - Сервер спыняецца (сігнал плаўнай спынкі)
   - Апрацоўшчык кідае неперахопленае выключэнне або фатальную памылку (прычына выхаду: `error`)
   - Воркер дасягае `WORKER_MAX_REQUESTS` (прычына выхаду: `max_requests`)
   - Воркер перавышае `WORKER_MAX_MEMORY_MIB` (прычына выхаду: `max_memory`)

**Заўвагі:**
- Гэта функцыя працуе толькі калі ўсталяваны `WORKER_FILE`. Яе выклік з звычайнага PHP-скрыпту выдае `E_WARNING` і вяртае `false`.
- Зменныя, аб'яўленыя за межамі замыкання апрацоўшчыка, захоўваюцца паміж запытамі. Выкарыстоўвайце гэта для злучэнняў з базай даных, канфігурацыі і іншай затратнай ініцыялізацыі.
- Клаўзула `use` апрацоўшчыка захоплівае зменныя па спасылцы або значэнні як звычайна. Зменныя, захопленыя па спасылцы, разалоўваюць стан паміж запытамі.
- Рэцыклінг воркера (праз `WORKER_MAX_REQUESTS` або `WORKER_MAX_MEMORY_MIB`) прыводзіць да выхаду і перазапуску працэсу воркера, які паўторна выконвае ўвесь скрыпт воркера, уключаючы загрузку.
- Метрыкі рэжыму воркера (`oxphp_worker_requests_handled_total`, `oxphp_worker_recycles_total` і інш.) даступныя на канцавой кропцы `/metrics`, калі ўнутраны сервер працуе.

## Функцыі плагінаў

Плагіны могуць рэгістраваць карыстальніцкія PHP-функцыі, якія можна выклікаць з вашых скрыптоў. Гэтыя функцыі рэгіструюцца падчас ініцыялізацыі PHP-модуля (`MINIT`) і адпраўляюцца праз C-мост у код апрацоўшчыка на Rust.

Функцыі плагінаў выкарыстоўваюць натыўны мост для дыспетчарызацыі з нулявой серыялізацыяй. Аргументы і вяртаемыя значэнні перадаюцца як сырыя ўказальнікі `zval` — Rust чытае і піша іх напрамую праз C-функцыі доступу, без накладных выдаткаў на JSON-кадаванне. Калі апрацоўшчык вяртае памылку, PHP выдае `E_WARNING`, і вяртаецца `NULL`.

```php
<?php
// Прыклад: выклік функцыі, зарэгістраванай плагінам
$result = some_plugin_function('arg1', 42, ['key' => 'value']);
```

Функцыі плагінаў пералічаны побач з убудаванымі функцыямі ў вывадзе `phpinfo()`, але яны зарэгістраваны глабальна (не пад пашырэннем `oxphp_sapi`), таму яны не з'яўляюцца ў `get_extension_funcs('oxphp_sapi')`.

## Інфармацыя аб пашырэнні

Метаданыя пашырэння бачныя ў вывадзе `phpinfo()`:

| Поле | Значэнне |
|-------|-------|
| Назва пашырэння | `oxphp_sapi` |
| Версія | `0.1.0` |

Вы можаце праверыць, што пашырэнне загружана:

```php
<?php
var_dump(extension_loaded('oxphp_sapi'));
// bool(true)

// Спіс убудаваных функцый пашырэння
print_r(get_extension_funcs('oxphp_sapi'));
// Array
// (
//     [0] => oxphp_request_id
//     [1] => oxphp_worker_id
//     [2] => oxphp_server_info
//     [3] => oxphp_request_heartbeat
//     [4] => oxphp_finish_request
//     [5] => oxphp_is_worker
//     [6] => oxphp_is_streaming
//     [7] => oxphp_stream_flush
//     [8] => oxphp_worker
// )
```
