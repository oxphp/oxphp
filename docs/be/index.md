OxPHP -- гэта асінхронны сервер PHP-дадаткаў, напісаны на Rust. Ён замяняе nginx + PHP-FPM адзіным бінарным файлам, які спалучае абслугоўванне HTTP, выкананне PHP і ўбудаванае назіранне ў адным працэсе.

## Чаму OxPHP

Традыцыйнае разгортванне PHP патрабуе вэб-сервер (nginx або Apache), менеджар працэсаў (PHP-FPM) і асобныя інструменты для метрык, абмежавання частаты запытаў і TLS-тэрмінацыі. OxPHP зводзіць увесь гэты стэк да аднаго бінарнага файла без знешніх залежнасцяў падчас выканання, акрамя бібліятэкі PHP.

Сервер выкарыстоўвае наладжвальны асінхронны рантайм Tokio (CPU / 2 патокаў па змаўчанні, наладжваецца праз `TOKIO_WORKERS`) для ўсіх аперацый уводу-вываду і пул вылучаных патокаў АС для выканання PHP праз Zend Thread Safety (ZTS). Такая архітэктура захоўвае асінхронны цыкл падзей свабодным ад блакіруючых выклікаў PHP, адначасова маштабуючы выкананне PHP на ўсіх даступных ядрах. Алакатар mimalloc забяспечвае нізкую затрымку алакацый пры канкурэнтным доступе.

## Магчымасці

- **Абслугоўванне статычных файлаў** з файлавым кэшам у памяці і аўтаматычным вызначэннем MIME-тыпу
- **Тры рэжымы маршрутызацыі**: традыцыйны (прамое супастаўленне файлаў), фрэймворкавы (франт-кантролер) і SPA (фолбэк аднастаронкавага дадатку)
- **Выкананне PHP** праз уласны SAPI (`oxphp`) з поўнай падтрымкай суперглабалаў (`$_GET`, `$_POST`, `$_SERVER`, `$_COOKIE`, `$_FILES`)
- **Дынамічнае маштабаванне воркераў** -- аўтаматычнае маштабаванне патокаў PHP-воркераў паміж наладжвальнымі мінімальнай і максімальнай межамі ў залежнасці ад нагрузкі
- **Абмежаваная чарга запытаў** з backpressure -- вяртае 529, калі чарга поўная, замест прыняцця неабмежаванай працы
- **Сістэма плагінаў** з хукамі жыццёвага цыклу, рэгістрацыяй PHP-функцый і тапалагічнай сартыроўкай залежнасцяў
- **Сістэма падзей** з тыпізаванымі падзеямі і апрацоўшчыкамі з прыярытэтным парадкам на кожным этапе жыццёвага цыклу запыту
- **Сціск Brotli** для тыпаў адказаў, якія паддаюцца сціску
- **TLS** праз rustls (без залежнасці ад OpenSSL на ўваходзе)
- **Абмежаванне частаты запытаў па IP** з наладжвальнымі лімітамі і часавымі вокнамі
- **Метрыкі, сумяшчальныя з Prometheus**, даступныя на вылучаным унутраным порце
- **Праверка стану** па шляху `/health` на ўнутраным серверы
- **Ідэнтыфікатары запытаў**, якія генеруюцца для кожнага запыту і даступныя ў PHP праз `oxphp_request_id()`
- **Структураванае JSON-лагіраванне доступу** праз фрэймворк tracing
- **Карыстальніцкія старонкі памылак**, якія загружаюцца з каталога на дыску
- **Плаўная спынка** з наладжвальным тайм-аўтам завяршэння
- **OPcache + JIT** -- падтрымка з скрынкі
- **Маніторынг здароўя воркераў** з аўтаматычным перазапускам упаўшых воркераў
- **Стрымінг SSE** -- Server-Sent Events у рэальным часе праз аўтавызначэнне `Content-Type: text/event-stream` або `oxphp_stream_flush()`
- **Ранні адказ** праз `oxphp_finish_request()` -- неадкладная адпраўка HTTP-адказу з працягам фонавай апрацоўкі
- **Рэжым воркера** -- персістэнтныя PHP-працэсы з мяккім скідам паміж запытамі, аўтаматычным рэцыклінгам і метрыкамі кожнага воркера
- **W3C Trace Context** -- распаўсюджванне `traceparent`/`tracestate` з trace ID, даступнымі ў PHP праз `$_SERVER`
- **OpenTelemetry** -- экспарт спанаў праз OTLP (gRPC/HTTP) з наладжвальным семплінгам і семантычнымі канвенцыямі
- **Ізаляцыя панік** праз `catch_unwind` -- аварыйны збой PHP не спыняе ўвесь сервер
