# 架构概览

OxPHP 是一个单二进制 HTTP 服务器，用于替代传统的 nginx + PHP-FPM 技术栈。它在单一进程中处理 HTTP 解析、TLS 终止、路由、PHP 执行、压缩和可观测性，运行时无需任何外部依赖。

## OxPHP 的工作原理

OxPHP 在单一进程中融合了两个运行时层：

1. **异步 HTTP 层** — 事件驱动的网络层，负责接受 TCP 连接、执行 TLS 握手、解析 HTTP 请求和发送响应。它使用非阻塞 I/O 处理数千个并发连接，一个慢速客户端永远不会阻塞其他客户端。
2. **PHP 工作进程池** — 一组专用的 PHP 工作进程执行您的 PHP 脚本。每个工作进程一次处理一个请求，与其他工作进程完全隔离。

两层通过有界队列进行通信。当需要执行 PHP 的 HTTP 请求到达时，异步层将其放入队列。可用的 PHP 工作进程取出请求、执行脚本，并将响应返回给异步层以发送给客户端。

这种分离意味着网络 I/O——接受连接、读取头部、压缩响应、服务静态文件——永远不会与 PHP 执行竞争资源。每一层都可以独立扩展。

## 工作进程池

PHP 工作进程池决定了可以并发执行的 PHP 脚本数量。OxPHP 支持两种进程池模式。

### 静态进程池

在服务器启动时创建固定数量的工作进程，并在服务器整个生命周期内保持运行。这是默认模式。

```bash
PHP_WORKERS=8    # 恰好 8 个工作进程
PHP_WORKERS=0    # 自动检测（默认）：可用 CPU 核心数的一半，最少 1 个
```

### 动态进程池

工作进程根据需求自动扩缩容。用冒号分隔最小值和最大值：

```bash
PHP_WORKERS=2:16    # 从 2 个开始，负载高时扩展到 16 个
```

当所有当前工作进程均处于繁忙状态时，OxPHP 会创建新的工作进程直至上限。当工作进程空闲时间超过 `PHP_WORKERS_IDLE_SECONDS`（默认 30 秒）时，该工作进程会退出，向最小值收敛。

### 队列与背压

在异步 HTTP 层和工作进程池之间有一个有界队列。其容量默认为初始工作进程数乘以 128，可通过 `QUEUE_CAPACITY` 覆盖。对于静态进程池，初始数量是配置的工作进程数；对于动态进程池（`MIN:MAX`），初始数量是最小值。

当队列已满——即所有工作进程均繁忙且队列达到容量上限时——OxPHP 会立即向客户端返回 `503 Service Unavailable` 响应。这种背压机制防止服务器接受无限工作量，避免内存耗尽或所有请求延迟增加。

## 请求流程

每个请求都经过相同的处理管道，无论是服务静态文件还是执行 PHP：

```text
客户端
  │
  ▼
TLS 终止（如已配置）
  │
  ▼
HTTP 解析 + 请求 ID 分配
  │
  ▼
限流检查
  │
  ▼
路由解析
  │
  ├── 静态文件 ──► 文件缓存 / 磁盘读取
  │                         │
  │                         ▼
  │                    压缩 + 响应头
  │                         │
  │                         ▼
  │                    响应返回客户端
  │
  └── PHP 请求 ──► 有界队列
                         │
                         ▼
                    PHP 工作进程执行脚本
                         │
                         ▼
                    压缩 + 响应头
                         │
                         ▼
                    响应返回客户端
```

1. **TLS 终止** — 如果配置了 `TLS_CERT` 和 `TLS_KEY`，OxPHP 直接处理 TLS。无需单独的反向代理。
2. **HTTP 解析与请求 ID** — 解析请求并生成唯一请求 ID（或保留传入的 `X-Request-ID` 头部）。
3. **限流** — 如果设置了 `RATE_LIMIT`，将根据每 IP 请求计数器检查客户端 IP。超出限制的请求立即收到 `429 Too Many Requests` 响应。
4. **路由解析** — URL 与配置的路由模式（传统模式、框架模式、SPA 模式或工作进程模式）进行匹配。结果为静态文件、PHP 脚本或 404。
5. **静态文件** — 直接从内存缓存（高频访问文件）提供或从磁盘流式传输。OxPHP 自动添加 `ETag`、`Last-Modified` 和 `Cache-Control` 头部。
6. **PHP 执行** — 请求放入有界队列，由可用的工作进程取出。如果队列已满，客户端立即收到 503。
7. **压缩** — 当客户端发送 `Accept-Encoding: br` 时，基于文本的响应在发送前使用 Brotli 压缩（通过 `COMPRESSION_LEVEL` 配置）。
8. **响应发送** — 完成的响应通过连接发送回客户端，如果启用了访问日志则触发记录。

## 工作进程模式与标准模式

OxPHP 支持两种 PHP 执行模型：

**标准模式**（默认）为每个请求创建全新的 PHP 环境。自动加载器、配置和数据库连接在每个请求时初始化，请求结束后销毁。此模式与所有 PHP 应用开箱即用兼容。

**工作进程模式**使 PHP 进程跨请求保持存活。您的应用只需引导一次——加载自动加载器、配置并建立数据库连接——然后进入请求循环。在请求之间，OxPHP 自动重置超全局变量、输出缓冲区和响应头，同时保留已引导的状态。

工作进程模式消除了每次请求的启动开销，对于引导成本较高的基于框架的应用（Laravel、Symfony 等）可以显著减少响应时间。

要启用工作进程模式，将 `WORKER_FILE` 设置为一个调用 `oxphp_worker()` 的 PHP 脚本：

```php
<?php
require __DIR__ . '/../vendor/autoload.php';
$app = new MyApp\Application();

oxphp_worker(function () use ($app) {
    $app->handle();
});
```

详细指南请参见[工作进程模式](../features/worker-mode.md)。

## 安全保障

OxPHP 提供多项保障，确保您的应用在生产环境中稳定运行：

- **请求隔离** — 如果某个 PHP 脚本崩溃或触发致命错误，只有该单个请求受到影响。服务器继续正常处理所有其他请求。崩溃的工作进程会自动替换为新的工作进程。
- **工作进程自动重建** — OxPHP 监控所有 PHP 工作进程的健康状态。如果工作进程意外终止，无需人工干预即可启动新的工作进程替代它。
- **背压保护** — 有界请求队列防止过载。当服务器达到容量上限时，新请求收到明确的 503 响应，而不是无限排队并导致级联超时。
- **路径遍历保护** — 所有 URL 路径在访问文件系统前均经过清理。百分比编码的遍历尝试、`..` 段以及逃出文档根目录的路径均被阻止。
- **优雅关闭** — 收到 SIGTERM 时，OxPHP 停止接受新连接，等待进行中的请求完成（最长等待可配置的排空超时时间），然后退出。
