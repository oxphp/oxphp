---
title: 速率限制
description: 可配置限额和时间窗口的每 IP 速率限制
---

OxPHP 内置了每 IP 速率限制器，超出限额的请求将被 429 响应拒绝。速率限制默认关闭，当 `RATE_LIMIT` 设置为非零值时激活。

## 配置

| 变量 | 描述 | 默认值 |
|----------|-------------|---------|
| `RATE_LIMIT` | 每个 IP 在每个窗口期内的最大请求数 | `0`（禁用） |
| `RATE_WINDOW_SECONDS` | 窗口期持续时间（秒） | `60` |

```bash
# 允许每个 IP 在 60 秒窗口期内发送 100 个请求
RATE_LIMIT=100
RATE_WINDOW_SECONDS=60
```

设置 `RATE_LIMIT=0` 将完全禁用速率限制。禁用后，速率限制处理器不会注册到事件分发器中，零开销。

## 工作原理

速率限制器使用 `DashMap`（分片并发哈希表），以客户端 IP 地址为键。每个条目存储请求计数和当前窗口期的开始时间戳。

### 请求流程

1. 在映射表中查找客户端 IP（或插入新条目）
2. 如果窗口期已过期，将计数器重置为零并开始新窗口期
3. 递增计数器
4. 如果计数器超过 `RATE_LIMIT`，返回 429 响应

### 429 响应

当请求被限速时，服务器返回：

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 45
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 45
X-Request-ID: 67890abc00000042

429 Too Many Requests
```

| 头部 | 描述 |
|--------|-------------|
| `Retry-After` | 距当前窗口期重置的秒数 |
| `X-RateLimit-Limit` | 每个窗口期允许的最大请求数 |
| `X-RateLimit-Remaining` | 当前窗口期内剩余的请求数（被限速时始终为 `0`） |
| `X-RateLimit-Reset` | 距当前窗口期重置的秒数 |
| `X-Request-ID` | 本次请求的请求 ID |

## 事件处理器集成

速率限制作为事件处理器实现，监听优先级为 **-50** 的 `RequestReceived` 事件。这意味着它在请求 ID 生成器（优先级 -100）之后运行，但在指标和其他处理器之前。

当速率限制器拒绝请求时，它会在事件上设置 `early_response` 字段。连接处理器检查此字段并立即返回 429 响应，跳过路由和 PHP 执行。

处理器始终返回 `Propagation::Continue`，以便指标和访问日志处理器仍然处理该请求。这意味着被限速的请求会出现在访问日志和指标中。

## 清理

一个后台 Tokio 任务每 60 秒运行一次，移除窗口期在 `2 * RATE_WINDOW_SECONDS` 秒之前已过期的条目。这可以防止 `DashMap` 在客户端发送一波请求后消失时无限增长。

## 限制

- **固定窗口算法** -- 限制器使用简单的固定窗口计数器，而非滑动窗口。客户端可以在两个窗口期的交界处以突发方式发送最多 `2 * RATE_LIMIT` 个请求。
- **仅按 IP** -- 速率限制以源 IP 地址为键。共享 NAT 或代理后面的客户端共享同一个计数器。
- **仅内存存储** -- 速率限制状态不在多个 OxPHP 实例之间共享。每个实例独立跟踪自己的计数器。
